# E04 · M1 浏览器演示与原件集成

运行基线 `7b622dde70549c2a4eb11d0bbf2774ca764f4818` 加本任务的目录对象标签、显示 Cell 编号和验证器。
空 SQLite、课程目录与缓存独立，Chrome 157 由 `agent-browser` 操作真实 FastAPI。
三个原件都由浏览器文件输入上传。只使用仓库公开样例。

## M1 和两种追问

1. 从空库导入 `Signal-lab.ipynb`，打开 signals 课程、文件和 Median filter lab 章节。
2. 打开第一个 Cell，点“下一项”到第二个 Cell，返回章节，再打开第 2 个 Cell。
3. 输入“展示这个 Cell 保存的两张图”。真实消息加载并解码两张 440×260 图。
   输出 0 是文字，图序由输出 1 和 2 组成。原生文字来自当前版，图仅展示。
4. 点击第二张图的“问这张图”后输入“横轴单位是什么？”。请求使用消息和显示标识。
5. 独立在输入框只输入“刚才第二张图”。实际 HTTP 只带四个轮次字段，
   服务端以完成消息的显示顺序定位第二图。两轮均选择
   `(local_97ea9230800f415aa56dabef6ce5f1f6,1,cell:1:output:2)`，输入 SHA-256 同为 `ce741007281a939680e7a21020fc80c34abfcb10d6d76d13e7984bc9d5743aa5`。
   真实 DashScope 定向读取两次，均读到 `Frequency [Hz]`。
6. 输入“那张图”触发澄清；浏览器刷新后两项仍可用，消息和显示编号恢复。

## 阅读器与范围

| 浏览器操作 | 实际结果 |
| --- | --- |
| PPTX 第 1 页行内原件 | `page:1`，1440×720，LibreOffice 转换后浏览器解码 |
| 点击目录表格并要求展示 | `page:1:shape:3`，1210×462，保留两列表头的 samples 单位及数据行 |
| PDF 第 2 页局部、放大、回原件 | 可信区域裁图 527×596，回同版 1224 像素宽整页标出右图 [浏览器高亮](./E04-evidence/pdf-highlight.png) |
| 切到 PDF 后单文件总结并刷新 | 实际范围只含当前 PDF，完成消息和选中范围刷新可恢复 |

集成修正把 B 已登记的表格、文本框、图表等类型展示为可区分的目录项。
消息里的 Cell 标签与目录统一使用一基展示，API 的原件索引依然是零基。
首次自动播放的表格等待条件曾匹配上一条已完成消息，切范围令在途轮次按契约失效。
脚本改为等待新完成消息以及实际图像解码，随后八轮浏览器回放全部通过。
独立首审复现 Notebook 图卡整页链接会返回 409。该图卡现在提供“查看原件”，
浏览器已校验它打开同版保存图，媒体请求为 `view=inline`。课件和论文保持同版整页导航。

PDF 可信区域仅由验证器对公开 PDF 的精确 SHA 与版本化来源登记。真实应用依赖注入使用
同一会话服务和 D 的渲染路径。常规应用按已登记定位渲染。E05 独立复核两个浏览器所有者、
换版与保留旧图、取消重试及离线浏览。

## 复现

```sh
SRAG_SOFFICE=/path/to/soffice bash docs/E/E04-browser.sh
```

默认不调用模型，浏览器验证定位、原件和读取状态。加 `E04_RECORD=1` 记录操作视频，
加 `E04_REAL_VISION=1` 会使用已配置凭据对公开第二图发起两次真实读取。
脚本将截图、原始 HTTP 和独立库写入临时目录，也可通过 `E04_OUT` 指定一个新目录。
