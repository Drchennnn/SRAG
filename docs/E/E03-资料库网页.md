# E03 · 资料库与问答网页

E03 使用 E01 已签版本 `860f4f7c79321d4deb880e19a578be434ca48c2f` 的 HTTP 契约。原生 HTML、CSS 和 JavaScript 位于 `app/web/workspace/`。页面通过同源 `/api/workspace` 使用当前拥有者的持久会话。网页可切课程或单份资料、沿目录下钻及返回、查看相邻位置、预览原件、导入二进制文件，以及搜索、提问和总结单文件。

| 操作 | 前端的依据与结果 |
| --- | --- |
| 导入与选择 | 浏览器发送 `application/octet-stream`。逐文件显示上传、发布或失败状态；选择更新时只允许传一份文件。范围与焦点保存于会话，刷新从服务端目录和会话快照恢复。 |
| 消息与媒体 | 按 `blocks` 顺序绘制，图片编号来自服务端 `visible_display_ids`。加载失败单独显示失败状态，并关闭对应图片操作。阅读器可放大，原页的引用区域使用服务端规范坐标。 |
| 图片卡片追问 | 选择卡片后显示当前引用，只发送 `anchor={type:"display",message_id,display_id}`。图片真实读取状态来自服务端记录。 |
| 纯文字序号追问 | 直接输入“刚才第二张图”，浏览器提交 `client_turn_id,kind,text,scope_revision`。消息和图像的解析由服务端负责。 |
| 运行状态 | 运行、失败、取消和澄清状态明确呈现；取消和重试按钮常驻输入区。未能确认的提交可用原轮次 ID 重发；切会话后旧响应无权覆盖新会话界面。 |

## 浏览器契约回放

只读使用公开 `docs/A/样例/Signal-lab.ipynb` 的两张已保存图像。真实 Chromium 通过浏览器选择并上传原件，fixture 捕获请求及实际字节数。fixture 模拟 E01 HTTP 回包、离线模型和轮次状态。SQLite、授权历史、正式持久化和真实网页接入由 E04/E05 核验。

| 实测操作 | 观察结果 |
| --- | --- |
| 空库 → 上传 → 资料 | 浏览器发送公开 Notebook 的 11,484 字节，响应显示 `v1`。 |
| 目录、相邻、预览 | 从资料进入 Cell 0，前进至 Cell 1，返回资料，再下钻到输出 1。图像在真实浏览器解码，放大和恢复均可操作。 |
| 两种追问 | 同一完成消息依序显示两张已解码图片，失败占位独立。点第二张图发送 `display_id=d2` 的卡片引用。手输“刚才第二张图”只发送四项基础字段。两条回执均显示图 2，读取状态保持未读。 |
| 运行控制 | 刷新后还原澄清选项，选项操作成功。模拟失败后重试成功，运行轮次可以取消。 |
| 更新会话 | 搜索和单文件总结经页面发送。新建空会话，再切回原会话，恢复图卡、焦点和总结记录。 |

本机 Chrome 157.0.8103.38 运行通过。回放用独立浏览器会话、临时本地 HTTP 服务和另一输出目录。fixture 只监听回环地址，不访问外部服务。记录的完整路径由脚本最后打印，内含 `empty.txt`、`ordered-images.txt`、`restored.txt`、`trace.json`。
