# C03 · 结构邻接与覆盖

## 结论

C03 已在 C02 远程确认版本 `d035c1929c9555241f4f0ab699bcbd340b4631da` 上实现一跳结构邻接、显式位置内对象、无文字锨点浏览和覆盖轨迹，可送交独立审核。实现仍只读 B 部的当前可见快照，没有读原件字节、渲染、裁图或调用视觉模型。

本项仅修改 C 线已分配的 `app/rag/structure_search.py`、`tests/test_structure_search.py` 并新增本报告。`app/main.py`、README、RAG、治理记录和 Git 发布仍由主控整合者负责。

## 策略与预算

请求的最终候选预算为 `K=top_k`，纯 FTS 与加邻接共用 FTS 种子检查上限 `C=min(3K, 150)`。`include_adjacency=false` 只返回前 K 个 FTS 候选，不启动页浏览回退。`include_adjacency=true` 在同一批前 C 个 FTS 种子上检查一跳边，最终仍只返回 K 个来源。

当 `K>1` 且存在合法邻接时，结构策略保留

```text
R=min(max(1, floor(K/3)), 4, K-1)
```

个邻接槽。它先保留最强 FTS 种子，用前 `K-R` 个种子填种子槽，再按父级、已登记图注目标、直接子级、同位置对象、前一位置、后一位置的顺序填邻接槽。邻接不足时按 FTS 排名回填。`K=1` 始终保留最强 FTS 来源，但合并其他种子对它产生的结构原因。

### 满 K 反例

隔离样例有 4 个 `budgetword` FTS 来源，`K=3, C=9, R=1`。实际结果如下。

| 策略 | 最终来源 | 数量 |
| --- | --- | ---: |
| 纯 FTS | `page:1:shape:1`, `page:2`, `page:3` | 3 |
| FTS + 一跳邻接 | `page:1:shape:1`, `page:2`, `page:1` | 3 |

`page:1` 由 `page:1:shape:1` 以 `parent_context` 引入，其 `seed` 保留完整 `(document_id, version, source_id)`。这个用例证明前 K 个 FTS 已占满时结构槽仍能生效，同时两组最终证据数一致。

## 一跳边与原因

| 原因码 | 验证行为 |
| --- | --- |
| `parent_context` | 页内对象或 Notebook 输出引入同版父页/Cell。 |
| `caption_target` | 仅使用 `locator.caption_target_source_id` 已登记的边。种子与目标必须有非空且相同的页号，目标必须是 `page_object`。 |
| `child_object` | 页或 Cell 引入直接子对象，不越过第二层。 |
| `same_position_object` | 用已验证的同页号或同 Cell 索引引入同位置对象。 |
| `previous_position` / `next_position` | 围绕种子或其基层父级，只引入同文档同版的紧邻基层页/Cell。 |
| `page_browse_fallback` | 唯一文件无 FTS 锨点时，按 `ordinal, source_id` 提供有界页/Cell 浏览。 |

公开小型图注探针中，已登记图注能以 `caption_target` 引入指定图像对象。对照探针把 `caption_target_source_id` 指向页主体，实现因目标不是 `page_object` 而拒绝强边，只保留 `same_position_object` 弱回退。实现不从图注文本、对象标题或词法相似度猜测图注对应对象。

FTS 命中同时保留 B 库的原始 `fts_origins`，对外原因码按 C01 签认语义映射：`native_text → fts_native`、`legacy_text → fts_legacy`、`enhancement → fts_enhancement`。三格式公开探针都断言原始值为 `native_text`、公开原因为 `fts_native`，不再暴露未签认的 `fts_native_text`。另一个隔离探针实际发布 `legacy_text` 来源并经版本/哈希/代次校验写入 `enhancement`，分别断言 `fts_legacy` 和 `fts_enhancement`。

## 显式位置和覆盖

显式页或 Cell 仍不运行全文 FTS MATCH。C03 以目标基层页/Cell 为首个候选，然后引入已登记图注目标、直接子对象和同位置对象。它不因显式位置扩展到前后页或前后 Cell。

同 Cell 多输出探针登记 `cell:0:output:0` 和 `cell:0:output:2`，中间输出缺失。对 `cell_id=plot` 的实际顺序是：

```text
cell:0
cell:0:output:0
cell:0:output:2
```

这个顺序来自 B 已发布来源的 `ordinal, source_id`，没有用“第二张图”重新编号。两个输出都保留 `child_object` 和对应 Cell 种子。该样例的一个 Cell 和两个输出已全部返回，因此 `full_file_read=true`。

`full_file_read` 只在显式位置请求的最终来源键集合与快照中该文档全部来源键集合严格相等时为 `true`。普通 FTS、FTS + 邻接和页浏览回退始终为 `false`。

部分超界范围不丢掉已找到的位置。真实 ASGI 用例对只有第 1–2 页的 PDF 请求 `page_range=[1,3]`，返回 `page:1, page:2`，`checked_positions=[page:1,page:2]`，并记录 `location_missing:page:3`。对只有 Cell 0–1 的 Notebook 请求 `cell_range=[0,2]`，对应返回两个 Cell 并记录 `location_missing:cell:2`。两份资料的实际全部来源均已返回，因此 `full_file_read=true`，但范围缺位没有被隐藏。全无目标位置时仍返回 `location_not_found`，`checked_positions=[]` 并附可用边界。

## 无文字锨点和未读状态

单文件范围无 FTS 命中、`include_adjacency=true` 且 `include_page_fallback=true` 时，结果为 `no_text_anchor`，按位置返回最多 K 个基层页或 Cell。两页扫描探针在 `K=1` 时只返回 `page:1`，轨迹记录：

- `match_kind=browse`
- `reason=page_browse_fallback`
- `truncated_by_reason.page_browse_fallback=1`
- `full_file_read=false`
- `misses=[no_text_anchor, visual_not_read]`

这只表示用户可以按页查看，不表示 C 已读取图像或 OCR。多文件范围无锨点时返回 `empty`，不用任意文件首页填充。`include_adjacency=false` 的纯 FTS 即使保持默认 `include_page_fallback=true`，也返回 `empty`，不偷渡成结构浏览策略。

## 轨迹字段

- `fts_candidate_cap`、`fts_seed_count` 和 `reserved_adjacency_slots` 记录 C、实际种子数和 R。
- `enumerated_source_count` 记录快照适配器在已解析范围中枚举的 B 来源行；`evidence_inspected_count` 记录实际用于 FTS/结构判定的唯一候选来源数；`returned_count` 记录最终条数。
- `checked_adjacency_edges` 记录实际形成的带原因一跳边数。`checked_positions` 来自完整候选池，包含已检查但被 K 截断的位置，不只是最终返回位置。
- 每个候选只返回一次，`reasons` 保留它的所有引入原因与每个原因对应的 A01 来源种子三元组。`truncated_by_reason` 按原因记录候选因 K 被截断的数量。

## 剩余边界

- 结构策略只走一跳，不递归扩展邻接候选。这使预算和引入原因可重放，也意味着跨两层的关系不在 C03 范围内。
- 同页弱回退会把该页的已登记对象作为候选，只有已登记的 `caption_target_source_id` 才表示特定图注对应对象。
- 页浏览回退不发起 OCR、渲染或视觉模型，`visual_not_read` 是强制的轨迹边界。
- 快照适配器仍会枚举已解析文档范围的 B 来源行。轨迹已区分枚举、实际检查和返回数，本项未测量大型真实课件的内存和延迟分布。
- C04 需由未参与 C01–C03 实现的审核者在同样本、同 K 和同快照下对比纯 FTS 与加邻接，并报告逐题命中、漏检和代价。
