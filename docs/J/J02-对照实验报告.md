## 四、逐策略深度分析与代表性 Case 漏斗拆解

### 4.1 `S0_prod_current` vs `S0_pool12` vs `S0_pool24`（预算解耦与池拥挤基线）

- `S0_pool12` 与 `S0_pool24` 在 `A1–A3` 论文深段题均可命中（`3/3`），在 `D1–D4` 控制组全部保持 `100%`（`4/4`）。
- 但同预算截断至 `6` 条后，**`S0_pool12` 与 `S0_pool24` 在 Group B 均为 `0/4`、Group C 为 `0/3`**；扩充候选池到 `24` 而不换重排或扩展机制（`S0_pool24`），仍然只会保留前 `6` 名，因此整题通过率与 `S0_pool12` 完全持平（`50.0%`）。
- `S0_prod_current` 因放行 `budget=12`，偶然把排在第 `8` 位的 `Lecture05 page:2` 顺带装入生成窗口而通过 `B2`（`57.1%`），以 `100,940` tokens（多出 `~33K` tokens）换取微弱顺带召回，但在 `B1`、`B3`、`B4` 与 `C1`–`C3` 同样全败。

### 4.2 `S1_pool12` & `S1_pool24`（G22 48 KB 修复实证与远程延时瓶颈）

1. **48 KB 修复完全可靠**：在 `S1_pool12` 与 `S1_pool24` 合计 `22` 次 Jev 评分（`54` 个批次）中，原始未摘取序列化负载最高分别达到 **`53,763 B`（`pool12` `C3`）** 与 **`110,197 B`（`pool24` `C3`）**——旧代码会 100% 在此处直接 `input_limit` 零外呼崩溃。经确定性三段窗口摘取与 `_TARGET_BATCH_BYTES = 42_000` 装箱后，单批实际载荷严格控制在 `16,408–34,602 B`，**`input_limit` 失败率为 `0.0%`（`0/54` 批）**，无需触发运行时递归二分即稳定装箱完成。
2. **扩池重排净救回截断题**：
   - 在 `pool=12` 同池上，`S1_pool12` 将原排第 `6` 与第 `8` 位的 `Lab04 cell:4:output:0` 与 `Lecture05 page:2` 精准提权至前 `2` 位，**救回 `B2`**（较 `S0_pool12` `+7.1 pp`，`57.1%`）；
   - 在 `pool=24` 上，原本位于 `pool=12` 之外的 `Lecture05 page:6`（`B3` 定义页）进入重排池，**`S1_pool24` 将 `Lecture05 page:6:shape:3` 与 `page:6` 提权至第 `1–2` 位，进一步救回 `B3`**（`9/14 = 64.3%`，B 组 `2/4`，比 `S0_pool24` 净增 `+14.3 pp` 且 `0` 退化）。
3. **触发的红线与局限**：
   - 远端 `Zev-1` API 实测单批 RTT 较高，多批串行导致 `S1_pool12` `p95 = 25,699.21 ms`（较 `S0_pool12` **`+15,551.54 ms`**），`S1_pool24` `p95 = 49,762.40 ms`（**`+39,614.73 ms`**），远超 [J01 §3.3](file:///Users/Link/code/SRAG-j/docs/J/J01-多文件检索对照设计.md#L266) 所设 **`> +8,000 ms` 禁用门槛**；
   - 且在中文查询面对纯数字/极低文本页时出现 `3/11`–`4/11`（`27%–36%`）`low_confidence` 回退（如 `C2`/`C3`/`D3`），本身也不具备跨文件无共现锚 `B1`/`B4` 的扩展能力。

### 4.3 `S2a_pool12`（零外呼字面 2-hop 的精确收益与适用边界）
