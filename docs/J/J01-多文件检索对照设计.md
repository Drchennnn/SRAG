### 1.2 现有默认路径（S0）在真实多文件课程（8–12 份混合资料）中的 4 类已知短板

在真实课程（8–12 份混合 PDF / PPTX / Notebook）下，当前生产默认路径 `S0`（`workspace_retrieval_strategy="fts"`，命中 `_HAN_QUERY and _has_latin_corpus` 时自动转 `bilingual`）暴露 4 类结构性短板：

1. **短板 ① · 跨多文件候选池拥挤与 Top-K 截断**：
   - [app/rag/workspace.py#L1421](file:///Users/Link/code/SRAG-j/app/rag/workspace.py#L1421) 固定 `top_k=12`，[app/rag/structure_search.py#L223](file:///Users/Link/code/SRAG-j/app/rag/structure_search.py#L223) 计算 `candidate_cap = min(36, max(18, top_k * 3))`。
   - 当课程中存在 4–5 篇数十页英文论文与多份短讲义、Notebook 并存时，SQLite FTS5 BM25 的 `OR` 匹配易被单篇长 PDF 的引言/综述高频通用词（如 `routing`, `memory`, `quantization`）占满 Top-12，将真正包含特定配置参数或实验结果的次要文件页/Notebook 输出 Cell 挤出 12 池之外。
2. **短板 ② · 讲义与实验 Notebook 无共享概念词的 2-hop 跨文件断链**：
   - 课程常见模式为：PDF/PPTX 讲义定义中文或英文概念及判定公式，并注明对应实验函数、数据集或配置键（如 `run_top2_probe`、`WikiText-Routing-16B`、`cache_sweep_v4`），而 `.ipynb` 实验文件只记录该标识符与实测数字，**绝不重复概念名词**。
   - 用户提问仅含概念词与“实验实测结果是什么”，`S0` 单跳（含双语改写）在 Notebook 中 0 命中；同时 [workspace_router.py#L363-L368](file:///Users/Link/code/SRAG-j/app/rag/workspace_router.py#L363-L368) 的 `SupplementRoute` 仅在 `workspace_answer_enabled=False` 触发，且现行 `_expand()` 因依赖 Jev 且漏 `snake_case` 标识符而无法闭环。
3. **短板 ③ · 纯图 / 极少文字 PPTX 幻灯片无词法锚点漏召回**：
   - [app/rag/parsers/local_slides.py](file:///Users/Link/code/SRAG-j/app/rag/parsers/local_slides.py) 对纯架构图/纯曲线截图幻灯片，提取 `page.text=""` 与 `picture` 子对象 `text=""`，完全无法进入 `local_fts`；
   - [app/rag/structure_search.py#L738-L744](file:///Users/Link/code/SRAG-j/app/rag/structure_search.py#L738-L744) 的 `_no_text_result()` 严格限制 `len(snapshot.documents) == 1` 才启用 `page_browse_fallback`，在多文件课程中直接返回 `empty`。
   - 此外，即便某图像源偶然通过 `visual_candidates` 透传到 [workspace.py#L1506,L1983-L1990](file:///Users/Link/code/SRAG-j/app/rag/workspace.py#L1506)，也仅由 `_attach_images()` **展示原图**，DeepSeek 生成阶段只看到 `unread_visual_total` 计数（`read_status="not_attempted"`），无法依据纯图内容作答。
4. **短板 ④ · G22 暴露的 Jev `48 KB input_limit` 高频失效**：
   - 12 条稠密英文学术 PDF 页面原文合计约 `55–65 KB`，[app/clients/jev.py#L110-L111](file:///Users/Link/code/SRAG-j/app/clients/jev.py#L110-L111) 直接截停于 `48_000` 字节上限，`external_call_count=0`，致使任何基于整池全量打包的 Jev 重排或扩展路径在真实论文课程中几乎 100% 退化失效。

### 2.3 四组策略详细技术规格

#### 策略 S0：基线（`FTS + 结构邻接 + 按需双语改写`）

#### 策略 S1：同池 Jev 评分重排（含 G22 `48 KB input_limit` 确定性修复）

- **单变量控制**：与 S0 使用**完全相同的输入候选池 `pool`**（同 `pool_cap`、同双语 RRF），仅在送入 `read_window` 前调用真实 `Zev-1`（`JevClient`）计算每个候选对原问题 `question` 的独立必要证据分 `noul` 并重排。
- **G22 `48 KB input_limit` 确定性修复方案（四层防线，严守安全与契约边界）**：
  1. **分层常量与精确字节测量**：
     - 保留服务端通信绝对上限 `_PAYLOAD_BYTES_LIMIT = 48_000`，新增安全装箱目标 `_TARGET_BATCH_BYTES = 42_000` 与单批候选上限 `_MAX_BATCH_CANDIDATES = 10`；
     - 每次试装前使用与请求发包完全相同的 `_json(payload).encode()` 计算真实 UTF-8 字节数（包含转义与结构键开销）。
  2. **仅限评分输入用的有界候选摘取 `_excerpt_for_jev(item, question, max_bytes)`**：
     - **核心边界**：摘取结果仅写入 Jev `candidate_passage` 用于打分，**绝不修改 `SnapshotSource`、本地 FTS 或后续 `read_window` 实读原文**；
     - 若原编码适合（默认单条 `max_passage_bytes = 2_800` B，确保每批可容 8–10 条；在多跳传入 `evidence` 时限制 `state` 中单条已读证据最多 `2_400` B / 总 `evidence <= 6_000` B），直接原样发送；
     - 若单条原文超过 `max_bytes`，按确定性算法生成三段窗口摘录（无随机、纯词法锚定位）：
       - **首段（`35%` 配额）**：标题、章节路径与段首定义/结论开头；
       - **查询命中核窗（`45%` 配额）**：定位 `question`（及双语查询词元）密度最高的一行/句为中心，向前后对称扩展完整 UTF-8 边界；
       - **尾段（`20%` 配额）**：页面/Cell 尾部总结、数值表尾或输出结果行（防止后段实验数值被头截断）；以 `"\n…[excerpt]…\n"` 拼接并按 UTF-8 边界安全截短至 `<= max_bytes`。
  3. **贪心分批 + `is_batch_limit_error` 递归二分（对齐 SAG-Wiki `models.rs`）**：
     - 遍历候选列表按当前 `state` 试装，若加入下一候选后 `len(_json(batch_payload).encode()) > _TARGET_BATCH_BYTES` 或 `len(batch) >= _MAX_BATCH_CANDIDATES`，立即封包当前批并开新批；
     - 若单条候选即使缩到最小摘取窗口（`min_passage_bytes = 600` B）后单批仍超 `48_000` B（例如超长 `question` + `state`），将该条标为 `candidate_oversized` 跳过并保留保底基线分，**不中止其余候选**；
     - 若 Jev HTTP 接口返回 `400 / 413 / 422` 且响应体包含 `limit | length | token | payload | size | too large`（参考 SAG-Wiki `models.rs:1444-1495`），且当前批候选数 `> 1`，自动将当前批按中点拆成两半并递归重试（递归深度受 `ceil(log2(len(pool))) <= 5` 天然封顶，每次重试前均调用 `verify()`）。
  4. **跨批一致性校验、归一化 tie-break 与低置信回退**：
     - 所有批次共享同一组不可变 `state`（`original_question` + 相同的 `previously_retrieved_evidence`）与同一 `criteria`，使各批返回的 `noul ∈ [0.0, 1.0]` 处于同一条件分布口径；
     - 保留严格校验：`set(answers) == set(batch_ids)` 且所有 `type == "noul"`、`0.0 <= noul <= 1.0`；任一批次失败仅降级该批回原 RRF 排名，完整成功批次保留其得分（`trace.jev.status` 细分为 `succeeded` / `partial` / `provider_error` / `invalid_response` / `low_confidence`）；
     - **稳定平局决胜**：排序键采用 `(scored_ok, round(noul, 4) + 1e-3 * rrf_rank_norm)`（`rrf_rank_norm = (N - idx) / N`），防止多候选并列 `1.0` 或 `0.0` 时打乱 S0 的结构邻接序；
     - **退化防线**：若全部有效分数 `max(noul) < 0.15`（Jev 对中文/领域术语全盘判低）或全部得分坍缩（`max - min < 1e-3` 且 `min > 0.8` 无法区分相关性），记 `jev_low_confidence` 并安全回退 S0 原排序。

#### 策略 S2：有界两步检索（`max_steps = 2`，含 `S2a` 与 `S2b` 双子变体）

为独立验证“无大模型规划的确定性字面锚扩展”与“大模型有界工具规划”的真实差距，S2 **强制解除当前 `expanded` 对 Jev 的死绑定**（默认基于 S0 池运行；若 S1 经评估通过，可按需正交叠加测试 `S1+S2a`）。

##### 子变体 `S2a`：确定性首跳读文抽词 + 同范围字面锚追加检索

2. **首跳原文读取与多模式字面锚抽取（对齐 SAG-Wiki `expansion_terms`）**：
   - 仅从 `pool_1[:min(6, len(pool_1))]` 中经 `library.read_source()` + `_PinnedScope.verify()` 版本校验一致的可读正文抽取新锚词，步骤如下：

       2. 点分/路径标识：`[A-Za-z_]\w*(?:\.[A-Za-z_]\w*)+`；
       3. 数据集/实验/版本连字符编号：`[A-Za-z]{2,}(?:[-_][A-Za-z0-9]+)+` 或 `[A-Z]+\d+[A-Za-z0-9_-]*`（排除纯常见页码/图号如 `Table-1`, `Figure-2`, `Page-3`, `v1`, `arXiv` 等泛词停用表）；
       4. 反引号 / 引号包裹的字面代码或配置键：`` `([A-Za-z0-9_.-]{3,64})` ``。
     - **去重与跨文件优先级排序（零额外外部调用）**：
       - 过滤已出现在 `prior_queries`（`question` + `alternate_query`）中的词；

       - 若 `selected_terms == []`，立即止步（`stop_reason="no_new_terms"`），耗时增量 `< 2 ms`。
3. **Step 2（单次受限二次检索与交错合并）**：

   - 若交错新增列表为空，立即止步（`stop_reason="no_new_candidates"`）；
   - 将新增候选插在 `pool_1[:protected_count]` 之后（优先吸纳来自新文档/实验的输出或补丁页，最多追加 `budget - protected_count` 个槽位，同时将 `pool_1[protected_count:]` 余项后移去重），保证最终入选仍严格 `<= final_source_budget`。
   - **可选协同子配置 `S2a+Jev`**：若在 S1（Jev 48KB 分批）可用且通过 S1 门槛时，用包含首跳受保护正文作为 `previously_retrieved_evidence` 的 Jev 对 `additions` 打分排序并滤除 `noul < 0.35` 的无关同名命中；默认对照 `S2a` 独立跑在纯本地补查上，与 `S2a+Jev` 分开记账！

## 三、预先锁定的量化评价指标、五层记账与启用/禁用判据

### 3.1 必需证据五层漏斗记账（逐题双口径：父位置 vs 精确对象）

每道测试题均预先锁定预期必需证据列表 `required_evidences`（含精确对象键 `document_id + source_id` 及其父页/父 Cell 键），实验运行器对每个必需证据独立记账 5 层漏斗状态（同时报告 **父级位置口径** 与 **精确对象口径**）：

| 层级 | 状态键名 | 严格判定条件（必须机检 + 人工复核一致） |
| --- | --- | --- |
| **L1 · 入库可定位** | `indexed` | SQLite `local_versions`/`local_sources` 与当前 `StructureSnapshot` 中存在且标题/页码/Cell/文本或对象框有效 |
