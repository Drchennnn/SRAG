## 实现结果

- `SourceEvidenceService` 只从 B 的归档 BLOB 读取字节。当前 HTTP 必须同时匹配服务端课程
  allowlist、`SourceKey`、`content_sha256`、`publication_epoch` 与 `is_current`；请求体不接受
  课程范围、本机路径、bbox 或 JSON Pointer。历史读取只有内部 `HistoricalSourceGrant`
  入口，没有公开 HTTP 开关。
- 页内对象沿同版父链一直解析到真实 `page`，带 visited guard；父级、原件哈希、当前版和
  epoch 任一不符即停止。框不可靠时 `requested_source` 保留原对象，实际展示和读取来源均
  改成父页。
- PDF 在 B02 共用的 `_PDFIUM_LOCK` 内打开、渲染和关闭。实现 D01 的 crop box + 0/90/180/
  270 度四角投影；裁区向外增加 2% 页面边距。公开故障样例实际渲染旋转页，并检查目标红块
  与 caption 蓝块均留在裁图中。
- PPTX 通过 `SRAG_SOFFICE` 或系统可执行文件运行独立临时 profile 的 headless
  LibreOffice，先校验转换页数和整页宽高比，再应用 shape 框。转换器缺失、超时、失败或
  页数/宽高比不符均给明确降级，不伪造裁图。
- Notebook 只按原始 JSON Pointer 解码指定 output 的指定 MIME，并复核字节长度与 SHA-256。
  显式 MIME 不可用时不替换成同 bundle 的另一种图片。PNG/JPEG/WebP 校验后原样返回，
  BMP/TIFF 经具名 Pillow 管线转 PNG；SVG 在无安全光栅化器时不内联、不送模型。
- 展示字节以有上限的 base64 raster 返回，带 MIME、宽高、字节数、SHA-256、renderer、版本、
  实际来源和裁区。缓存键覆盖来源三元组、原件哈希、locator、页/裁区、区域 revision/components、
  MIME、DPI 与 renderer 版本；缓存读取重算哈希并重新解析图片。同一进程以
  `(cache_dir.resolve(), rendition_key)` 做跨 service 实例的单航班，不同键使用不同锁并行；
  owner 成功后 waiter 复读已校验缓存，owner 失败也在 `finally` 释放并清理 flight。成功、失败
  和缓存命中在返回前都重新核对授权，撤权或换版后不会从缓存泄漏。
- 渲染失败、原件缺失或 inline 超限时，在再次授权成功后只返回经过白名单筛选的页/Cell
  定位、原生标题/文字/表信息；未授权结果不返回哈希、定位或 fallback。
- Pillow 只在实际图片解码、裁图或编码时惰性导入，不进入 `app.main` 顶层加载链。基础安装
  没有 Pillow 时仍能 `import app.main` 和 `create_app()`；D 的 PDF/PPTX 图片返回
  `rendition_unavailable:pillow_unavailable`，Notebook 图片返回
  `image_unavailable:pillow_unavailable`，授权后的原生页/Cell 定位与文字回退仍可用。

## 独审返工记录

首次送审件由 `docs/D/D02-独立审核.md` 判为返工：独立探针让两个线程同时请求同一空缓存
PDF key，实际 `_render_pdf_page` 调用 2 次，两份结果均为 `cache_hit=false`。原子替换只保护
缓存文件，没有满足 D01 已签认的同键单航班。

本次修复把 flight 从单个 service 实例提升到进程共享协调器，并把 cache namespace 纳入 key，
因为 FastAPI 默认依赖每次请求创建 service。确定性 HTTP 回归实际创建两个依赖实例：第一个
render owner 被 event 暂停，第二个请求已创建独立 service 后再释放 owner；最终 render 调用
严格为 1，两份并发结果哈希相同、`cache_hit` 分别为 false/true，第三个后继请求仍为 true。
另一 barrier 用例证明 page 1 与 page 2 不同 key 能同时进入渲染；故障用例证明 owner 抛错后
flight 清理，下一请求重新渲染成功，随后缓存命中。首次失败记录保留在独立审核报告中，没有
改写成初次通过。

## 已知边界与 D03 交接

- D02 没有模型读取证据，所有结果 `read_status=not_attempted/not_requested`。真实/模拟视觉
  结果、提示版本、问题定向缓存和通用转写写回属于 D03。
- 当前 HTTP allowlist 是显式配置，默认空即关闭。E 尚未开放前，历史引用只能由后端测试或
  内部调用注入 grant；D02 不提供能绕过会话授权的临时历史路由。
- SVG 安全光栅化器尚未引入，所以 SVG-only 输出为 `image_unavailable`；原始 SVG 的受信附件
  下载与隔离响应由后续阅读器决定。
- PPTX 渲染是可选运行时能力；没有 LibreOffice 时基础导入和原生文字仍可用，图片明确降级。
  D04 应在同一公开原件上重新实际转换并人工核对，而不是只信本报告中的哈希。
- 当前项目基础依赖没有把 Pillow 设为主应用硬依赖；D02 因此保证主入口可加载并在图片操作点
  显式降级。D04 的干净环境复现必须单列 Pillow/PDFium/LibreOffice 的实际可用性，不能把
  “应用能启动”误报成“图片能渲染”。
