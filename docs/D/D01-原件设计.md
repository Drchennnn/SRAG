# D01 · 原件、裁图与视觉缓存设计

状态：**待独立审核**。本设计基于工作区 `HEAD 5aa2bdd8a0c4`，沿用 A01 已签认的
来源与版本语义和 B05 已通过的本地发布行为；不改变 `(document_id, version,
source_id)`、`content_sha256`、`publication_epoch` 或历史访问语义。

## 1. 目标、边界与数据归属

D 接收一个已经授权、已经版本化的来源，返回可展示的原件/裁图，以及可选的通用转写或
问题定向读图结果。它必须让调用方分别回答：

1. 页面展示了哪个对象；
2. 模型实际读取了哪个对象、哪一幅输入图；
3. 本轮是否真的调用了外部服务，还是只命中缓存、模拟协议或根本没有读取。

D 不选择课程范围、不做召回排序、不把任意路径暴露给浏览器，也不执行 Notebook。B 仍拥有
归档原件、版本可见性、发布代次和 FTS 写回；C 只产出候选来源；E 保存消息中的展示顺序。
D 拥有渲染规格、区域投影、产物哈希、视觉读取记录与缓存。

实现修改范围预定为：

- `app/rag/source_evidence.py`：授权后原件解析、渲染、裁图及回退；
- `app/rag/source_vision.py`：通用转写、定向读图、缓存与写回；
- `app/api/source_evidence.py`：只接受来源引用和展示/读取意图，不接受本机路径；
- `tests/test_source_evidence.py`、`docs/D/`：公开 fixture、自动验证与审核证据；
- `app/main.py` 由整合人接线路由，公共模式或 B 的只读网关若需补充也由整合人处理。

现有 `app/rag/vision.py`、`app/clients/dashscope.py` 及其工作区未提交修改不由 D 覆盖。
D 的新服务可适配已提交客户端，也可使用独立的小接口；不得依赖未提交差异才能运行。

## 2. 共用来源接口与授权

### 2.1 输入

C 与 D 共同使用 `app.schemas.local.SourceKey`，禁止另造可替代来源身份的键：

```python
class SourceKey(BaseModel):
    document_id: str
    version: int        # > 0
    source_id: str
```

D 的内部调用契约为：

```text
EvidenceRequest
  source: SourceKey
  expected_content_sha256: 64 位小写十六进制
  expected_publication_epoch: int          # 当前查询必填
  rendition: original_page | object_crop | notebook_output
  read_intent: display_only | generic_transcription | directed_question
  question: str | null                     # 仅 directed_question 必填
  preferred_mime: str | null               # 仅 Notebook 输出可用
  registered_region_id: str | null         # 只引用后端已登记区域，不携带坐标

AuthorizedScope（仅服务端注入，不从请求 JSON 信任）
  course_ids: 非空课程集合
  current_course_allowlist: 配置的受信课程集合
```

正常 D HTTP 入口只读取**当前版**。它从服务端配置的受信课程 allowlist 取得范围，默认空集合
即关闭；调用方不能在 JSON、query string 或 header 中扩大课程范围。当前引用来自 B 当前可见
快照或 C 的候选轨迹，必须带 B 返回的版本、原件哈希与发布代次；进入渲染前再次核对当前版。

历史读取不由公开请求中的 `access_kind=true` 或任意 `message_id` 打开。E 尚未实现时，HTTP
不暴露历史入口；测试只能直接向服务注入后端构造的 grant。E 以后从持久消息中解析
`message_id + evidence/display`，二次核对会话所有者和课程权限，构造不可由请求体伪造的
`HistoricalSourceGrant(source, course_ids, message_id, evidence_id)`，再调用 D 的内部历史方法。
D 精确读取 grant 中的原版本，不把最新版本静默替换进来。API 层不接受调用方传入的
`course_id`、文件路径、bbox 或 JSON Pointer 作为授权或定位依据。

B 的授权只读网关须在同一 SQLite 查询/连接的一次结果中返回以下快照；其行为是对现有
`read_source` 的增量，不是新的来源语义。由共享整合人给现有 `HistoricalSource` 增加两个
有默认值的字段，并保持调用签名不变：

```python
@dataclass(frozen=True)
class HistoricalSource:
    status: Literal["available", "original_unavailable", "not_accessible"]
    source: SourceDraft | None = None
    content_sha256: str | None = None
    original: bytes | None = None
    publication_epoch: int | None = None
    is_current: bool = False

def read_source(
    self, key: SourceKey, *, course_ids: Sequence[str]
) -> HistoricalSource: ...
```

同一个 SELECT 从 `local_documents` 取得 `publication_epoch`，并计算
`is_current = (current_version == key.version)`，与来源、版本、原件字节一起返回。正常 D HTTP
要求非空服务端范围、`is_current=true`、哈希与请求 epoch 同时匹配。历史调用仍要求非空的
grant 范围、资料未删除且仍有当前可见版本、原版本曾发布和哈希匹配；它不以当前 epoch 替换
原版本，只能由已验 `HistoricalSourceGrant` 的内部调用方使用。

```text
HistoricalSource
  status: available | original_unavailable | not_accessible
  source: SourceDraft | null
  content_sha256: str | null
  publication_epoch: int | null
  is_current: bool                         # 默认 false
  original: bytes | null
```

- 未授权、已删除、未发布或历史引用入口无效时返回 `not_accessible`，不泄漏标题、路径、
  版本、哈希或“是否存在”。
- 仍获准且归档字节完整时返回 `available`；D 必须对 `original` 重算 SHA-256，并与登记值
  和请求期望值一致后才解析。
- 获准但只剩定位元数据时返回 `original_unavailable`。可展示版本、页/Cell 标签和失效原因，
  但不得伪造图片，也不得调用视觉模型。
- 当前读取若 `is_current=false`、哈希或代次不符，由 D 转为 `stale_reference` 并让上层重新检索；
  历史读取不要求当前版相同。相同版本经删除后重新发布会产生新代次，旧写回票据仍失效。
- 异步视觉调用前和返回图片/答案前，D 都用同一服务端范围重新调用 `read_source`。当前请求
  再次核对 `is_current + hash + epoch`；历史请求再次核对 grant、版本和 hash。期间换版、
  删除或权限变化时丢弃对外结果并返回失效状态，不能用旧缓存绕过复查。

### 2.2 输出

```text
EvidenceResult
  status: available | partial | original_unavailable | not_accessible |
          stale_reference | rendition_unavailable | image_unavailable | failed
  requested_source: SourceKey
  content_sha256: str | null
  display: DisplayRecord | null
  read_status: not_attempted | succeeded | partial | failed
  capability_reason: not_requested | provider_not_configured | input_unsupported |
                     mock_only | null
  reads: list[ReadRecord]
  warnings: list[str]

DisplayRecord
  display_source: SourceKey       # 图片实际展示对象；父页回退时必须是父页
  actual_source: SourceKey        # 构造图片实际使用的对象；回退时可为父页
  rendition_kind: original_page | object_crop | notebook_output | parent_page_fallback
  media_type: image/png | image/jpeg | image/webp
  width: int
  height: int
  byte_sha256: str
  rect_visible_norm: [l, t, r, b] | null
  renderer: str
  renderer_version: str
  cache_hit: bool
  fallback_reason: str | null

ReadRecord
  requested_source: SourceKey
  actual_source: SourceKey
  actual_input_sha256: str
  actual_input_media_type: str
  actual_input_rect: [l, t, r, b] | null
  method: native_text | native_table | ocr | vision
  purpose: generic_transcription | directed_question
  execution: real_provider | cache_reuse | mock_protocol
  provider: str | null
  model: str | null
  prompt_version: str
  question_sha256: str | null
  status: succeeded | partial | failed
  missing_or_error: list[str]
```

“已展示”仅表示 `DisplayRecord` 的字节已成功生成并返回；它不改变 `read_status`。只有真实
OCR/视觉服务确实读取该 `actual_input_sha256`，或复用了完全匹配且原始证据为真实成功的缓存，
才可记为 `succeeded/partial`。协议模拟记 `mock_protocol`，只验证软件协议，汇总
`read_status=not_attempted, capability_reason=mock_only`，不得列为真实模型结果。未请求是
`not_attempted/not_requested`；请求读图但缺凭据且没有发出网络请求是
`not_attempted/provider_not_configured`；输入格式在调用前不受支持是
`not_attempted/input_unsupported`。只有已经发出真实调用后发生超时、限流、服务错误、响应
损坏或空结果才记 `failed`，并留下 `execution=real_provider` 的失败 ReadRecord。

对象框不可靠而回退父页时，`requested_source` 保留用户原请求，`display_source` 和
`actual_source` **都改为真实父页 SourceKey**，并用 `fallback_reason` 说明从哪个请求对象
回退。E 的展示卡与后续“问这张图”必须锚定实际父页，不能继续把未展示的子对象冒充为卡片
来源。

## 3. 原件解析、渲染与区域回退

所有派生图片先由授权快照中的归档字节写入任务私有临时目录；不按登记路径重新打开文件。
临时文件仅存在于单次任务，成功产物进入内容寻址缓存，原始临时文件在 `finally` 清理。

### 3.1 后端登记区域

B 已发布 locator 中的可靠对象框可以直接使用。对论文局部、图注或验收 corpus 中尚无独立
`page_object` 的区域，D 允许受信服务或公开 fixture 注册表提供如下结构，但不把它变成新的
来源身份：

```text
RegisteredRegion
  region_id: 后端唯一 ID
  source: SourceKey                       # 必须是同版页/对象
  content_sha256: str
  coordinate_frame: visible_page_norm_v1 | pdf_page_units_bottom_left_v1
  target_rect: [l, t, r, b]
  components:
    - role: target | legend | x_axis | y_axis | caption | table_header
      rect: [l, t, r, b]
      coordinate_frame: 同上
  provenance: published_locator | trusted_corpus_registration
  revision: 正整数
```

注册时逐项验证 SourceKey、原件哈希、页号、坐标框和组件都属于同一版本/同一页。有效裁区是
目标与所有已验证必要组件的包围框，再加安全边距。正常 HTTP 最多提交 `registered_region_id`；
D 必须在后端查到与请求 SourceKey、当前 hash 完全匹配的记录，任意 bbox、components 或
`revision` 都不能从公开请求体传入。D02 的双栏论文公开样例可把页 SourceKey 与目标、图例、
双轴和图注登记到测试 registry；修改同一来源的 rect 或 components 时增加 revision，新的
有效框进入 `RenditionKey`，旧裁图不会命中。注册区域不产生新的 `source_id`，展示与追问仍
锚定其关联的真实 SourceKey。

### 3.2 PDF

整页由 `pypdfium2` 渲染为 sRGB PNG，默认 144 DPI；渲染规格记录 DPI、背景、目标格式、
PDFium 版本、页号、旋转和 crop box。PDFium 是进程级非线程安全边界，D 必须复用
`app.rag.parsers.local_slides._PDFIUM_LOCK`，打开、取页、渲染、关闭均在同一把锁内，不能
新建一把看似独立的锁。

原生坐标框使用 `[x0, y0, x1, y1]`、左下原点的 crop box 坐标。先扣除 crop box，再按
页面顺时针旋转角 `r` 投影到左上原点的可见页像素。令 `X=x-x0`、`Y=y1-y`，原宽高为
`W=x1-x0`、`H=y1-y0`：

| `r` | 可见点 `(X', Y')` | 可见尺寸 |
| --- | --- | --- |
| 0 | `(X, Y)` | `(W, H)` |
| 90 | `(H-Y, X)` | `(H, W)` |
| 180 | `(W-X, H-Y)` | `(W, H)` |
| 270 | `(Y, W-X)` | `(H, W)` |

对原生框四个角逐点变换，取最小/最大值，再除以可见尺寸得到
`visible_page_norm_v1`；最后夹到 `[0,1]`。角度不是 90 的倍数、框退化、超出 crop box 后为空、
页尺寸无效或登记变换版本未知时，不精裁，回退整页。

已有 `visible_page_norm_v1` 框仍须验证 `0 <= l < r <= 1`、`0 <= t < b <= 1`，并与登记的
页号、旋转、crop box/变换版本一致。裁图按最终渲染像素向外取整，默认四边增加 2% 页面
边长的安全边距。表格必须保留首行表头和单位；论文图必须保留能可靠关联的图例、坐标轴和
图注。若关联区域不能证明在同页、扩区仍会截断必要标签，或对象跨页，则不拼接成一张
“原图”：返回各自带页号的整页/区域列表，主对象以父页回退并写明原因。

### 3.3 PPTX

原生 shape 的可靠框沿用 B02 的 `pptx_slide_emu_v1 -> visible_page_norm_v1`。只有顶层、未
旋转、未退化且 `position_basis=native_shape_extents_v1` 的对象可以精裁；分组 shape、任意
旋转 shape、画布外对象或未知变换一律回退整张幻灯片。表格裁区同样扩到完整表头和单位；
原生 `rows/columns` 可用于核对，但不能代替实际图片读取记录。

真实整页渲染采用可配置的 LibreOffice `soffice`：优先显式配置路径，再查系统安装路径与
`PATH`。每次转换使用独立临时用户配置目录，执行 headless、无首次启动、有限超时的
`PPTX -> PDF`，记录可执行文件版本、命令退出码和输出 PDF 哈希，再在共享 PDFium 锁下
渲染目标页。转换后必须核对页数和幻灯片宽高比；不一致时不得套用 shape 框。

当前接手环境 `PATH` 中没有 `soffice`。D01 预检另用已核验 SHA-256
`de943203795e5057785f65515063e2db5eb60b0bb6d8e2534fec59e5cc5fb988` 的官方 macOS ARM64
发行镜像，在隔离挂载中运行 LibreOffice `26.8.3.1`，把公开 `Signal-slides.pptx` 成功转为
2 页 PDF；首轮输出 SHA-256 为
`f8764df5a30c5dbb51f2e48c3ec3a30f743657525b6bf48009ab1093b8edacfd`。PDF 元数据可能令整文件
哈希跨轮变化，因此 D02 还须核对页数、逐页渲染哈希/视觉内容，而不能把该首轮 PDF 哈希当成
永恒快照。实现通过 `SRAG_SOFFICE=/path/to/soffice` 或等价设置显式选择运行时，公共证据不
记录主机临时绝对路径。

默认找不到转换器时，必须把这一情况返回为
`rendition_unavailable: converter_unavailable`，仍提供页号、原生文字/表和获准的原文件下载
入口；不得偷偷使用 GUI 自动化或把 WPS 输出宣称为 LibreOffice 结果。D02/D04 可使用隔离、
版本固定的 LibreOffice 二进制完成公开 fixture 实测，但它不是导入和纯文字检索的硬依赖。

预检和 D02 的等价命令形态为：

```bash
SRAG_SOFFICE=/path/to/soffice
"$SRAG_SOFFICE" --headless --nologo --nodefault --nolockcheck \
  --nofirststartwizard \
  -env:UserInstallation=file:///absolute/private/temp/profile \
  --convert-to pdf --outdir /absolute/private/temp/out \
  docs/A/样例/Signal-slides.pptx
```

### 3.4 Notebook

Notebook 只读归档 JSON，按 B03 登记的 `cell_index + output_index + representations[].
json_pointer` 取值，绝不执行代码、解析外部链接或读取旁路文件。读取后按登记编码重新解码，
逐字节核对 representation 的 `byte_length` 和 `sha256`。

调用方显式给 `preferred_mime` 时只能读取该 MIME；不存在、为空或损坏时返回
`image_unavailable`，不能悄悄换成同 bundle 的另一种图片。未指定时按
`image/png -> image/jpeg -> image/webp -> image/bmp -> image/tiff -> image/svg+xml`
确定性选择第一个 `available` 表示，并把实际 MIME 写入展示和读取记录。PNG/JPEG/WebP 可
原样展示；BMP/TIFF 先经具名、带版本的解码器转成 PNG，展示和模型输入记录转换后哈希。SVG
原始字节**不以内联活动内容返回**：只有经具名、带版本、禁用外部资源的安全光栅化器转成
PNG 后才可展示或送入模型，光栅化后的新哈希才是 `DisplayRecord.byte_sha256` 和
`actual_input_sha256`；无该光栅化器则显式 `image_unavailable`。原 SVG 只能作为获准的附件
下载，由后续 E 设置 attachment 与隔离响应策略。无可用图片的 stream、文本或空输出返回
`image_unavailable`，其文字仍可由上层按原生证据展示。

### 3.5 回退优先级

1. 可靠对象框：返回对象裁图；
2. 框不可靠但父页可渲染：返回父页，`display_source` 与 `actual_source` 都记父页，原请求只
   留在 `requested_source` 与 `fallback_reason`；
3. 页面渲染失败但归档原件在：返回原件入口和已核对的原生文字/表，图片为不可用；
4. 归档原件缺失：`original_unavailable`；
5. 未授权或已删除：`not_accessible`，不附带任何定位信息。

回退不会把“附近页”或“同 Cell 另一输出”当作实际读取对象。跨页对象、双栏论文区域或图注
关联不确定时宁可展示整页并标注未精裁，也不生成看似精确的错误裁图。

## 4. 通用转写、定向读图与写回

`generic_transcription` 的提示只要求转写可见文字、公式、轴、单位、图例和不确定项，不针对
当前问题推断。成功结果可申请 B 的 `write_enhancement` 写回 FTS；写回必须同时提交
`SourceKey + AuthorizedScope.course_ids + content_sha256 + publication_epoch`。B 返回 `false`
表示已换版、删除、范围不符或票据过期；本次读取记录仍可作为审计证据，但不能进入当前
搜索结果，也不能作为新版缓存命中。

`directed_question` 必须读取请求所指的同一图，提示中包含问题和当前对象标签。回答只用于
本轮，不写 FTS。两张相似图、同 Cell 多输出及同一对象重复展示均以 `SourceKey` 和实际输入
哈希区分；`display_id` 只用于 E 的消息内反查，不进入 D 的来源身份。

模型请求只发送公开验收 fixture 或用户已授权的本地对象。测试日志只记录模型名、状态、
耗时、输入哈希和脱敏错误类型，不记录密钥、认证头或私人原件。服务超时、限流、无密钥、
响应截断、非结构化输出或空结果均返回 `failed/partial` 与具体缺项；原图展示保持可用。

## 5. 缓存键、隔离与失效

缓存分三层，键均为规范 JSON 的 SHA-256，字段不可用空字符串代替：

```text
RenditionKey v1 =
  SourceKey + content_sha256 + original_byte_sha256 + source_locator_digest +
  rendition_kind + renderer/name/version + page + dpi/background/format +
  registered_region_revision/components_digest + effective_rect +
  coordinate_transform_version

GenericReadKey v1 =
  RenditionKey + actual_input_sha256/media_type + pipeline/name/version +
  provider + model + prompt_version

DirectedReadKey v1 =
  GenericReadKey + question_sha256 + question_context_sha256
```

原件换版、归档字节不符、页或 MIME 改变、裁区/安全边距改变、旋转/crop box/变换变化、
渲染器或模型/提示版本变化均自然生成新键。定向问题使用 UTF-8 原文的 SHA-256；不得仅按
归一化关键词合并不同问题。通用转写没有问题字段，不能命中定向缓存，反之亦然。

授权不编码进可复用内容键，但**每次取缓存前仍重新做 B 的授权和版本检查**；知道缓存键不
授予访问。只缓存结构完整的 `succeeded` 或明确列出缺项的 `partial` 结果。失败、超时、无
凭据和协议模拟不进入成功缓存；如实现短期退避，只能放在独立 failure namespace，且绝不能
返回为已读内容。缓存文件原子写入，先写临时文件、校验长度与哈希后再替换；损坏条目删除并
重算。并发同键用单航班锁，不同键不得互相污染。

D04 报告按以下矩阵分列，不能互相顶替：

| 类别 | 是否外发 | 汇总状态 | 可证明什么 |
| --- | --- | --- | --- |
| `real_provider` 成功/部分 | 是 | `succeeded/partial` | 公开图片被指定真实模型读取；记录模型、输入哈希、耗时与脱敏调用计数 |
| `real_provider` 调用失败 | 是 | `failed` | 已尝试真实调用及其脱敏失败类型，不能证明图片内容已读 |
| `cache_reuse` | 否 | 沿用原真实记录的 `succeeded/partial` | 完全同键复用；须回指原 `real_provider` 记录 |
| `mock_protocol` | 否（模拟 transport） | `not_attempted/mock_only` | 只证明请求/响应、失败和缓存协议，不计模型质量 |
| `not_attempted` | 否 | `not_attempted` | 展示但未读、未配置 provider，或输入在调用前不受支持；记录具体 capability reason |

若凭据可用，D04 至多对公开 fixture 做有界真实调用；凭据不存在时不得外发，记
`not_attempted/provider_not_configured`。服务调用已经发出而失败时记 `failed`。两者都保留
未测项，不能用模拟结果补成“真实通过”。
