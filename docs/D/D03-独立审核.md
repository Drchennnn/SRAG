## 当前阻断缺陷：预发送配置错误被误计为真实外呼

在解析修订冻结件上，以 `execution_kind=real_provider`、非空测试凭据和
`base_url="not-a-valid-url"` 请求公开 PDF。httpx 在本机 URL/协议校验阶段抛
`UnsupportedProtocol`，请求不可能离开进程；实际结果却为：

```text
status=available
read_status=failed
external_call_count=1
ReadRecord.execution=real_provider
ReadRecord.external_call=true
missing_or_error=['provider_UnsupportedProtocol']
```

D01/D03 的口径要求：未配置或输入在外发前失败属于未读，只有已经发出真实调用后发生超时、
限流、HTTP 服务错误或响应损坏才计真实外呼。当前实现对 `provider.read()` 内所有
`httpx.HTTPError` 一律计 1，因而会把本地无效 URL/协议配置冒充成一次实际外部调用；这会污染
D04 的真实调用审计。

返工要求：在初始化或外发前验证 provider URL，或单独处理 `UnsupportedProtocol`/
`InvalidURL` 等明确的预发送错误，返回 `not_attempted` 与适当 capability reason、
`external_call_count=0`，不生成 real-provider 失败记录或缓存；补真实 ASGI/服务层回归，同时
保持连接已尝试、HTTP 错误和响应损坏的既有脱敏计数。修复后重新冻结 core、测试和作者报告并
送独立复审。
