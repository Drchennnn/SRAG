## 阻断缺陷与复现

D01 §5 明确要求“并发同键用单航班锁”。当前 `_artifact()` 在读取缓存未命中后直接进入
PDF/PPTX/Notebook 渲染，没有同键锁或 in-flight 合并。独立探针在空缓存上以两个线程同时请求
完全相同的 PDF `SourceKey + content_sha256 + epoch + rendition`，给 `_render_pdf_page` 增加只计数
和短暂等待的包装后得到：

```text
{'render_calls': 2,
 'statuses': ['available', 'available'],
 'cache_hits': [False, False]}
```

预期是同键只渲染一次，另一请求等待并复用同一产物。当前结果会让昂贵的 LibreOffice/PDF
渲染重复执行；高并发时还会绕过单航班所承诺的资源边界。原子 `replace` 只保护最终缓存文件，
不能满足该契约。

返工要求：为 rendition key 增加进程内同键单航班（不同 key 不互相阻塞），补充确定性的并发
回归测试，证明同键渲染调用次数为 1、两请求产物哈希一致且后继读取为缓存命中；修复后在上述
冻结件和共享整合快照上重新送独立审核。
