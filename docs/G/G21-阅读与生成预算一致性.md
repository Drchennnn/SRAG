## 0. 一条真实网页问答直白说明：以前为什么退回摘录、这次送进模型哪些证据、用户最终看到了什么

1. **以前（基线 `6b3e81a` / `d993748`）为什么退回英文摘录？**
   - 阅读窗口 `read_window` 按**单次 JSON 序列化**估算开销：用固定常数 `1800 + estimate_input_budget([question, context]) = 2,074` 字节作提示词预留，算得阅读预算 `30,694` 字节；每段元数据漏计了 `file_name`、`id`、`reads` 包装且未计二次转义，最终选入 **15 个片段**（`page:1`..`page:8`、`page:7:table:1..3`、`page:9 [0..202]`、`page:11 [0..469]`、`page:12 [0..826]`、`page:12:table:1 [0..606]`），自认为仅用 `30,662 <= 30,694` 字节。

## 2. 统一预算架构设计与降级契约（任务要求 2）

1. **同一最终消息表示的精确可加分解**：
   - 最终发往 DeepSeek 的请求体中，`messages` 为 `[{"role": "system", "content": instructions}, {"role": "user", "content": json.dumps(prompt_data, ensure_ascii=False, separators=(",", ":"))}]`，总输入预算估算值为 `estimate_input_budget(messages) + _CHAT_FRAME_RESERVE`（单位：UTF-8 序列化字节；与供应商返回的账单 `total_tokens` 分别记录在 `trace["generation"]["estimated_input"]` 和 `trace["generation"]["total_tokens"]`）。
   - 在 [app/rag/workspace_generation.py](../../app/rag/workspace_generation.py) 中提取 `estimate_prompt_reserve(question, mode=mode, context=context, coverage=coverage)`，精确计算 `"evidence": []` 时的最终消息固定开销 `fixed_overhead`。
   - 在 [app/rag/workspace_reading.py](../../app/rag/workspace_reading.py) 中新增 `estimate_embedded_json_budget` 与 `estimate_embedded_text_budget`：
     - 第 `idx` 个候选片段的元数据开销 `metadata_size_for(idx)` 按最终 `prompt_data["evidence"]` 的真实字典骨架 `{"id": f"ev-{idx}", "source": ..., "file_name": ..., "locator": ..., "reads": [{"method": ..., "status": "succeeded", "text": ""}]}` 计算二次 JSON 转义字节数（`idx > 1` 时含列表逗号 `1` 字节）。
     - 片段文本 `text[offset:end]` 的开销与二分裁剪函数 `_fit(text, start, budget)` 均按 `estimate_embedded_text_budget`（二次 JSON 转义后的字符字节数）计算，并保证裁剪出的片段非纯空白（`text[offset:end].strip()` 非空）。
   - 单文档全文检测兼容 `"full_text_scope": true`（4 字节）与 `false`（5 字节）的 1 字节差异，确保在任意边界条件下 `trace["reading"]["estimated_message_input"] == trace["generation"]["estimated_input"]` 恒成立（误差 `0` 字节）。
2. **生成预检的按实际开销缩减与引用一致性保障**：
   - 当 `generate_response` 被直接调用（包括 `_rewrite_previous`、`_answer_composition`、`compare_versions` 或单元测试）且传入的 `evidence` 超出 `input_budget` 时：

   - **路径三（模型失败）**：预算预检通过后模拟供应商抛出异常（HTTP 503 / `RuntimeError`），系统记录 `generation.status = "provider_error"`，自动退回 `excerpt_fallback`（`回答模型未能生成可核对的答案。本条保留已读原文摘录。`），已读原文摘录及其引用按钮仍可正常打开（HTTP `200`）。
