## 实际运行及保留的缺项

新编 Basalt Latch PDF、PPTX 与两个 Notebook 文件，在 ASGI 三个空库、网页一个空库运行。环境和文件哈希见[公开结果](./结果.json)。

- ASGI 跨文件定义与留出集实验由 `evidence_answer` 完成，返回严格高于 8 V 的定义和 4 个样本、MAE 0.26 至 0.19。可核对 PDF 第 1 页与 Notebook 文字。PPTX 完成导入，未专门验收 PPTX 图像渲染。
- ASGI 盐雾反例出现**条件误配**。回答沿用了留出集数值，现有原件无盐雾观测。保留原答与候选、引用，不计为通过。
- ASGI v1 图序成功定位 `cell:0:output:1`，回答 `Voltage [mV]`。提供者实际图片 SHA、已保存 read 及引用预览 PNG 摘要相同。替换发布 v2 成功；不重选焦点的首轮报 `stale_reference`，后续指代仍提示旧图。v1 预览在发布 v2 后返回相同字节；v2 实时视觉未完成，保留失败。
- Chromium 从空库导入三格式，正常发送组合问题并实际点击 PDF 第 1 页与 Notebook Cell 1。生成 `partial`，可见结论与两个引用保留。导出会话、目录和引用元数据。首个网页探针在服务退出时丢失延后写入的 provider 文件，已保存的 ASGI 检查点保留。补演练只启动新网页空库，提供者记录每次完成立即写盘。该补演练实际调用均为 200。

持久化核对包括 turn 的状态、trace、scope、候选及实读区间，消息的正文、引用、`revision.source` 三元组、内容摘要与发布代次、`reads.actual_source`、`method`、`status`、实际输入摘要，图块的 `display_source` 和可见序号，以及导出时的预览 HTTP 状态和字节 SHA。浏览器和 ASGI 分别导出。公开封存索引核验 12 个成员，只读 SHA-256 为 `def2a928e4ecf12ccbd7b1d06573df9dbf738aeff4ebd7b8ad7527e1ac5dfa36`。公开结果为原始导出的节选。

## 正式执行与独立评分交接

1. 主审签发受测产品 SHA、正式复测授权与分角色交接。执行员远端回读后新建干净归档，核验原运行器摘要、原锁逐成员、原件版本、历史封存哈希及本机配置。验证 Python、OS、浏览器和如适用的 LibreOffice 版本。配置或运行器差异先交主审确认。运行角色仅接触题面和操作步骤。
2. 用空库和题间隔离的 SQLite、原件、视觉缓存，按固定题序单次运行，记录问题、范围、发布事件、响应、候选、实读、裁区、实际出站和失败。服务调用失败保留，冷热与缓存另记，并保留未测项。新档命名绑定 SHA，逐成员校验、只读封存，原首跑保持独立。
3. 评分员独立核对候选、锁和封存成员后，再访问批准的原件和答案键。按 G01 逐题记录空白、部分或完整，用已读片段和实际画面核事实、单位、条件与引用，双轮合并后汇总各固定分母。旧提示或图块形状与评分辅助器不兼容时，保留首个评分错误，兼容性处理单独核对，不更换判据或重交题。评分产物另档封存，主审只接收可公开聚合及受限档的交接。
4. **已就绪**。固定 SHA、公开配置对照、真实 ASGI/网页入口、版本化证据及导出、样例封存验算。**待处理**。正式运行器与锁定材料的授权校验、独立评分员交接、公开替身的条件误配与 v2 焦点未达。当前运行并未覆盖原分母，也没有替代未测的独立评分。
