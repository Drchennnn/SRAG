    if (image && (!text || image.rendition_kind === "object_crop")) {

### 必改项 3：第 3.3 节 `X1` 水平栏切分与 `X2` 公式编号判定存在确定性逻辑冲突
- **排版与逻辑依据**：
  - 标准 LaTeX 学术论文（无论单栏还是双栏）的独立编号公式均采用“主体居中、编号 `(1)` / `(2.3)` / `[4]` 靠栏右缘对齐”的排布，公式主体右端与编号左端之间的水平空白通常高达 `40–180 pt`。
  - `G29-设计.md` 第 3.3 节 **X1** 规定同一 `y` 桶内凡 `dx > max(20.0 pt, 2.2 * median_line_height)` 即无条件切分为独立行片段。若在 **X2** 之前无条件执行此切分，右缘公式编号 `(1)` 会被永久切离成孤立碎片（不含运算符因而无法通过 X2），公式主体则丢失编号标签，导致 **X2 条件 (b)** 在真实 LaTeX 论文中普遍失效。
  - 同时，真实 LaTeX 分式（上下分子/分母）与分段大括号公式在垂直方向跨越多个小字号行，相邻子对象 `y` 差常超出 `4.0 pt` 且水平居中对齐，若未明确同栏垂直归组，易将同一独立公式拆碎或漏检。
- **修改要求**：
  - 在 **X1 / X2 / X3** 中补充明确的**同栏右缘公式编号重关联规则**：先识别页面单/双栏边界，再对同栏内仅包含公式编号模式（`^\(\d+(?:\.\d+)?\)$` 或 `^\[\d+\]$`）且位于栏右缘、与左侧居中数学行垂直范围重叠的碎片，**重关联并合并至该公式块**，而非切分丢弃；同时明确分式/分段展示公式在同栏内的紧邻垂直合并护栏（确保仍不吞入上方/下方常规散文段落）。

### 必改项 4：第 3.2 节 `V5`（`Form XObject`）与第 3.1 节 `T2`（多表分组）存在真实排版过严/过宽缺陷
- **逻辑依据**：
  1. **`V5` 边界与重叠过严**：真实 LaTeX `\includegraphics{fig.pdf}` 嵌入的 `Form XObject` 原始 PDFium 边界常因裁切框/出血/字形外框略微超出 `page_bbox` `0.5–6 pt`，要求“边界严格在 `page_bbox` 内”会系统性漏登有效矢量图；要求“不与其他 Form 重叠”在相邻子图标签微擦边或父/子层叠 Form 场景下也会直接误弃。此外，`page.get_objects(max_depth=1)` 无法读取 `Form XObject` 内部子对象，设计需写明如何通过 PDFium Form 子对象遍历接口（`FPDFFormObj_CountObjects` / `FPDFFormObj_GetObject` 或有界递归）检查内部是否含路径/图像并正确评估 `V3` 复杂度。
  2. **`T2` 分组阈值过大且过早截断**：`0.35 * page_h`（Letter 792 pt 上高达 `277 pt`）远超同页上下并排多张 booktabs 表的典型间距（常见 `50–160 pt`），容易把同页多表长期留在同一组中；同时 `pdf_tables.py:36` 的均匀网格拒收目前位于分组切分之前，可能误杀带多个分组横线的真实三线表；且子窗扫描应允许在同一横线组内提取**多张互不重叠合法表**（并放宽单页多表时的横线数上限，不止步于 `len <= 12` 或首张命中即 `break`）。
- **修改要求**：
  - 修订 **V5**：将“边界严格在 `page_bbox` 内”改为“与 `page_bbox` 交集占自身面积 `>= 0.90` 后夹紧至 `page_bbox`”；将“零重叠”改为按重叠面积占比阈值（如 `overlap / min(area_a, area_b) <= 0.15`）判别，并明确 Form 子对象遍历方式（用于区分纯文字流与真正含路径/图像的矢量图并接入 V3 过滤）。
  - 修订 **T2**：先执行 T1 剥离与基于“表间非表格正文/表注行或较小间距阈值”的子组切分，再执行均匀网格检查；子窗扫描支持同一组内提取多张互不重叠合法表并明确上限防组合爆炸。
