## 产品与架构

目标是让学生在一个课程网页工作区导入 PDF、PPTX、Notebook，按课程或选定文件提问、看原件、追问或比较版本。原 SRAG 的向量/混合检索、旧问答及评估入口有兼容价值。SAG/Carbon 提供了本地资料优先、按需解析与判断相关性的参考。现行 SRAG 同时承担课程范围、版本化引用、视觉实读和跨轮一致性。实现现状、参考设计和后续产品计划须分开陈述。

| 部分 | 主要职责和交界处 |
|---|---|
| A/B | 约定 document_id、version、source_id，分开对象身份与消息中的展示身份。原件留本地，解析后在 SQLite 发布当前版本、结构和 FTS。切换版本、按历史版本回原件、拒绝迟到写回要一致。入口可从 app/rag/parsers、app/stores/local_library.py 追查。 |
| C/D | C 在本轮授权范围定位对象，用显式位置、FTS、结构邻接及有条件的双语改写找候选。D 读取原文、表格、裁区或 Notebook 保存输出，必要时定向读图。候选、展示、实读要分别留证，点击引用需还原同版对象。 |
| E/F | FastAPI /workspace/ 及工作区 API 提供统一发送、侧边阅读、会话和焦点。app/rag/workspace.py 协调路由，workspace_versions.py 处理跨版。对话记住消息展示顺序和既有读取，换范围后重新校验依据。跨文件问题按定义、条件、实验等拆缺项，用实读锚点最多补查一次；生成链见 workspace_generation.py，确定性条件判定见 evidence_supplement.py。 |
| G 及后续 | G 集成并评估上述链路。H 为单课程知识图谱，J 为同预算评分对照，K 为最终交付，R 为历史人工复核。桌面扩展属后续。M2 仍返工，H/J 与桌面端未放行。 |
