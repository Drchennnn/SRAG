## 从空数据目录开始人工试用

以下从已复核的候选提交启动单独工作树和空数据目录。用当前仓库已安装的 Python 依赖。需要查看 PPTX 裁图时，配置 `SRAG_SOFFICE` 为本机 LibreOffice 可执行路径。

```sh
repo=/Users/Link/code/SRAG
trial="$(mktemp -d /tmp/srag-m2-trial.XXXXXX)"
git -C "$repo" worktree add --detach "$trial/code" 733da32ac9f5440eac59a6505bf6e561d88b7c35
mkdir -p "$trial/courses"
cd "$trial/code"
COURSE_ROOT="$trial/courses" DATA_DIR="$trial/data" SQLITE_PATH="$trial/data/library.sqlite3" \
  WORKSPACE_COURSE_IDS=trial SOURCE_VISION_ENABLED=false QDRANT_URL=http://127.0.0.1:1 \
  "$repo/.venv/bin/python" -m uvicorn app.main:app --host 127.0.0.1 --port 18880
```

1. 打开 `http://127.0.0.1:18880/workspace/`，展开「导入资料」，课程选 `trial`。选择你自己的 PDF、PPTX 或 Notebook，点击「开始导入」，查看每份资料的版号。
2. 用自己的话提问并保留原问题。打开回答的「依据」或图片卡片的「回原件」，记下文件名、版本、页或 Cell、原件能否打开，以及高亮框实际圈中的内容。换版后可在原消息重开旧引用核对。
3. 在浏览器 Network 中保存对应 `POST …/turns` 的响应。`message.sources[*].revision.source` 有 `document_id/version/source_id`，`locator` 定位页或 Cell。`message.blocks` 的 `source_image.display_source`、`rect_visible_norm` 和 `read_status` 记录实际展示和视觉状态。`message.sources[*].reads` 记录实际读取对象、方法、状态、图片摘要和来源；结合 `turn.trace.external_call_count` 及 `vision` 区分真实外发、缓存和失败。若没有读图记录，按未读取记。只在本机保存你自己的试用内容。

启动命令默认关视觉，仍能验证定位、查看原件及原生读取。若要实测视觉，启动时可把 `SOURCE_VISION_ENABLED` 改为 `true`，并在 uvicorn 命令后加 `--env-file "$repo/.env"` 使用本机已有模型配置。模型接收当前问题及系统为当轮选定的图片。在同一版本和裁区重复相同问句可观察缓存。

主会话在 `733da32ac9f5440eac59a6505bf6e561d88b7c35` 的独立检出实测这条启动和导入路线，确认从空库进入 `trial`、导入成功、回答显示视觉未读取。该提交的 `tools.chat`、`tools.workspace_chat`、`tools.evidence_answer` 的 `--help` 全部退出 0。
