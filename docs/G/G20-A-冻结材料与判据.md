### 2.2 每个必需证据单元（`E01`–`E17`）的五层记账规则

按 [G20 证据断点诊断协议](./G20-证据断点诊断.md) 对 11 题（12 轮）共 **17 个必需证据单元** 逐层记账，**父页/父 Cell** 与 **精确对象** 分别统计，并同时报告**总体分母**（17 个父页单元、8 个精确对象单元）与**进入该层的条件分母**（仅计上一层成功或不适用的单元，避免将上游一次失败重复算作下游五次失败）：

1. **入库可定位（Layer 1）**：导入后 SQLite 中是否存在对应版本的父页/父 Cell；若题目指向具体表、图或保存输出，该目标是否登记为独立 `page_object` / `notebook_output` 或具备可核验裁区（纯页级文本证据在“精确对象”列记为 `不适用`）。
2. **进入候选（Layer 2）**：该轮检索产生的候选池（`candidates` / `candidate_pool`）是否包含目标版本键并记录排名。若单文件直读、显式页/Cell 直读或按上一轮展示序号直读绕过词法检索，则在候选排名列记为 `不适用`。
3. **入选（Layer 3）**：经排序、预算截断（如 `budget=4` 或 `object_choices` 方位筛选）后，该对象是否进入本轮送去阅读的 `selected` / `preferred` 集合；未入选时记录截断或筛选原因。
4. **实读（Layer 4）**：`read_window`、`_read_text` 或 `SourceVisionService` 是否实际读取了该对象的文字范围或图像字节（核对 `text_span`、`actual_input_sha256`、`rect_visible_norm` 与 `origin_execution="real_provider"`）；区分仅展示未读、真实调用、缓存命中与父页回退。
5. **答案采用（Layer 5）**：最终中文回答的结论、适用条件和引用 ID 是否由该实读对象正确支撑，且引用在网页/API 可点开对应版本原件。遇合理澄清（`Q10`）或缺证场景（`Q11`），按冻结预期判定。串版、串对象、把未测值当实测或用其他条件数值代用均单独记为**严重错误**。
