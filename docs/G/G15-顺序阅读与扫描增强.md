# G15 顺序阅读与扫描增强

`read_window` 读取已发布的快照。原生 PDF 页、PPTX 页和表格、Notebook Cell 及文本输出按文档内部次序返回。每段记录 `document_id/version/source_id`、页或 Cell、原字符串的字符起止位置和原文摘要。PPTX 同页重复文本框可以跳过。数据行与原生表头保留在同一来源。图片和图表的展示与实读由视觉路径另记，文本窗口给出未读的可定位图像。

预算同时检查模型上下文、单次输入上限、提示预留与最多输出预留。官方默认 `deepseek-flash` 使用 1,048,576 上下文，工作区的单次输入上限默认 32,768，自定义端点可设 `DEEPSEEK_CONTEXT_TOKENS`。UTF-8 JSON 大小仅用于保守估算预算，账单用量由供应商返回。[DeepSeek 模型元数据](https://api-docs.deepseek.com/api/list-models/)

文本可放入预算时按顺序读完。较长时返回目录及标题、先安排已验证关联位置，窗口内保持原文顺序。游标绑定当前范围、版本、发布代次、原件哈希和可读段集合。续读输出下一窗口，记录已过区间、超预算和缺少文字的原因。实际送入回答模型的段落与引用由 G16 独立核对。

## 公开原件验收

| 原件 | 对照结果 |
| --- | --- |
| 8 页英文 PDF | 全量读取页 1–8，核对页 3、5、7 的日期和页 8 的七月条件。缩小预算时先读第 8 页，下一窗口续读后还原 8 页原文。所有读取位置可与发布原文逐字符对照 |
| PPTX 原生表 | 同一 shape 保留 `Frequency [Hz]` 和 `Current [A]` 等表头，Cedar 的 13.75 可回查 |
| Notebook | Cell 0 的文本和 stream 输出 0 可读，图片输出 1 单列为未读，保持输出位置 |
| 扫描 PDF | 先完成原生发布，全文查找该词无命中。按需 OCR 后，`Overview [unscaled]` 可按原页查到并标为 `ocr` |

实测现有 Docling 2.131.0，无需安装新副本。双图和旋转裁边图的定位已由原生导入取得，Docling 也能取得同页标题和图片框。原生空文本扫描页可通过现有 Docling OCR 补 19 字符。实测这份扫描的基础发布约 2.7 ms，后置增强约 6.9 秒。原生 PDF/表与 Notebook 的读取仍沿用现有导入。OCR 支持当前有原件、处于待识别状态的 PDF 页。结果以独立 FTS 来源保存，写入再次检查课程、版本、内容哈希和发布代次。 [实测 Docling 对照](./G15-docling.json) · [读取与增强实测](./G15-reading.json)

## 复现

```sh
reading_trial="$(mktemp -d /tmp/srag-reading.XXXXXX)"
HF_HUB_OFFLINE=1 PYTHONPATH="$PWD" .venv/bin/python docs/G/G15-reading-probe.py "$reading_trial"
.venv/bin/python -m tools.workspace_reading read --course COURSE_ID --document DOCUMENT_ID
.venv/bin/python -m tools.workspace_reading ocr --course COURSE_ID --document DOCUMENT_ID
```

`read` 可用 `--prefer SOURCE_ID` 首读关联部分。要续读，把返回的 `next_cursor` JSON 传回 `--cursor`，保留上一窗口的范围及优先来源。OCR 命令在基础索引已发布后执行，前台问答不承担这一步等待。
