## 1. 直白中文回答三个核心问题

### 1.1 最常见的首个断点是什么？

在真实网页默认配置（`WORKSPACE_ANSWER_ENABLED=true`、`strategy=fts`、`SOURCE_VISION_ENABLED=true`，11 题 12 轮共 17 个必需证据单元）下，**7 个单元通过全链路，10 个单元中途丢失**。正确证据第一次丢失的位置并非集中在某一个单点，而是由**三类并列高频的首个断点**共同造成（合计占全部丢失单元的 **8/10**，其余 2/10 为对象登记/方位几何阈值问题）：

1. **首个断点一（占丢失单元 3/10，且同时作为次生断点阻断所有读满单窗的长文）：读后生成预检的二次 JSON 转义预算失配（Layer 5 `budget_exceeded`）**。
   - 在 `Q01`（`E01, E02, E03`）中，`Mixtral` 论文的第 1、2、3 页其实**已经 100% 入库、进候选、入选并由 `read_window` 完整实读**（装入 `30,662 <= 30,694` 字节）。
   - 但在送给 DeepSeek 前，`generate_response` 先将 `prompt_data` 序列化为 JSON 字符串放入 `messages[1]["content"]`，再调用 `estimate_input_budget(messages) + 128` 对 `messages` 做**第二次 `json.dumps`**，把每段 PDF 文本与 JSON 结构里的所有 `"` 和 `\n` 二次转义为 `\"` 与 `\\n`，凭空多出约 `1,200` 字节加上每段 `file_name`/`reads` 包装开销，使 `estimated_input` 达到 `33,939 > 32,768`（`workspace_input_token_limit`），**在真正调用模型前被本地拦截为 `budget_exceeded` 并退回英文摘录**。任何字符数超过 `30,000` 的真实课件只要装满单轮阅读窗口，都会 100% 撞上这堵墙。
2. **首个断点二（占丢失单元 3/10）：自然中文问法误入专用死胡同规则路由（Routing -> Layer 2/5 断裂）**。
   - 用户用自然中文问“定义…实验…”（`Q07`：`E10, E11`）时，被 `asks_for_definition_and_experiment` 劫持进 `_answer_with_supplement`（`SupplementRetriever`）：检索候选上限从 12 被砍到 `top_k=2`（直接把 `E11` Notebook 实验输出挤出候选），且对已实读的 `E10`（`Mixtral page:2`）强制要求行首匹配 `^(Definition|定义):` 僵化正则，**全程不调用 DeepSeek 即拒答**。
   - 用户在换版后用自然中文问“跟上一版相比…有什么变化？”（`Q09`：`E14`）时，因未同时写出冗余词“新版/当前版”且不属于 6 字短句“和旧版相比呢”，被 `is_version_comparison` 漏判，误入只查当前版 v2 的普通检索，导致 SQLite 历史库中完好可取的 v1 证据（`E14`）在 Layer 2 根本未被召回。
3. **首个断点三（占丢失单元 2/10）：长文与跨文件下纯中文对英文原件的 FTS 词法漏召回及融合池无文字图片占位挤出（Layer 2/3 断裂）**。
   - 用户用纯中文问 27 页英文长文的附录超参（`Q05`：`E07` `DPO page:20`）时，默认 `fts` 零种子（`no_text_anchor`），浏览回退只覆盖前 12 页且窗口预算在第 7 页耗尽，`page:20` 在 Layer 2 漏召回。
   - 跨文件提问（`Q06`：`E09` `DPO page:20`）时，`fts` 仅命中高频词 `Mixtral`/`DPO` 所在页；切到默认 `bilingual` 后，英文改写虽已在 `alternate_pool` 第 6 名召回 `DPO page:20`，但 `_fuse` 因保留 2 个无文字图片邻居（`page:6:image:1`、`page:2:image:1`）将其挤到第 13 名（掉出 `pool_cap=12`）；剔除无文字图片后 `DPO page:20` 排第 11 名进入候选池，但在 `bilingual` 下又被 `budget=4` 截断在 Layer 3。
4. **其余两项对象级首个断点（各占 1/10）**：
   - `Q02`（`E04`）：真实论文的 LaTeX 三线表（`booktabs`）没有竖线，`_confirmed_pdf_tables` 未将其登记为 `page_object`（Layer 1 精确对象未登记），而 `_answer_object(kind="table")` 拒绝回退读取已含完整表格文字的父页 `page:8`。
   - `Q03`（`E05`）：第 5 页右图 `page:5:image:1`（`bbox=[0.444992, 0.688088, 0.800889, 0.863947]`，水平中心 `0.623`）已精确登记并进入第 5 页图像候选池，但 `workspace_objects._on_side("right")` 硬编码要求左边界 `x0 >= 0.5`，因纵轴标签探至 `0.444992` 在 Layer 3 被误筛。

### 1.2 哪种单项改动确实救回了哪些题？

1. **`C1`（对齐 `read_window` 的 `prompt_reserve` `+1,600` 字节，消除 `generate_response` 二次 JSON 转义 `budget_exceeded`）**：

   - **救回题目**：**`Q02`（救回 `E04` 父页级支持 1/1）**，以及样本外 **`H02`**（`PagedAttention` 第 9 页 Table 1 的 KV 缓存容量与最大槽位数）。注：按协议整页答对仅计**父页级支持**，精确表对象仍为 `0/1`。
3. **`C2b`（放宽 `workspace_objects._on_side("right")` 允许水平中心 `(x0+x1)/2 >= 0.55` 且 `x0 >= 0.4` 的右半页图像入选）**：

4. **`C3a`（开启 `WORKSPACE_RETRIEVAL_STRATEGY=bilingual` 双语改写召回）**：
   - **救回题目**：在 **`Q05`（`E07` 27 页长文第 20 页）** 上单独救回 **Layer 2（进入候选 #1）、Layer 3（入选 #1）与 Layer 4（实读 `ev-7`）**；叠加 `C1` 窗口预留修正后**完整救回 `Q05`（`E07` 1/1）**，并在样本外 **`H03`（`PagedAttention` 第 13 页）** 上完整救回长文后段纯中文问答。
5. **`C3b`（`_fuse` 排除无文字图片占位 + 在相同 12 文本候选池上启用 `jev` `Zev-1` 评分排序）**：

6. **`C4`（移除 `asks_for_definition_and_experiment` 非模型僵化正则劫持 / 采用 `max_steps=2` 有界 SAG 式工具选择）**：

### 1.3 下一项最值得做什么、什么证据会推翻这个建议？

- **下一项最值得做的工程动作（按投入产出比排序的最小主路径收敛包，建议在架构负责人放行后实施）**：
  **不要推倒重写现有版本化存储、阅读窗口或视觉证据链（Layer 4 实读成功率为 100%），而是优先实施「四项低成本主路径止血修复 + 按需双语/Jev 路由」**：
  1. **消除 `read_window` 与 `generate_response` 的预算计量失配（`C1`）**：统一使用单次序列化长度计量（或在 `read_window` 预留实际 `_INSTRUCTIONS` + JSON 转义开销），彻底消灭读满单窗即 `budget_exceeded` 的自杀式降级（0 额外 API 成本、0 延迟增加，直接救回所有 >30KB 的真实课件问答）。
  2. **解除 `asks_for_definition_and_experiment` 的非模型僵化劫持与放宽 `is_version_comparison` 自然跨版识别（`C4` + `C5`）**：当 `WORKSPACE_ANSWER_ENABLED=true` 时，禁止让不含 LLM 综合的 `SupplementRetriever(top_k=2)` 拦截自然“定义+实验”提问；让 `_OLD + _COMPARE` 的自然跨版提问正常进入已验证可靠的 `compare_versions`。
  3. **显式页表格无 `page_object` 时回退父页原生文字，并放宽页内双图 `_on_side` 中心判定（`C2a` + `C2b`）**：当 `_answer_object(kind="table")` 在目标范围找不到已登记网格表时，回退到 `_generate_snapshot` 读取父页文字（标记为页级引用）；将 `_on_side` 从硬边界 `x0 >= 0.5` 改为中心点结合合理边界。
  4. **在 `_fuse` 中过滤无文字图片占位，并对中文问英文长文/跨文件默认启用 `bilingual`（跨多文件候选 >4 时可选启用 `jev`）（`C3a` + `C3b`）**：单文件短文仍走零额外调用的顺序读全；当 `fts` 种子不足或跨文件检索时启用 `bilingual`（仅 +1 次轻量改写），并在 `_fuse` 中排除 `text=""` 的纯图片邻居。
- **什么证据会推翻这个建议？**
  1. **推翻“三线表只需回退父页文字（`C2a`）、暂不必上重型版面/表格解析”的证据**：
     我们在步骤 D 样本外新资料复核（`PagedAttention-2309.06180v1.pdf` 第 9 页 Table 1，`H02`）中已经观测到一个**真实的边界预警**：当 LaTeX 三线表的某一行没有竖线且各列词面结构不一致（如 `GPUs` 行：`A100 | 4×A100 | 8×A100-80GB` 在 `page:9` 原生线性文本中连成 `GPUs A100 4×A100 8×A100-80GB`）时，虽然父页文字回退正确答出了 `13B/66B/175B` 的总显存（`40/160/640 GB`）、KV 缓存内存（`12/21/264 GB`）和最大槽位数（`15.7K/9.7K/60.1K`），但将 `GPUs` 行的 `4×A100` 错移给了 `13B`。**如果在后续评测中发现多列无竖线表格的列错位频繁发生，或用户必须获得三线表的精确 `object_crop` 裁图，则必须推翻“仅回退父页文字”的建议，优先在 `local_slides.py` 中利用字符横坐标聚类或水平三线规则重建 `page_object` 表格列结构。**
  2. **推翻“用单次 `bilingual`（必要时 `+jev`）而非全面替换为多步 Agent 循环（`C4b`）”的证据**：
     如果在新课程跨文件题集中，目标实验文件既不包含问题中的概念名、也不包含单次双语改写能猜出的英文同义词（例如讲义称某算法为理论名称，而代码 Notebook 只出现自定义函数名 `run_exp_v3()`，必须先读讲义拿到函数名再做第二跳搜索），那么单次 `bilingual + jev` 的召回率将显著低于 `C4b`（有界 SAG 式多步工具循环或 `expanded` 字面锚补查）。一旦此类多跳跨文件题占比高且单跳双语漏召回，应直接切向 `max_steps=2` 的有界工具循环。
