## 4. 对 `Jev` 默认关闭与隔离向量候选的独立复核意见

1. **是否同意默认不开启 `Jev`：完全同意默认关闭（保持 `workspace_retrieval_strategy="fts"` 按需双语）**。
   - **硬载荷边界实证**：在未见 33 页 `ReAct` 上，单页约 3.6k–5.2k 字符，12 候选池输入载荷达 `57,128–61,827` 字节，**5 / 5（100%）直接超出 Jev 48 KB（`49,152` B）上限**被拒；在 `QLoRA` 上也有 **3 / 5（60%）** 触发 `input_limit`（`55,637–56,978 B`）。
   - **净收益为负与截断风险**：`strategy="jev"` 将 `candidate_budget` 收紧为 `4`（即使在 `input_limit` 未真正调用 Zev-1 时也生效），导致 **`QLoRA Q02`**（门审复跑）和 **`ReAct H_Q01`**（未见终验）的正确页（分别排在双语池第 3–5 名之外或因排序波动被挤出 `top-4`）反而在 `jev` 臂**退化失败**，而默认 `g22_bilingual`（`budget=12` 交由 `read_window` 按优先级装满 32 KB 窗口）全部通过。
   - **高延迟与超时代价**：在仅有的成功调用中（如 `QLoRA Q01` `47,577 B`），Jev 首试超时 `15.8 s`、重试 `2.1 s`，单轮总耗时飙升至 `26.06 s`（默认双语仅 `5.8 s`）。因此在无净收益且存在 `top-4` 截断退化风险前，必须维持 `Jev` 默认关闭。
2. **对隔离向量候选的复核意见：同意 G22 不在 `/workspace/` 默认主路径接入向量候选**。
   - 经本机核查，`http://localhost:6333` Qdrant 服务当前离线（`ReadTimeout`），且整个工作区定位为离线可用 SQLite FTS5 主路径。
   - 跨开发/回归（`G20 Q05/Q06` + `QLoRA Q01–Q06` = 8/8）与未见终验（`ReAct H_Q01–H_Q06` = 5/6，其中唯一的 `H_Q03` 原始英文译文亦可将 `page:14` 排到 `#1/12`）实证：一旦双语改写通过校验，BM25 双语词法池已覆盖全部 **14/14** 目标证据页，尚未出现“双语改写通过但词法仍漏页”需要向量兜底的实证缺口。后续若有语义同义词盲区，应在独立隔离评估中单列增量、延迟与索引构建成本后再行裁决。
