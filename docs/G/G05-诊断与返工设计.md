# G05 · 普通提问诊断与返工设计

放行基线为 `96113392f9403f505d4e3416cf39956704abd11f`。用新编公开原件独立检查首问对象、同轮换版和多类材料。A03 封存、原门槛及首跑评分留作 G09 独立复测基线。

## 如何定位

在隔离 SQLite 和公开归档上，从网页原话提交问题。跟踪授权范围和指代、候选、实际选中键和展示键、读取方法和字节、正文和引用。每项以最早缺失的约束定位，后续缺项单列。普通提问的请求不传目标来源键；正例可使用既有的历史卡片契约作为同数据对照。可核对显示字节和来源的未读记录保留 `not_attempted`；真实视觉调用和缓存各自计数。

## 最小实现边界

| 任务 | 输入、选择和证据 | 回退和验收 |
| --- | --- | --- |
| G06 普通首问 | 非卡片问题指定文件内页、Cell、图片输出或原生对象。用已授权的当前快照识别父位置，再在其候选中按可靠的对象类型、位置或独立输出序号消解。原生表格用 B 实读单表；明确需看图时先核对 D 实际选中键、裁区和字节，再按需用当前问题与该图调用 D。显示、实际读取、引用分别记录。 | 两个相似对象、无可信裁区、对象存在但图不可读分列。按页内左右位置只使用原生可信几何或已登记区域。即使目标与回退都使用同一个页键，也须核对裁区与回退状态。不能确认时澄清、给范围或保留未读；可预览父页但不拿来充当子图事实。展示要求不需视觉。原点卡和纯历史引用回归。 |
| G07 范围、图序与版本 | 明确历史词语或点卡使用实际展示序；显式文件/位置或当前焦点使用原件内部顺序。没有可唯一解释的焦点/历史时给可选择的来源。旧侧仅从当前 owner 与 session 的已完成消息取已存版本、来源、可见课程与原件哈希，当前侧独立取同文件及可靠对应位置的当前版本、哈希和代次。提交事务原子校验两侧。 | 无历史、歧义、刷新后选择、两版同时打开、版本/代次失效和删除后拒绝。轮内分别保存旧和当前引用；旧引用依赖已经授权的会话消息，用户文字中的版本号不能扩权。历史图沿 E01 只做校验与渲染。旧侧事实须由同版可实读原生文字、表格或与比较属性一致的既有可信读图支持；旧图仅有像素时允许可点开并说明该属性未读。缺任一侧或不能比较，明确说明缺哪一侧、哪些属性未读。 |
| G08 多类依据 | 仅当提问明示需要三类证据（原理/条件、原生表格、保存的实验输出）才进入组合，原有双角色请求沿 F 原路径。同一授权快照先检索，再原样读取使结论成立的来源；同类支持摘录和实验适用条件经核对才进入答案，每个正文块引用其实际支持的本轮证据。表格必须实读原生对象，父页中的复制文字仅作为线索；输出必须是保存的实测内容，代码、展示或错误堆栈不能充数。只有指标、单位与适用条件对得上才能作数值比较。 | 分别移除一类、替换其条件或单位、把数字移到父页或相邻对象、在另一课放同名真材料。核对缺项提示、原件重开、引用没有串源以及相关数值不被当作目标结论。首轮缺项且能确定取自已读定义原文的专名才补查，同课程与首轮固定文件集合，首轮一查及最多一次补查分别计数。候选与预算取舍保留。保留 F 既有单跳/最多一补与旧样例。 |

G06 和 G08 可并行。Codex 主会话整合 `app/rag/workspace.py`、共享断言和三份治理记录，模块作者各自写入独立模块和对应测试。决策优先考虑已有的显示锚和明确跨版任务，再考虑多类事实组合与明确首问。既有双项 F 问答、普通搜索与总结保留原入口。新逻辑复用 `SourceKey`、发布代次、`TurnEvidence`、消息附件和提交事务的版本复核。只读候选时保持 `not_attempted`，找不到身份匹配的父子或新旧位置时不升格成事实。新增对外交互及已签接口如果确需改义，先记录影响并按仓库规则交接。

G09 从签认后的固定提交另建数据目录。独立执行者先封存 A03 实际响应及证据，独立评分者再按原门槛判分。实现作者只使用公开样例和聚合原因。公开复现的通过不抵销 A03 必达项。任何一项未达，M2 仍为返工。
