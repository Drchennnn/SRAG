# SRAG 架构独立会诊交接 · G19

## 给评审模型的委托

请以独立架构评审身份分析一个课程资料问答产品。用户希望知道为什么多轮工程改进后 M2 仍未通过，以及保留、组合或替换哪些路径最值得。此轮交付分析和可证伪的实验设计。实施、正式复测和新阶段放行留待评审后决定。先独立形成解释，再与下文已有假设对照。欢迎推翻已有判断。

产品希望学生能用中文问英文课件，跨页、跨文件比较，追问“刚才第二张图”或换版前的结果。用户既要读得懂回答，也要能点开当时那一版的页、表、公式或 Notebook 输出核对。原件本地保存，可配置服务处理问题、必要文本和选定图片。网页是当前交付入口。

## 三套架构，三个不同入口

| 对象 | 导入与召回 | 阅读、回答与评审重点 |
|---|---|---|
| 原有 SRAG | 结构化切块，文本及视觉向量化，Qdrant 文本 dense/sparse 检索和 RRF 融合，按需召回视觉页，SQLite 管理文档版本 | 保留了旧检索和聊天入口。审查原有向量能力是否适合当候选生成器，以及其结果能否准确映射到现有版本化对象。旧入口的测试成绩不能直接代替网页验收。 |
| 参考 SAG-Wiki | 本地文件转换与索引，快速搜索；深入检索以 Jev 评估候选证据价值并按需扩展。内置问答可引导模型用中英文等义查询 | 回答模型可主动搜索和分段读取。本机一条真实选定 PDF 会话中，模型仅用两次 read 读完 15,288 字符后综合作答。该例说明指定短文件可直读。独立 CLI 小样中，两条中文查询无命中，手工附英文词后找到条件或图注；当时 Notebook 未被索引。这些是个例，不能推断 SAG 已解决 SRAG 的跨版读图。 |
| 现有 SRAG 网页 | PDF、PPTX、Notebook 入库，SQLite FTS5 和结构邻接为默认；保留当前与历史原件。可选双语、Jev 评分和一次有界扩展。给定单文件且预算足够可顺序阅读 | 生成路径调用 DeepSeek；需要视觉时读取选定对象并记录视觉调用。通过文档、版本、来源标识区分检索候选、展示、实读和引用。已支持追问、换版和侧栏预览。具体行为依赖模式、开关和专门路由，须从网页入口追到实际分支。 |

## 现有解释与尚缺的证据

关闭回答开关会同时改变工作区生成和部分检索规划；有些特殊意图优先走专门分支。需要区分评测配置差异、路由、解析丢失、候选漏召回、排序截断、对象或版本选错、实际读取失败、答案忽略证据，以及评分器漏计。当前聚合数字无法把九个缺失单元逐一归因。尤其要查：图已展示是否真有正确字节送入模型，表和公式是否保留条件，上轮所指是否绑定到当时版本。

已有候选实验是在新公开资料上比较普通网页、给定正确页、给定精确对象与校验字节。请评审这一设计是否遗漏“索引里根本没有该对象”或“开关同时改变多个变量”等混杂因素，可提出更小、更有辨识力的替代。保留 A03 历史口径；生产配置的质量需要单列。使用新公开题诊断，私有答案、保留题逐题轨迹和个人课件留在本机。

## 评审交付

1. 一段面向产品负责人的直白判断，包括是否需要换路径、最重要的理由和可能推翻判断的证据。
2. 从真实入口列出原有 SRAG、当前网页默认/增强/锁定路径与 SAG 的关键差异，特别标出“仓库有实现”与“受测轮次实际执行”的区别。
3. 给出最多三个竞争解释。逐项说明支持、反证、缺失观测，以及失败首次出现在哪一层。不能确定的地方保留为未知。
4. 给出最小区分实验：题材、资料、固定变量、指标和结果如何改变路线。把正确对象是否已索引、是否进候选、是否入选、是否实读、是否用于正确结论分开统计。对照本地基线、真实产品配置及最值得挑战它的一个方案，说明成本与停止条件。
5. 最后给出首选路线、备选路线和切换条件。区分短单文件、长文或跨文件、图表和跨版追问。指出目前最不值得继续投入的一项工作。
