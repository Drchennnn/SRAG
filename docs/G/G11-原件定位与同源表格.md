# G11 PDF 图片定位与同源表格

G10 的 G09 基线显示两处可修复的断点。PDFium 能在原件定位两张独立图，索引只有整页。定向表格问答已有可用的原生值和对象引用，消息缺同一表格的裁图。[G10 基线](./G10-基线诊断.md)

## 来源和坐标

- PDF 图片作为当前版本的 `page_object` 存到页下。读取坐标来自 PDFium，记录原件原坐标、可见页比例坐标及 CropBox 和旋转的变换。左右定位使用可见页比例；裁图和回原页取同一版归档。
- 对扫描、复合图片或存在竞争的未知边界，保留页级访问。无法确认具体子图时提示位置不足或澄清。导入仍以原件内容发布，图像子对象没有虚构的原生正文。
- 旧资料通过重新导入相同的 PDF 原件获得图片子对象。同一事务追加缺失对象，当前发布代次随有效新增刷新，已有页和表的 ID、版本和正文保持可回读。新内容通过原有机制产生新版本。

## 表格回答

普通首问可用“原表”或明确的列位置触发核对。在快照内选定唯一表格后，用其原生读取创建引用，再挂该表格的原生边界裁图。原生值、裁图和引用共用同一个证据 ID。裁图尽量保留原表表头与单位。已有注册局部覆盖可继续在对应原件操作使用，核对原表使用原生表格整框。

消息里的原生读取为 `native_table`。附图只经过渲染时，视觉状态为 `not_attempted`，外部调用为零。裁图不可用时仍给出原生引用及提示。无可靠对象时要求补充位置，失败的渲染不会作为该表格子对象的图片发布。

## 独立验收

`g10_gate` 在冻结候选 `dccbdcf69105ebe871e15c3ea472bd2604bd9e9d` 独立复现。该候选包含本任务全部产品和测试文件，发布提交只再加入报告和治理更新。独立定向测试 99 项通过，含真实 LibreOffice。全量测试 477 项通过。

| 路径 | Chromium 实测 |
| --- | --- |
| 普通与旋转裁边 PDF 首问 | 两份原件分别选中 `page:1:image:2/v1`，裁图可辨识右侧内容，回到原页有可核对的高亮框。图像未尝试视觉读取 |
| 原表与具体列 | `page:1:shape:2/v1` 原生读到表头 `Frequency [Hz]` 及 `Cedar 13.75`。同一证据的图片和引用都能打开，回原页能看到原表。实际视觉调用为 0 |
| 同字节重导与换版 | G09 空库导入后只有页，候选两次重导来源计数为 1→3→3。版本仍为 v1，随后改字节形成 v2。浏览器临时上传路径随重导移动，当前代次按既有规则刷新。v1 页级引用在重导、换版后均 HTTP 200 |
| 扫描、歧义、点卡与权限 | 扫描页与未消歧双图没有读取对象。点卡追问保持同一来源。另一所有者请求媒体返回 404 |

首次独立脚本的 Python 工作树路径与浏览器滚动各出现一次运行器问题。修正脚本后重新用空库执行，只采纳通过源码定位断言的浏览器结果。零真实读图、零缓存读取、零调用失败和零被阻请求。[独立实测数据](./G11-独立实测.json)

## 复现

从本任务发布提交（`git log --grep='feat(G11)' -1 --format=%H`）运行公开浏览器脚本。准备本机 Python 依赖、`agent-browser` 及 LibreOffice。

```sh
G10_SUBJECT="$(git rev-parse HEAD)" G10_SOFFICE=/path/to/soffice \
  SRAG_PYTHON=/path/to/venv/bin/python bash docs/G/G10-browser.sh
```

可在脚本输出找到普通首问请求及实际消息、对照页位置、媒体读取和历史引用。基线与本版可按同名场景对照。该脚本关闭外部模型，图像的横轴内容需要用原件或另行实际读图核验。定向、原件与全量测试在同一产品候选运行，配置 `SRAG_SOFFICE` 时包括实际 PPTX 转换回归。
