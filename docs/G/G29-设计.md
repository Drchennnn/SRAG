## 一、显式四阶段回合管道拆解

### 1.1 现状问题与冲突根因

当前 `app/rag/workspace.py` 同时承担了会话门面、范围/焦点解析、正则意图拦截、历史展示指代、澄清续接、对象消歧、文本/图像实读、生成预算与附件组装，导致：

1. **并行分支直接冲突**：`ed616f2` 在 `_retrieve()` 的 `object_intent` 入口增加 `caption`/`formula` 快照存在性检查，并在 `_answer_object()` 将 `caption`/`formula` 接入文本消歧与裁图；`f6d2c23`/`0f5c93c` 在 `_run()` 增加 `_OUTPUT_ANAPHORA` 与 `owner` 透传，在 `_retrieve()` 的 `object_intent` 后叠加 focused multi-output cell 拦截，在 `_answer_object()` 的 `len(choices) != 1` 叠加 Cell 多输出澄清。两支在同一控制流切口直接碰撞。
2. **焦点状态与文本正则职责倒置**：`_run()` 尚未解析 `session.focus_id` 与当前焦点下的子对象，就先用 `_IMAGE_REFERENCE` 抢跑进入 `_resolve_reference()`，导致聚焦页/Cell 内多图场景与历史展示链路纠缠。
3. **澄清机制不可恢复父动作**：`ClarificationAnchor` 仅支持 `display`、单对象 `current_object` 与普通文档检索三种硬编码动作，无法携带父动作上下文（如跨版比较 `compare_versions` 的历史侧引用与比较属性）。
4. **文本/预览证据口径分裂**：`caption`/`formula` 文本存放在 `locator["object_text"]`，但 `historical_evidence()`、`_scoped_previous()`、`_native_read()` 仍直接校验 `source.text`；`render_citation_preview()` 仅识别 `_follow_display` 写在 `resolution` 里的 `(message_id, display_id)`，未识别挂在当前消息 `blocks` 中的 `source_image` 附件。

### 1.2 四阶段回合管道总览

将 `WorkspaceService._run()` 拆为**顺序、单向、职责正交**的四个显式阶段，`WorkspaceService` 收敛为外层事务/权限门面与管道调度器：

```text
TurnRequest (+ owner, session)
   │
   ▼  Stage 1: Scope & Focus 状态解析 (app/rag/workspace_context.py)
   │  输出: TurnContext { session, scope_snapshot, catalog, focus_state, history_summary }
   │  约束: 纯只读状态装配，不做正则意图判定，不触发渲染/视觉/LLM 调用
   │
   ▼  Stage 2: 统一意图与对象路由 (app/rag/workspace_router.py)
   │  输入: (TurnRequest, TurnContext)
   │  输出: RouteDecision (显式枚举路由 + 目标/参数 + 诊断字段)
   │  约束: 纯决策层，按显式优先级阶梯裁决，彻底消除抢跑与分支冲突
   │
   ├─► Stage 3: 可恢复澄清执行器 (app/rag/workspace_clarification.py)
   │   职责: 统一构造结构化 ClarificationOptionRecord；
   │         在 ClarificationAnchor 续接时执行 7 项权限/范围/版本/会话二次校验，
   │         并恢复 follow_display / read_object / retrieve_document / compare_versions
   │
   └─► Stage 4: 统一证据与预览服务 (app/rag/workspace_evidence.py + workspace_preview.py)
       职责: 统一 readable_source_text() 单一真相源；
             统一对象文本/裁图/视觉实读附件组装；
             统一 /media/{display_id} 与 /evidence/{eid}/preview 对称校验与 /evidence/{eid} 200 契约
```

### 1.4 统一路由优先级阶梯（彻底消除两支冲突）

`workspace_router.py` 按以下 **6 级确定性顺序** 判定 `RouteDecision`：

1. **Level 1 · 显式前端锚点（零正则）**：
   - `DisplayAnchor` → `FollowDisplayRoute`
   - `ClarificationAnchor` → `ResumeClarificationRoute`（进入 Stage 3）
2. **Level 2 · 非 `ask` 模式**：
   - `kind in {"search", "summary"}` → `RetrieveOrGenerateRoute(mode=kind)`（若 `summary` 多文档，在执行阶段走单文档澄清）
3. **Level 3 · 跨版本比较与跨版本对应对象（允许陈旧焦点下的单文档历史恢复）**：
   - `is_version_comparison(text)` → `CompareVersionsRoute`
   - 命中显式新版对应指代（匹配 `_CURRENT_VERSION` 且不匹配 `_OLD_CH_VERSION`/`_OLD_EN_VERSION`，且无显式展示序号 `_ORDINAL`）→ 探测 `resolve_current_counterpart`：若返回 `resolved` / `ambiguous` / `deleted`，进入 `CurrentVersionCounterpartRoute`；若返回 `none`（无跨版历史）则继续向下。
4. **Level 4 · 显式历史回看指代（绝不借用当前焦点）**：
   - 命中显式历史词（`_HISTORY_IMAGE`，含 `0f5c93c` 扩展的带中文定语/动词修饰表达如 `"刚才读过的旧版图"`）或 `_OUTPUT_ANAPHORA`（且非实验/定义问法）→ `HistoryDisplayReferenceRoute(explicit_history=True)`：
     - 优先使用 `history.latest_single_vision_read`（当无显式序号且上一轮存在唯一已实读图像，区分“仅展示多图”与“已实读单图”）；
     - 否则按 `history.latest_visible_displays` 序号定位或列出可点击 `display` 澄清；
     - 若会话内无任何已完成图片回答，直接返回无历史图澄清（`options=[]`），不借用当前焦点对象。
5. **Level 5 · 焦点优先消歧与显式对象/表格路由（两支收敛点）**：
   - 若 `focus_state.status == "stale"`（已排除了 Level 3/4 的跨版与历史回看）且未显式切换文件 → `StaleFocusRoute`（抛 `WorkspaceError("stale_reference")`，保留 `"看当前 Cell"` 对照语义）。
   - 若命中显式文件切换（`_FILE_MENTION` + `_affirmed_switch`）→ 跳过焦点绑定，进入 Level 6。
   - **焦点优先图/对象消歧**（详见 2.1 节）：
     - 若问句含指示性图指代（`"这张图/那张图/图里"` 等，无 `_HISTORY_IMAGE`）或 `object_intent(text, include_reference=True)` 命中，且非显式其他页/Cell 位置：
       - 若为裸序号（如 `"第一张图/第二张图"`，不含 `_CURRENT_IMAGE`）且同时存在 `focus_state.status == "valid"` 与 `history.latest_visible_displays`，先执行焦点-历史冲突检查（冲突时返回范围澄清，保留既有 G07 语义）；
       - 若 `focus_state.status == "valid"` 且焦点为 `page` 或 `cell`（或已聚焦 `document` 且无前轮展示图），在焦点范围内直接路由到 `TargetObjectRoute`（支持 `image`/`table`/`caption`/`formula` 与 focused multi-output cell）；
       - 若 `focus_state.status == "none"`：有前轮展示图且命中 `_IMAGE_REFERENCE`/`_ORDINAL` 时走 `HistoryDisplayReferenceRoute(explicit_history=False)`；无前轮展示图时走 `TargetObjectRoute`（在当前文档范围消歧或出可点击候选）。
   - **显式对象意图路由**（带显式页/Cell/文件名，或任意范围 `object_intent(text)` 命中）：
     - 若 `intent.kind in {"caption", "formula"}` 且 `scope_snapshot.sources` 中**不存在**任何对应 `page_object`（例如纯 Notebook 或无公式/图注对象的 PDF），安全忽略该 `object_intent` 并落入 Level 6（完整承接 `ed616f2`）。
     - 否则路由到 `TargetObjectRoute`（由 Stage 3 统一处理多候选澄清，消除 PDF 与 Cell 行为分裂）。
   - **聚焦多输出 Cell 的非图通用输出问句**（承接 `328ae63`）：
     - `focus_state.status == "valid"` 且 `focus_state.source.kind == "cell"` 且 `len(focus_state.child_outputs) >= 2`，问句命中 `_CELL_OBJECT_QUESTION`、非纯预览、无显式输出/图序、非复数对比、非定义/实验 → `FocusedCellOutputsRoute`（返回带全部可选图像/文本输出的 `ClarificationAnchor` 列表）。
   - **历史表格指代**：`_TABLE_REFERENCE`（无显式位置或含 `_PREVIOUS_TURN`）→ `FollowTableRoute`（若无历史表则回退 Level 6）。
6. **Level 6 · 跨类组合、补查与常规检索/生成**：
   - `asks_for_composition(text)` → `CompositionRoute`
   - `not workspace_answer_enabled and location is None and asks_for_definition_and_experiment(text)` → `SupplementRoute`
   - 其余 → `RetrieveOrGenerateRoute(mode="ask")`

**冲突消除证明**：`731422b` 的 `caption`/`formula` 判定与存在性回退、`328ae63` 的 `_OUTPUT_ANAPHORA` / `resolve_current_counterpart` / focused multi-output cell 拦截，全部成为 `workspace_router.py` 决策阶梯中的独立、有序分支；所有多候选对象澄清收敛到 `workspace_clarification.py`；`workspace.py` 中不再存在互相覆盖的 `if` 补丁。

## 二、四处已知契约裂缝的精确修复方案

### 2.1 裂缝 1：`Q04` 焦点优先消歧与可点击候选闭环

#### 现状缺陷
1. 当 `session.focus_id` 指向含两个矢量子图的 `page:2`，用户问 `"这张图里的曲线趋势是什么？"`（未写页码）时：
   - `_IMAGE_REFERENCE` 在 `_run()` 中抢跑进入 `_resolve_reference()` → `resolve_current_image()`；
   - `_clarify()` 不记录 `trace`（导致 `route=null`、`clarification_reason=null`、`object_candidates` 缺失），提示语为泛化的 `"请明确要读取的当前文件或图片。"`；
   - 若该会话此前有来自其他页/文档的展示图，`_resolve_reference()` 第 777 行会直接返回 `options=[]` 的死路澄清；
   - 若问句包含页码进入 `_answer_object()`，PDF/PPTX 同页多图直接返回无 `ClarificationAnchor` 选项的 `object_ambiguous` notice。

#### 精确修复设计
1. **焦点优先解析规则**（落实在 `workspace_router.py` Level 5）：
   - 对非显式历史（`not _HISTORY_IMAGE`）、非裸序号（`ordinal is None`）的指示性图问法（如 `"这张图里的曲线趋势是什么？"`、`"那张图横轴是什么？"`）：
     - 若 `focus_state.status == "valid"` 且 `focus_state.source.kind in {"page", "cell"}`：直接以 `focus_state.source` 为焦点调用 `object_choices(intent, focus_sources, focus=focus_state.source, region_rects=region_rects)`，**不再被 `_IMAGE_REFERENCE` 截胡为历史回看或无选项泛化澄清**。
     - 若 `focus_state.status == "valid"` 且 `focus_state.node.entry["kind"] == "document"`（如网页点击了文档节点）且无前轮展示图：以该文档下全部符合 `intent.kind` 的对象作为候选池执行消歧。
     - 若 `focus_state.status == "none"`（无焦点）：
       - 存在前轮展示图（`history.latest_visible_displays` 非空）→ **保留既有历史指代语义**（单图直跟 `_follow_display`，多图给出 `display` 澄清选项）；
       - 无前轮展示图 → 在当前 `scope_snapshot` 内收集候选对象消歧（单候选直读，多候选返回带可点击具体选项的澄清）。
     - 若 `focus_state.status == "stale"` → 普通新问（非跨版比较/非显式新版对应/非显式回看旧版）保持返回 `failed` · `stale_reference`。
2. **统一对象歧义澄清输出契约**（同时满足 `Q04` 冻结判据与既有 G25/G26/G24 回归断言）：
   - 当 `TargetObjectRoute` 得到 `len(choices) >= 2` 且非复数对象对比问法（`not _VERSION_PLURAL_OBJECT.search(text)`）时：
     - 从 `ctx.catalog` 映射每个候选到 `(node_id, source)`，最多取前 8 项，构建 `ClarificationOptionRecord` 列表（`kind="document"`，`resume_action="read_object"`，`node_id=...`，`target_source=_key(choice)`，`current_object=(target.kind == "image" or _can_display(choice))`）。
     - 若可点击选项数 `>= 2`，调用 `workspace_clarification.build_clarification(...)`，**设置**：
       - `turn.status = "clarification"`
       - `message.blocks = [{"type": "notice", "code": "object_ambiguous", "text": prompt_text}]`（保留 `code="object_ambiguous"`，确保 `test_g25_workspace_objects_e2e.py` 与 `test_workspace_table_routing_g26.py` 断言全部通过；表格场景继续保留 `_format_table_ambiguity(choices, docs)` 的页号文案）
       - `turn.outcome["trace"] = {"route": "target_object", "clarification_reason": "object_ambiguous", "effective_scope": _effective(docs), "object_candidates": [_key(c).model_dump() for c in choices], "external_call_count": 0}`
       - `turn.outcome["options"] = [...]`（对外投影为 `turn["options"]`，每个按钮对应一个 `ClarificationAnchor`）
   - 若为复数对比问法（如 `"比较当前版里的两张图片有什么区别"`）或找不到 `>= 2` 个有效目录节点，维持 `completed` + `notice(code="object_ambiguous")`（兼容 `test_workspace_versions_g24.py:293`）。
3. **空间方位与对象区分标签**（`format_object_option_label`）：
   - **同页多图像（PDF/PPTX）**：基于同页候选的归一化 `bbox` 计算空间相对关系：
     - 2 个图像水平分离（两框中心 x 分别位于 `< 0.5` 与 `>= 0.5` 且水平重叠率 `< 0.2`）→ 附加方位前缀 `左图` / `右图`；
     - 2 个图像垂直分离（中心 y 分居上下且垂直重叠率 `< 0.2`）→ 附加方位前缀 `上图` / `下图`；
     - 其余多图 → 附加 `图 1` / `图 2` ...；
     - 组合标签：`"{file_name} · v{version} · 第 {page} 页 · {spatial_tag} · {title}"`（无标题时省略末段）。例如：
       - `Vector-Subfigures-Guide.pdf · v1 · 第 2 页 · 左图 · (a) Left Panel: Step Response`
       - `Vector-Subfigures-Guide.pdf · v1 · 第 2 页 · 右图 · (b) Right Panel: Damped Decay`
   - **Notebook 多输出 Cell**：沿用 `"{file_name} · v{version} · Cell {cell_num} · 输出 {out_idx}（图像 | {text_snippet}）"`。
   - **多表格 / 多图注 / 多公式**：`"{file_name} · v{version} · 第 {page} 页 · {_label(choice)}"`。
4. **选定后的实读闭环**：
   - 用户选择某 `ClarificationAnchor` 提交后，Stage 3 校验通过并执行 `resume_action="read_object"`：
     - 图像对象（`page_object` 图像或 `notebook_output` 图像）→ 调用 `answer_current_image`，仅对选定对象发起 1 次真实视觉实读，生成带裁图/原图与引用的回答；
     - 原生文本对象（`notebook_output` 文本、`table`、`caption`、`formula`）→ 直读目标对象文本（并按类型附 `object_crop` 裁图）。
5. **既有语义保护清单**：
   - 显式历史词（`"刚才第二张图"`、`"前一条的那张图"`）无历史图时仍返回 `options=[]` 澄清，绝不借用当前焦点（`test_workspace_initial_focus.py:56`）；
   - 裸序号遇不同焦点与历史展示（`"第二张图"`）或展示序与页内序冲突（`"第一张图"`）仍返回范围澄清（`test_workspace_initial_focus.py:70, 94`）；

### 2.2 裂缝 2：`caption`/`formula` 的 `GET /evidence/{eid}` 200 契约

#### 现状缺陷
`ed616f2` 为避免破坏页级 FTS 排序与 `searchable_count`，将 PDF `caption`/`formula` 文本存放在 `locator["object_text"]` 并保持 `SourceDraft.text = ""`；但 `workspace.py:655` 的 `historical_evidence()` 校验 `self._matches_text(evidence, read, source.text)` 时拿到空串，导致 `GET /sessions/{sid}/messages/{mid}/evidence/{eid}` 返回 `HTTP 409 (original_unavailable)`。

#### 精确修复设计
1. **定义单一公共可读文本函数**（`app/rag/workspace_evidence.py`）：
   ```python
   def readable_source_text(source: SourceDraft | SnapshotSource) -> str:
       """Return the authoritative native text for reading and historical verification."""
       if source.text.strip():
           return source.text
       if (
           source.kind == "page_object"
           and source.locator.get("object_type") in {"caption", "formula"}
           and isinstance(object_text := source.locator.get("object_text"), str)
       ):
           return object_text
       return ""
   ```
2. **统一接入所有文本读取与核验消费者**：
   - `WorkspaceService._read_text()`：使用 `readable_source_text(source)` 与 `readable_source_text(raw.source)`；
   - `WorkspaceService.historical_evidence()`：将 `self._matches_text(evidence, read, source.text)` 替换为 `self._matches_text(evidence, read, readable_source_text(source))`；
   - `WorkspaceService._scoped_previous()`：校验上一轮引用原文时改用 `readable_source_text(raw.source)`；
   - `workspace_versions.py:_native_read()`：改用 `readable_source_text(source)`，使 `caption`/`formula` 支持同页跨版原生文本对比；
   - `_disambiguate_text_object_choices()`（原 `_disambiguate_table_choices`）：统一使用 `readable_source_text(choice)` 打分；
   - `_tree()` 目录节点摘要：使用 `readable_source_text(source).strip()[:800]`，让目录侧栏点击图注/公式节点也能看到摘要文字。
3. **严格保持 FTS 与导入统计零污染**：
   - `local_slides.py` 创建 `caption`/`formula` `SourceDraft` 时**继续保持 `text=""`**、`locator["object_text"]=text`；
   - `local_library.py:_save_sources()` 仅对 `item.text.strip()` 写 `local_fts`，因此不增加重复 FTS 条目、不改变页级 BM25 排序、不改变 `ImportResult.searchable_count`；
   - `workspace_reading.py:_readable_sources()` 在整页阅读窗里仍仅消费 `source.text`（因为父页 `page:{p}` 已包含该页全部原生文字，避免阅读窗重复计入字节预算）。
4. **验证响应契约**：
   - 对 `Q02`（`page:2:caption:1`）和 `Q03`（`page:2:formula:1`），`GET /api/workspace/sessions/{sid}/messages/{mid}/evidence/{eid}` 稳定返回 `HTTP 200`，JSON 精确包含 `{"source", "file_name", "locator", "text", "is_current", "has_preview"}`，且 `has_preview == True`；换版后历史引用仍返回 `HTTP 200`（`is_current == False`）；跨会话或文档删除后严格返回 `HTTP 404`。

### 2.3 裂缝 3：`b2` 可恢复澄清 Schema（恢复双边 `compare_versions`）

#### 现状缺陷
在 `0f5c93c` 中，v2 输出重排后触发 `compare_versions` 澄清时，选项仅记录 `{"kind": "document", "node_id": ..., "current_object": True}`，丢失了“父动作是双边版本比较”与“已确认的 v1 历史侧对象引用”。用户选定 v2 候选后，`_choose()` 误路由到 `answer_current_image`，仅向视觉模型发送 v2 单图和“对比两版”原句，模型返回 `status="partial"`，未形成双边 `v1 + v2` 对比。

#### 精确修复设计
1. **结构化澄清续接 Schema**（定义在 `app/rag/workspace_clarification.py`，序列化存储在 `workspace_turns.outcome["options"]`）：
   ```python
   class HistoricalComparisonRef(BaseModel):
       model_config = ConfigDict(extra="forbid")
       message_id: str
       evidence_id: str
       display_id: str | None = None
       source: SourceKey
       course_id: str
       publication_epoch: int
       content_sha256: str

   class ComparisonResumeContext(BaseModel):
       model_config = ConfigDict(extra="forbid")
       original_question: str
       historical_ref: HistoricalComparisonRef
       is_image: bool
       attribute: str | None = None
       inherited_image: bool = False

   class ClarificationOptionRecord(BaseModel):
       model_config = ConfigDict(extra="forbid")
       option_id: str
       label: str
       kind: Literal["display", "document"]
       resume_action: Literal[
           "follow_display",
           "read_object",
           "retrieve_document",
           "compare_versions",
       ]
       message_id: str | None = None
       display_id: str | None = None
       node_id: str | None = None
       target_source: SourceKey | None = None
       current_object: bool = False
       comparison_context: ComparisonResumeContext | None = None
   ```
   - **对外投影不变**：`_turn_entry()` 仍只暴露 `{"option_id", "label", "kind"}` 给浏览器/调用方，隐藏内部 `node_id`、`target_source`、`comparison_context` 等服务端续接状态；
   - **旧记录向后兼容**：解析历史会话中尚未含 `resume_action` 字段的旧选项时，按 `kind == "display" -> "follow_display"`、`current_object == True -> "read_object"`、其余 `"retrieve_document"` 自动归一化。
2. **重排比较澄清构造**（`workspace_versions.py:_reordered_comparison_options`）：
   - 当 `len(old) == 1` 且当前文档同 Cell 存在多个候选输出（图像对比仅筛选 `_can_display(src)`）时，为每个 v2 候选构造 `ClarificationOptionRecord`：
     - `resume_action = "compare_versions"`
     - `kind = "document"`
     - `node_id = entry.entry["node_id"]`
     - `target_source = _key(cand)`
     - `comparison_context = ComparisonResumeContext(original_question=question, historical_ref=HistoricalComparisonRef(...), is_image=image, attribute=attribute, inherited_image=inherited_image)`
   - 澄清轮次的 `dependencies` 同时登记当前版 `refs` 与旧版 `history_ref`（历史依赖记入 `historical_refs`，当前版记入 `publication_refs`），确保 `turn_access()` 与访问控制一致。
3. **`resume_clarification()` 强制 7 项二次校验**（防跨会话越权、防篡改、防版本漂移）：
   1. **会话与归属校验**：`previous = store.clarification(session.session_id, anchor.turn_id)`（SQL 强绑定当前 `session_id`），且 `previous.request.scope_revision == session.scope_revision` 且 `_turn_access(previous)`；失败抛 `inaccessible()`（404）。
   2. **选项存在校验**：`anchor.option_id` 必须命中 `previous.outcome["options"]`；失败抛 `inaccessible()`（404）。
   3. **课程范围二次校验**：`set(session.course_ids) <= allowed_courses`，且 `historical_ref.course_id in allowed_courses` 且 `historical_ref.course_id in session.course_ids`；失败抛 `inaccessible()`（404）。
   4. **v2 目标节点与版本校验**：重新通过 `service._node(session, option.node_id, stale=True)` 解析当前版节点，验证 `_in_scope(session, node.document)` 且 `node.source is not None` 且 `_key(node.source) == option.target_source`（若澄清后又发 v3 或原件被删，抛 `stale_reference` / `not_accessible`）。
   5. **v1 历史消息跨会话隔离复验**：调用 `service.store.completed_answer(owner, session.session_id, historical_ref.message_id)` 确认该历史消息严格属于**当前 `owner` + 当前 `session_id` + `completed` 状态**，且 `evidence_id` 在其 `sources` 中存在且 `revision`（`source`, `course_id`, `publication_epoch`, `content_sha256`）完全一致；失败抛 `inaccessible()`（404）。
   6. **v1 原件与附件复验**：调用 `service._historical_source(...)` 确认 v1 归档字节可用且 SHA-256 吻合；若 `is_image=True`，调用 `service._attachment(session.session_id, historical_ref.message_id, historical_ref.display_id)` 确认附件归属、无 fallback 且 `display_source == historical_ref.source`；同时验证 `node.document.document_id == historical_ref.source.document_id` 且 `node.document.version != historical_ref.source.version`。
   7. **双边比较恢复执行**：复用从 `compare_versions` 抽出的公共函数 `execute_paired_comparison(service, owner, turn, session, past, document, selected, history, question=..., is_image=..., attribute=..., inherited_image=...)`：
      - **v1 侧**：渲染/核对历史图像附件并验证 `_previous_visual_read()`，将 v1 图像块与 v1 已读取内容写入 `draft`（`ev-1`）；
      - **v2 侧**：使用面向单图的定向提示词（有 `attribute` 时 `"当前图中的{attribute}是什么？"`，否则 `"请描述当前图中可见的指标名称、单位和核心数值。"`，**而非将双版比较句原样发给单图视觉调用**）对选定 v2 输出执行 1 次真实视觉实读，获得 `status="succeeded"`（非 `partial`），将 v2 图像块与 v2 实读文本写入 `draft`（`ev-2`）；
      - **提交双侧门禁**：`refs=[_doc_ref(v2_doc)]`，`historical=[history_ref]`，`trace["route"] = "version_comparison"`，`trace["resumed_from_clarification"] = anchor.turn_id`。

### 2.4 裂缝 4：图像预览端点对称性（`/media/{display_id}` 与 `/evidence/{eid}/preview`）

#### 现状缺陷
- `workspace_preview.py:render_citation_preview()` 仅当 `turn.outcome["resolution"]` 带有 `origin_message` 与 `display_id`（即 `_follow_display` 路径）时读取附件图像；
- 对于 `answer_current_image`、`_answer_object`（矢量/光栅图）与 `compare_versions`（v1 + v2 图），图像附件直接挂载在**当前消息**的 `blocks`（`type="source_image"`, `evidence_id=eid`, `display_id=did`）中，`resolution` 中没有 `message_id`/`display_id`，导致 `render_citation_preview()` 跌落到 `service.historical_evidence()`，后者因无原生文本读记录抛出 `HTTP 404`。

#### 精确修复设计
在 `app/rag/workspace_preview.py`（配合 `app/rag/workspace_evidence.py`）建立**统一的三层解析链**，确保所有产生图像引用的路径在 `/media/{display_id}` 与 `/evidence/{eid}/preview` 两个端点上**语义对称、字节哈希一致、权限严格对齐**：

1. **前置统一授权校验**：
   - `stored = service.store.completed_answer(owner, session_id, message_id)`（校验 `owner`、`session_id`、`message_id`、`status="completed"`，跨会话严格 `HTTP 404`）；
   - 验证 `evidence_id in message["sources"]` 且 `service._turn_access(turn)`；
   - 允许的引用归属条件：`cited_in_text or attached_as_visible_image`（即该 `evidence_id` 在文本块 `citations` 中被引用，或作为当前消息 `visible_display_ids` 中的 `source_image` 块展示）。不满足直接 `raise inaccessible()`（404）。
2. **Branch A · 当前消息同源附件直查（覆盖 `answer_current_image`、`_answer_object`、`compare_versions`、`_render_object_crop` 表格/图注/公式裁图、以及 `display_only` 展示图）**：
   - 在当前 `message["blocks"]` 中查找 `block["type"] == "source_image" and block.get("evidence_id") == evidence_id and block.get("display_id") in visible_display_ids`；
   - 若命中 `(message_id, block["display_id"])`，调用公共函数 `_verified_attachment_preview(service, owner, session_id, message_id, display_id, evidence, turn)`：
     1. 校验 `service._attachment(session_id, message_id, display_id)`、`service.store.display_ordinal(session_id, message_id, display_id)`；
     2. 校验 `details` 中 `display_source`、`course_id`、`content_sha256`、`publication_epoch` 与 `evidence.revision` 完全一致；
     3. 若 `evidence.reads` 含已成功的真实视觉实读（`method == "vision"`, `status in {"succeeded", "partial"}`, `origin_execution == "real_provider"`），**强制校验** `read.actual_input_sha256 == details["byte_sha256"]` 且 `read.actual_input_media_type == details["mime_type"]`（确保预览字节与视觉模型实际输入字节哈希完全一致）；
     4. 通过 `service.historical_media(owner, session_id, message_id, display_id, view="inline")` 取字节（内部复核原件未删、SHA-256 一致），再次校验 `sha256(image) == details["byte_sha256"]` 与 `service._turn_access(turn)`；
     5. 返回 `(image, mime_type)`（`HTTP 200`，带 `_MEDIA_HEADERS`）。
3. **Branch B · 历史追问来源附件解析（覆盖 `_follow_display`，含 `historical_only` 已验证旧图追问）**：
   - 当前消息无直接 `source_image` 块，但 `turn.outcome["resolution"]` 含 `(origin_message, display_id)` 且 `evidence.reads` 含 `method == "vision"`：
   - 调用同一个 `_verified_attachment_preview(service, owner, session_id, origin_message, display_id, evidence, turn)`，要求存在匹配的 `real_provider` 视觉实读哈希，返回 `(image, mime_type)`（`HTTP 200`）。
4. **Branch C · 纯文本引用原件渲染回退（覆盖 FTS 搜索、阅读窗生成答案、`table`/`caption`/`formula` 裁图不可用时的文本引用）**：
   - 调用 `service.historical_evidence(owner, session_id, message_id, evidence_id)`（已通过 2.2 节支持 `caption`/`formula`），校验 `key` 一致后，按 `locator` 渲染 `original_page`（保持与前端 `workspace.js` 的页内 `bbox` 高亮坐标系一致）或 `notebook_output`，复验 `service._turn_access(turn)` 后返回图像。

## 三、PDF 真实复杂排版对象解析护栏

逐行审查 `ed616f2` 在 `app/rag/parsers/pdf_tables.py` 与 `app/rag/parsers/local_slides.py` 中的三处实现后，识别出在真实多栏学术论文（IEEE/NeurIPS/ICML/arXiv）与教学课件 PDF 上最易发生的误报与漏报场景，并制定如下**纯确定性、无模型依赖**的解析护栏与页级回退条件。

### 3.1 `extract_horizontal_rule_tables`（`app/rag/parsers/pdf_tables.py`）

| 真实排版风险场景 | `ed616f2` 现状缺陷 | 确定性护栏规则 |
| --- | --- | --- |
| **页眉/页脚装饰线混入同宽横线组** | 仅向后切片 `ordered[start:]`，未剔除页眉/页脚孤立横线，底部脚注线会把表格底边界拉到页尾吞并正文 | **T1（页眉/页脚孤立线剥离）**：位于页顶 6% 或页底 7% 区域、且与相邻同宽横线间距 `> 0.12 * page_h` 的孤立装饰线直接从横线组剥离。 |
| **同页上下两张同宽 booktabs 表** | `_group_horizontal_rules` 将 6 条同宽线合并为 1 组，`ordered[start:]` 跳过第一张表或吞并两表间正文 | **T2（大间距分组 + 有界双向子序列）**：按 `y` 降序扫描横线组，相邻间距 `> 0.35 * page_h` 时先切分为独立子组；组内长度 `4..12` 且整体解析失败时，按紧凑子窗 `[start:end]`（`3 <= end - start <= len`）尝试提取互不重叠的合法表，避免头尾多余横线阻断。 |
| **LaTeX `algorithm` 伪代码框误判为表** | `algorithm` 恰好具备 3 条同宽横线，行号+语句可凑出 2 列 | **T3（正文/伪代码拒绝规则）**：若表体出现单行覆盖 `> 75%` 表宽的连续非对齐长句（排除单行分组标题），或第 1 列呈纯递增行号（`1:`, `2:`, `3:`）且其余列仅有 1 列缩进代码，或表头匹配 `^Algorithm\s+[0-9]`，拒绝注册为表格。 |

- **页级回退条件**：旋转页（`page_rotation != 0`）、区域内含竖线、列归属歧义行 `>= 2`、边界截断正文词、表头列数不足或表体不足 2 行多列数据时，不登记 `table` 对象，安全保留 `page:{p}` 原文与整页预览。

### 3.2 `_pdf_vector_image_sources`（`app/rag/parsers/local_slides.py`）

| 真实排版风险场景 | `ed616f2` 现状缺陷 | 确定性护栏规则 |
| --- | --- | --- |
| **图文混排页漏报矢量图** | 仅在 `if not page_images:` 时运行；页角一个小光栅 Logo 就会让整页矢量图表全部漏报 | **V1（图文共存 + 键位向后兼容）**：先提取可靠顶层光栅图 `raster_images`，再运行矢量图提取（排除与 `table_boxes` 和 `raster_images` 重叠的路径）；矢量图序号严格追加在光栅图之后，不改变已有光栅图 `page:{p}:image:{i}` 键。 |
| **整页边框 / 章节分隔线 / 双栏中缝线粘连** | 仅过滤 `>= 0.9 * page_w and >= 0.9 * page_h`；0.85 页宽边框或长横线/中缝竖线仍充当聚类桥梁，把两张子图或表格粘成一个巨框 | **V2（装饰线与超大容器预过滤）**：聚类前剔除：① 面积 `>= 0.65 * page_area` 或单边 `>= 0.88 * page_dim` 且另一边 `>= 0.70 * page_dim` 的整页框；② 细长横线（高 `<= 3.5 pt` 且宽 `>= 0.45 * page_w`）与细长中缝竖线（宽 `<= 3.5 pt` 且高 `>= 0.45 * page_h`）；③ 页眉/页脚安全带（顶/底 `<= 6%` 页高且高 `< 24 pt`）装饰路径。 |
| **带边框的公式框 / Theorem 框 / 代码高亮框误报为图** | 仅要求 `path_count >= 3` 且 `>= 48x48 pt`，简单矩形边框+底纹+顶栏即可触发误报 | **V3（简单文本框反误报）**：若候选簇满足：① 组成路径数 `<= 6` 且全部为薄边/轴对齐矩形或水平/垂直线（无斜线/曲线/多点折线）；且 ② 簇内原生文本行数 `>= 2`、文本覆盖宽度占簇宽 `>= 65%` 或文本含段落标点/独立公式特征，拒绝登记为 `image`，交由正文或公式解析器处理。合格矢量图须满足尺寸 `>= 48x48 pt`、面积 `<= 0.72 * page_area`、与表格重叠面积占比 `<= 10%`。 |
| **双栏紧凑子图被 `gap=10.0 pt` 粘连成单图** | 统一 `10.0 pt` 膨胀容易跨越 6–8 pt 的子图间距 | **V4（保守聚类间距 + 防跨中缝合并）**：聚类默认间距收紧至 `gap = 5.0 pt`（足以连通同一坐标轴与刻度/图例，不跨越双栏中缝）；若页面存在双栏空白带（中线 `0.46..0.54 * page_w` 内无跨栏矢量路径穿过），禁止跨中缝合并左右栏路径簇。 |
| **LaTeX `\includegraphics{fig.pdf}` 生成的 `Form XObject` 漏报** | `max_depth=1` 仅枚举 `FPDF_PAGEOBJ_PATH`，完全忽略顶层 `FPDF_PAGEOBJ_FORM` 矢量图 | **V5（受控 `Form XObject` 矢量图候选）**：对顶层 `FPDF_PAGEOBJ_FORM`，仅当边界严格在 `page_bbox` 内、面积在 `[48*48 pt², 0.72 * page_area]`、不与表格/光栅图/其他 Form 重叠、非纯正文文本流（内部含路径或图像子对象且不触发 V3 文本框拒收）时登记为矢量图（`position_basis="pdfium_native_vector_extents_v1"`）。 |

- **页级回退条件**：旋转页（`page_rotation != 0`）、PDFium 边界非有限值、多层透明重叠无法分离或单页矢量图簇异常超过 12 个时，放弃该页矢量图切分，安全回退页级 `page:{p}`。

### 3.3 `_pdf_text_object_sources`（`app/rag/parsers/local_slides.py`）

| 真实排版风险场景 | `ed616f2` 现状缺陷 | 确定性护栏规则 |
| --- | --- | --- |
| **双栏论文左右栏同行文字被合并成一行** | 仅按 `abs(yc - prev_yc) <= 4.0` 归行，不区分水平列间隙，导致左栏图注/公式吞入右栏正文 | **X1（栏内切分后再归行）**：同一 `y` 桶内按 `x0` 排序，若相邻文本对象水平间隙 `dx > max(20.0 pt, 2.2 * median_line_height)`，切分为独立行片段，绝不跨双栏合并。 |
| **正文行内等式（如 `lr = 1e-4`, `N = 100`）大量误报为独立公式** | `_FORMULA_EQ` 匹配任意 `var = val` 且仅限制 `len(blk) <= 4`，真实论文短段正文会批量误报 `formula` | **X2（独立公式高精度门槛）**：除匹配数学关系符（`=`, `:=`, `≈`, `≤`, `≥`, `∝`, `→`）外，须**同时满足**以下独立展示特征之一：<br>(a) 被有界公式框包含（`frame_box` 面积 `< 0.35 * page_area` 且不与表格/图像重叠）；<br>(b) 行尾含独立公式编号（如 `(1)`, `(2.3)`, `[4]`）；<br>(c) 块行数 `<= 3` 且公式主行呈短行/居中/缩进特征（自然语言叙事词数 `<= 6`，允许附带 1–2 行以 `Condition:` / `where` / `for` / `适用条件` / `其中` 开头的条件说明行）。明显散文句（主行常规英文词 `>= 8` 或含完整叙事句号且无编号/无框）一律拒收。 |
| **多行图注被截断或向下吞并正文** | 固定 `vgap <= 10.0` 在大行距下会截断第 2 行图注；而在紧凑排版下会把下方正文首行吸进图注；`excluded_boxes` 1 pt 擦边即丢弃图注 | **X3（自适应行距与图注终止护栏）**：<br>- 块合并使用自适应行距 `vgap <= max(10.0, 1.35 * median_line_height)` 且要求较窄行水平投影重叠率 `>= 0.35`；<br>- 遇到垂直间距突增（`vgap > prev_vgap * 1.6 + 2.0`）、左边界显著漂移（`abs(cur_x0 - prev_x0) > 28.0 pt` 且非悬挂缩进）、或新章节/`Table`/`Figure` 标题前缀时立即截断块，不吞并正文；<br>- `excluded_boxes` 过滤改用**重叠面积占比 `> 0.35`**（而非任意 1 pt 擦边即排除），防止紧贴图框下沿的 `Figure N:` 图注被误删。 |
| **公式外框 `frame_boxes` 缺少面积上限** | 只限制 `>= 48x18 pt`，可能选中整页背景框吞并整页文本 | **X4（公式框尺寸上限）**：`frame_boxes` 强制要求宽度 `<= 0.92 * page_w`、高度 `<= 0.38 * page_h`、面积 `<= 0.35 * page_area`，且内部文本总字符数 `<= 1200`。 |

- **页级回退条件**：旋转页（`page_rotation != 0`）、扫描无原生文本页或文本提取异常时，不登记不可靠 `caption`/`formula`，回退 `page:{p}` 页级全文/OCR 路径。
