## 首跑与评分校正

第一次真实运行保留。G09 浏览器完成，候选首个视觉请求的输入因取样脚本先把带留白的裁图缩到 150×80、目标色只剩 32 像素而被拒，实际发送零次。独立原件边界与该版本的右图登记一致。取出 SHA 完全相同的首次输入，原始字节内有 13,067 个完全同色的目标像素，按原来的每通道容差有 15,234 个，邻图为零。离线浏览器打开同一裁图和第 1 页，验证对象及高亮。随后用原始像素重算，同一容差和阈值拒绝含左右图的原页。两边在新的空库正式对照一次，固定提交、题面、裁区内容和评分条件均保持。

封存评分器直接从消息 locator 取 `object_type`，该字段实际由版本化来源表提供，消息仅保留位置。对照原样评分得 3/9 对 3/9，普通入口、展示、读取、版本、引用和答案已有上表所示收益，门槛通过。派生评分器按 `document_id/version/source_id` 只读核对同一运行库，要求登记表与消息的 page、bbox 匹配后给对象轴计分，故对象由 3/9 对 3/9 校正为 5/9 对 8/9，整题为 3/9 对 7/9。评分阈值、未测边界和严重错误标准保持封存口径。两份原始评分及复核结果均提供。项目可依照预定规则进入独立 A03 复测。

## 复现

运行器需要仓库的 Python 环境、agent-browser 和可用的 LibreOffice。实测为 Python 3.14.7、agent-browser 0.43.0、Headless Chrome 157、LibreOffice 26.8.3.1 与 pypdfium2 5.13.0。已封存的文件存于 `materials/`，生成代码可在副本目录重建合成课件。重建 PPTX 的 ZIP 时间戳可能变化，复跑原实验应直接使用封存件。

```bash
cd /Users/Link/code/SRAG
suite="$PWD/docs/G/G13-public-review"
run_dir="$(mktemp -d /tmp/srag-g13-public.XXXXXX)"
export SRAG_PYTHON="$PWD/.venv/bin/python"
export SRAG_SOFFICE="/path/to/LibreOffice.app/Contents/MacOS/soffice"
export G13_ENV_FILE="$PWD/.env"
bash "$suite/browser.sh" e921fa87f48a4e67c58010181a187c6e0e12b833 "$run_dir/g09" 19139
bash "$suite/browser.sh" 733da32ac9f5440eac59a6505bf6e561d88b7c35 "$run_dir/g12" 19140
"$SRAG_PYTHON" "$suite/score.py" "$run_dir/g09" "$run_dir/g12" "$run_dir/comparison.json"
```

本机实测的 LibreOffice 路径在临时安装目录下。若只需观察展示与原件，取消 `G13_ENV_FILE` 即可禁用模型并在结果中明确标记视觉未测。要校验先前封存内容，可在一个临时目录合并 `preseal/` 下的文件与根目录的 `fixtures.py`、`protocol.json`、`materials/`，按该目录下 `seal.json` 校对各文件。要对同一结果运行封存评分器，在这个组合目录中执行 `score.py`，将上面命令的两个运行目录和一个新的报告路径作为参数。
