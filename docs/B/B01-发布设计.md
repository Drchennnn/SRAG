# B01 · 本地导入与版本发布设计

A01 的资料、版本、来源、展示和读取语义继续生效。本页划定 B 的实现、迁移和首搜验证。[公共契约](../A/A01-公共契约.md) · [A04 签认](../A/A04-整部审核.md) · [接手状态](./接手版本.json)

## 现有入口和写入归属

旧 [MetadataStore](../../app/stores/sqlite.py) 在 schema v1 管理 document、version、page/Cell、chunks 和 assets。[Notebook 索引器](../../app/rag/indexer.py) 从绝对路径派生旧 ID，写 SQLite 和 Qdrant 后激活版本；[课件包索引器](../../app/rag/slide_indexer.py) 用原件哈希前 24 位生成旧 ID，校验 deck/chunks/embeddings 后执行相似流程。旧版会清理过期结构，缺原件时无法重跑向量包导入。现有 HTTP、CLI 请求和旧响应字段保留。

B 在同一个 SQLite 库增加 `local_*` 表。B 管理原件、稳定 ID、版本、当前发布、来源、全文行、增强写回和旧 ID 对照。旧表、包格式、向量数据及旧写入流程保留；兼容查询仍用旧 ID/版号，仅当已映射资料的已授权当前版与旧快照相符时返回旧向量。C 使用 B 提供的来源结构和最小 FTS 入口，D 按三元组读取已验证原件并提交可复用增强，E 再决定对话和媒体 API。

- 选择路径使用 `POST /api/rag/local/import`，输入 `course_id, paths, document_id?, release_at?`，单路径更新可明确指定已登记资料 ID。目录按文件排序递归处理，支持 PDF/PPTX/IPYNB，逐文件原子发布，返回状态、ID、版号、发布代次、结构及可搜行数。路径选择受本地服务的 `COURSE_ROOT` 约束。显式迁移支持旧库当前可见资料、及旧 deck/chunks 包。首次本地迁移和搜索不需要旧 embeddings 文件或向量服务。
- `POST /api/rag/local/search` 接受文本和课程/文件范围；响应带完整来源键和当前发布代次，供 B 的验收与 C 的接入。旧 `/api/rag/search` 保持默认 legacy，并允许部署配置选择本地文字路由。选择本地时沿用旧请求与响应结构，目标精确引用用新增接口读取。显式 visual 仍走旧视觉路径。老 CLI 仍可运行，向量召回也经过同一份 SQLite 可见性限制。切回 legacy 仅改变路由；被替换、删除或未经映射的新旧版本不会因此复活。旧资料仍用原登记 ID、路径和版号服务兼容调用方。
- 本地删除逻辑撤销可见性，保留 tombstone 和历史版本身份；旧删除兼容入口删除对应旧资料时同时撤销已映射的本地资料。来源精确回读由 storage 提供给已核对范围的调用方。当前 B 仅面向可信本机操作，无需在 API 返回原件字节、绝对归档路径或暴露媒体端点。

## 解析边界

B02/B03 共用下述中间结构。B04 独占公共模型、存储、调度、入口与迁移文件。在 B02/B03 各自文件定义解析器，正式接线等两项均通过；独立探针依靠模型相同结构运行。

- `app/schemas/local.py` 中 `SourceDraft` 字段为 `source_id, kind, ordinal, parent_id=None, title="", text="", locator={}, state="available"`。kind 为 `page | page_object | cell | notebook_output`。ordinal 是版内读取顺序；locator 保留 A01 规定的页码、框、Cell 索引、输出索引、MIME 和字节哈希。来源身份按原始位置编码，消费者只将其作为不透明 ID。命名空间分别为 `page:<1-based>`、`page:<n>:shape:<id>[.<id>...]`（PPTX 的原生 shape 路径）、`page:<n>:table:<1-based>`（PDF 同页确认的表按原生位置排序）、`cell:<0-based>`、`cell:<i>:output:<0-based>`。数值为 ASCII 十进制且无前导零。PDF 表使用可见页上到下、左到右的候选顺序，位置并列时用原生内容序号；记录定位依据。同一字节由同一定位算法重解析生成相同 ID，重复 ID 或跨版父键拒绝失败。PDF 定位算法变更需要保留历史对应关系或按 A01 标记定位失效。
- `ParsedSource` 为 `title, sources`；各解析入口都接收临时快照 `Path`，只返回文本和来源位置，独立于 SQLite/Qdrant。PDF/PPTX 为 `parse_local_slides(path)`，Notebook 为 `parse_local_notebook(path)`。
- B02 提取每页标题、原生文字、可靠框、PPT 原生表格及 PDF 中可确认的表格式布局。PPTX 用 shape ID 路径确定对象，表包含可复制的行和列标题；PDF 版内定位记录保存页面坐标与提取依据，检测不到可靠表或框时保留页级文字。纯扫描页登记 `needs_ocr` 且 FTS 无正文行；基本导入不触发 OCR/全页渲染，原生文字可独立发布。旋转或组合变换不能可靠投影时优先保留文字和父页。
- B03 读取原始 JSON Cell 顺序。Cell ID 缺失、重复或无效时使用版内原始索引核查，locator 的原件 `cell_id` 为空；源对象 ID 可按位置稳定生成。标题是原 Markdown 层级，代码只做文本。outputs 每项独立登记，原生顺序包括 stream 及空位；同一 MIME bundle 的多个表示归同一输出。无输出的代码 Cell、空输出或不可解码媒体有明确状态。媒体通过版本原件中的 locator 回读；基础导入不会执行代码、打开 Markdown 外部附件或请求网络。

## 表键和稳定身份

| 表 | 要保证的键和含义 |
| --- | --- |
| `local_documents` | `document_id` 主键，单一 course。存当前路径、`current_version`、`publication_epoch`、删除标记及最多一个 `pending_version/pending_at`。 |
| `local_paths` | `(course_id, canonical_path)` 唯一，持有 doc ID。规范路径解析自显式选择的路径。 |
| `local_versions` | `(document_id, version)` 主键，`(document_id, content_sha256)` 唯一；存原件 BLOB、标题、位置 path 标签和首次实际发布时间。 |
| `local_sources` 和 `local_fts` | 前者整数 rowid，唯一 `(document_id, version, source_id)`，父来源限同版。FTS 原生/旧正文行用 `2*source_rowid`，增强行用 `2*source_rowid+1`。同一事务内替换同一 rowid，全文行和来源一一对应；检索按来源归属、课程和可见版本联合过滤。 |
| `local_legacy_versions/keys` | 旧 `(document_id, version)` 固定完整 hash、course、当前映射的本地版本；旧 chunk/element/asset key 加来源键可一对多，旧版号遇到不同字节拒绝覆盖。 |

首次未指定 ID 且查不到登记路径，在提交事务内分配随机 `local_<uuid4.hex>`，主键冲突时重试分配。首次已核对的旧资料迁移可保留旧 ID，遇冲突拒绝自动合并。显式选 ID 移动时同一事务登记目的路径，保存旧路径为同课历史别名。重导历史路径仍返回同一资料；未显式移回时不能改变主显示路径。已归属同课另一资料的路径拒绝绑定；并发首次导入按唯一约束和观察令牌序列化。不同课各自登记。

## 进入发布事务前与事务内

1. 文件解析前读取目标资料、当前发布代次及 course；用已确认的归属查找同课同路径。跨课同名、同路径、同哈希都维持各自身份。对已登记 ID 变更路径须显式指定。复制选定原件字节并在临时目录以原名解析，计算整个快照的 SHA-256，避免解析和归档跨版本，用快照字节作为 SQLite BLOB。旧包缺原件时归档为空且保留可核对的旧完整哈希。未确认哈希的相似资料保留旧引用标签，不强行映射。
2. 使用 `BEGIN IMMEDIATE` 重新核验归属、被选资料与预期代次。新文档仅在写事务登记；竞争导入若观察值改变则拒绝提交，调用方可重试。按 `(document_id, content_sha256)` 去重，现行同内容无变更时跳过；同一资料回用历史字节可复用版号，发布代次递增。换版新增原件、正文和结构，与必要的 `local_fts` 行及可见指针同事务提交。空正文版有目录，但没有文字匹配。未来 release 只登记已备妥的待定版及到期时间，旧指针继续可见。每个本地搜索、历史读取和旧可见性查询都在建立读取快照前调用同一 `promote_due(cutoff)`，写事务开始后也调用。该函数处理同一 cutoff 下所有到期且未删除的待定项，在一个写事务内把待定版改为当前、记录首次实际发布、清空 pending 并递增 epoch；读者随后查询已提交指针，未到期时仅查原当前版。并发尝试以待定指针和时间为条件串行，第二次为空操作。到期前，同一资料新的成功预约替换前一个待定项，成功即时发布则清空待定项；失败操作无副作用。登记/撤销待定时也改变 epoch，使正在准备的任务可被明确拒绝。待定版曾发布时仍属原有历史，首次准备的版本在首次成功切换前无历史读取资格。
3. 事务报错或进程中断时 SQLite 恢复到提交前版本；解析失败不写版本。历史引用查精确版和对象，校验可访问性、字节哈希与归档状态。发布中的版本不被新搜索或历史引用读取。删除标记并递增代次，撤销当前搜索与历史访问；用户明确重导可重建当前发布，已删除代次的增强令牌永不复活。
4. 可复用增强写回带 `(document_id, version, source_id, content_sha256, publication_epoch)`，事务内检查授予、当前版、哈希、代次、未删除及来源归属，再更新该来源的派生文字 FTS 条目；旧代次/旧版/删除后返回拒绝且零副作用。派生文字的 provenance 与原生正文分开；问题定向解释留在 D/E。FTS 查询用参数绑定和普通词的转义，标准 unicode61；复杂双语分词、召回排序对照和结构检索归 C。[SQLite 事务](https://www.sqlite.org/lang_transaction.html) · [SQLite FTS5](https://www.sqlite.org/fts5.html)

## 旧资料映射、切换和回退例

可见性桥接在 `MetadataStore.visible_versions`、旧目录和旧全文读取共享 SQLite 条件。无本地表或无已迁移身份时沿用原条件；有映射时要求旧文档与版本对应的 alias 在同一读快照内通过 course、legacy 内容哈希和本地当前版检查，且本地未撤销。Qdrant 将此集合用于候选过滤，返回之前再次据实际 MetadataStore 核对版本，避免召回期间跨版。旧删除将本地 tombstone 与旧删除放在同一个 SQLite 事务。部署设置决定 `/search` 查哪一边；切回不删除本地数据或跳过上述桥接。

假设 SQLite 旧资料 `document_<旧哈希前缀>` v1 为一份 PPTX。迁移从 SQL 同一快照读取 course、path、当前版与 hash，以及页记录、chunk/element/asset 关系；旧包也可经校验后供同一转换流程使用。存在原件且全哈希匹配时按新解析器生成来源。逻辑资料初次迁移保留旧 ID 作为其稳定 ID（遇到冲突需拒绝或由已确认归属显式绑定）。记住 `(legacy_document_id, legacy_version, legacy_key)` 到新版一个或多个来源键的映射。旧记录每版保留内容哈希，避免复用旧 ID/版号指向另一字节。

- 页号映射到新页，PPTX 旧表 element 通过同页唯一、相同类型、文本与可验证框对应为新 shape 路径来源；旧 asset 经其 element 关联，无法唯一确认归到同页。带多个元素的旧 chunk 对应多个来源；只有粗定位时映射到页。Notebook 旧 chunk 通过 block IDs 和 Cell 原始索引对照；有新版原件可核验的旧 output/asset 才映射输出项，无法核实时只落到 Cell。旧 PDF/PPT 多框与缺证据情况保留可确认父级。
- 若旧原件缺失或现有路径哈希不同，只将旧 SQLite/包中的正文标记为 legacy_text 回填，并登记已知页/Cell；旧精细对象回退到已确认父级，原件访问返回 `original_unavailable`。对无完整 hash 的外部 deck 不宣称身份已核对。迁移完成需核对页/Cell 数、版本身份、可搜行和抽样内容后，才将兼容搜索切到 local。切回 legacy 保留原库，旧检索仍受 SQLite 当前可见性约束。若 v2 无等价旧向量，切回期间明确缺该表示，不能返回 v1 作为当前版。
- 将 PPTX 替换成新内容，明确登记到同一资料，得到本地 v2。提交成功后 FTS 仅返回 v2，旧 v1 的历史请求继续到 v1 归档。插入新结构或 FTS 后、提交之前中断，查询及旧引用保持原版，新版未发布。计划 v2 发布前，在检索和访问上仍使用 v1。删除 v2 后尝试其迟到增强，即使重新导入 v2 的相同字节，旧代次也被拒绝。B04 采用带原件、无原件、旧包/旧库、旧 Cell 多输出及实际中断探针核验这些划分。

## 初次可搜计时与审核

以同一进程的单调时钟，从将已选路径交给本地导入入口之前计至首条新查询实际读到目标当前文档与版本。包含原件读取、解析、SQLite 事务及查询。冷测用新 SQLite 路径，首次使用连接与依赖；热测用同进程已加载依赖和已初始化库，导入另一份逻辑登记的相同字节，避免用跳过重导当作热导入。二者按格式报告原件字节、提交耗时、到首个命中耗时、来源键和外部调用次数。冷是应用/数据库冷启动，系统磁盘页缓存可存在。

B02/B03 由独立审核者核对固定样例和新故障样例。B04 测试应以隔离 SQLite 复放同内容、换版、事务中断、删后迟到、旧包/旧库回填、路由切回和每个对应历史键。B05 使用无 Qdrant、无模型凭据的环境并守卫外连，实测三格式和故障回放。A03 样例只用于文件导入探针；题集和评分保持锁定。建议入口 `pytest -q tests/test_local_*.py`，兼容回归 `tests/test_indexer.py tests/test_slide_indexer.py tests/test_sqlite_store.py tests/test_rag_api.py`，整部用单独报告和可重放脚本签认。
