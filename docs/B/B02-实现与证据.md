状态：实现完成，待未参与实现者独立审核。设计依据为 `B01-发布设计.md` 的

## 实现边界

- `parse_local_slides(path)` 只读调用方提供的临时快照，支持 PDF 与 PPTX，返回
  `ParsedSource`。它不渲染整页、不做 OCR、不调用网络，也不写 SQLite 或原件。
- PDF 用 PDFium 按原生页序读取文字。只有无文字且存在原生图片对象的页标为
  `needs_ocr`，正文保持空；真正空白页标为 `no_native_text`。PDFium 的打开、读取和
  关闭均受模块级锁保护，避免 B04 在线程池中跨文档并发进入 PDFium。页、文字页和
  文档句柄均在 `finally` 关闭。
- PDF 仅把至少三条横线、三条竖线组成，且表头与数据行均有两列文字的轴对齐原生
  规则网格登记为表。表的 ID 按可见位置为 `page:<n>:table:<k>`；定位保存原生框、
  `visible_page_norm_v1` 框、内容序号和带版本的原生到可见坐标变换。旋转页仍发布页级
  文字，但不发布未证明正确的表框。
- PPTX 按原生幻灯片顺序读取标题、shape 文字、图表标题/系列和原生表。对象 ID 使用
  `page:<n>:shape:<id>[.<id>...]`，表保留表头、单位和全部行。未旋转的顶层 shape 保存
  EMU 原框、归一化框与变换版本；分组、旋转或裁夹后退化的 shape 保留文字和路径，
  不发布精确框。仅含图片的幻灯片标为 `needs_ocr`。渲染状态始终单独记录为
  `not_attempted`，不影响原生解析成功。

## 已知限制与人工复核点

- PDF 表识别刻意保守：无规则线表、合并单元格、旋转表和不能可靠投影到裁边后可见页的
  表只保留页级原生文字，不伪造对象框。基础解析不处理扫描文字。
- PPTX 分组子 shape 与任意角旋转 shape 的精确投影未在 B02 宣称可用；消费者应根据
  `position_basis` 回退到父页。图片字节回读与独立渲染属于后续精确读取层，不是本解析器
  的输出。
- 自动测试证明原生字段、状态和不可渲染回退；最终审核仍应人工对照 A03 PPTX 表头、单位、
  `Median / 5 / 2` 行和 `[0.1, 0.3, 0.9, 0.9]` 框。A03 PDF 没有原生表，专用规则表是
  B02 的兼容故障样例，不改动锁定原件。
