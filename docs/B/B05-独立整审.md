## 换版与故障回放

### 提交前硬中断

独立子进程先发布 v1，再把原件改为 v2。探针包裹真实 `_activate`，确认事务内 `current_version=2` 且新 FTS 已存在后写入临时标记，以 `os._exit(73)` 在事务上下文提交前硬退出。新的独立连接实测如下。

- 当前搜索仍命中 v1 的 `oldfaultword`，不命中 v2 的 `newfaultword`。
- v1 历史原件为 `available`，v2 为 `not_accessible`。
- 库中持久化记录只有 1 个版本、1 个来源和 1 条 FTS，没有 v2 残留。
- 对同一 v2 原件重试后得到 `published / v2`，新搜索只命中 v2，v1 历史原件仍可读取。

这项证据不是普通异常注入。子进程在 SQLite 事务中已经执行指针和 FTS 修改，进程硬退出后由另一连接验证回滚。

### 删除、迟到写回和同字节重导

先以正确哈希和 epoch 写入一次增强，确认增强可搜，作为正控制。删除资料后，当前正文和增强均不可搜，历史引用为 `not_accessible`，旧票据写回返回拒绝。同字节重新导入复用 v1 但产生更高 `publication_epoch`，删除前票据仍被拒绝，迟到文字没有进入 FTS；当前原生文字重新可搜，当前 v1 历史原件恢复为 `available`。

## 旧资料迁移、回填与切回

独立探针没有复用 B04 测试 fixture 的断言，而是重新建立隔离旧 SQLite 和真实旧 PPTX 包。

- 旧 Notebook SQLite 活动版迁移后，本地 FTS 命中 `legacysqlword`，历史原件可读。相同资料发布新字节后只命中新 v2，旧 `MetadataStore` 的可见版本为空。把原字节切回后复用 v1，旧入口再次可见。
- A03 PPTX 旧包在原件缺失时以 `legacy_text / page:1` 发布，`Peak` 可搜，历史读取为 `original_unavailable`。恢复完全相同原件并重新迁移后，旧 table key 从父页精化到 `page:1:shape:3`，原件历史读取为 `available`。
- 兼容回归另行覆盖旧 Notebook/课件索引、旧 SQLite、旧 `/api/rag/search`、Retriever 和 CLI 范围、引用与日志语义。定向 60 项与 CLI 4 项均通过。
