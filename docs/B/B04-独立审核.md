## 首轮必须修正

### 1. 新预约当前版不能替换旧 pending

复现场景：v1 当前，预约 v2 在 `T+10` 发布；随后把原件恢复为 v1，并成功请求 v1 在 `T+20` 发布。B01 要求后一个成功预约替换前一个待定项。实际 `_activate()` 在发现 `current_version == version` 且新 `release_at` 在未来时直接返回 `skipped`，没有清除或替换 v2 pending。

实际探针：

```text
v1=published/1
v2=scheduled/2
latest=skipped/1
after_latest=(current_version=1, pending_version=2, pending_at=T+10, epoch=2)
at T+11 => 搜索命中 v2
```

这会让已经被更新预约否决的 v2 仍自动上线。修复应明确：当前字节的新预约遇到不同 pending 时，至少取消旧 pending 并递增 epoch；若产品需要保留未来动作，也可登记当前版为新的 pending，但不得留下旧版本。增加该精确回归，并核对旧 pending 未发布历史仍不可读。

### 2. 旧搜索适配伪造 Notebook Cell 身份

`app/api/rag.py::_local_hit_to_legacy` 从 opaque `source_id` 拆出 `cell:0` 或 `cell:1`，把它写入旧 `SourceReference.cell_id/cell_ids`，并只用命中 title 构造 `section_path`。B03 已核对的原件定位实际在 locator：`cell_id` 可能为 `signal-plots` 或 `None`，`section_path` 可能为多级章节。

独立探针实际输出：

```text
source_id=cell:0, locator.cell_id=None, locator.section_path=[Course, Topic]
=> cell_id=cell:0, cell_ids=[cell:0], section_path=[Topic]

source_id=cell:1:output:2, locator.cell_id=signal-plots,
locator.section_path=[Course, Plots]
=> cell_id=cell:1, cell_ids=[cell:1], section_path=[Topic]
```

旧字段原义要求使用原件 Cell ID。无有效唯一 ID 时 `cell_id/cell_ids` 应为空，位置由 `cell_index` 回退。`section_path` 应采用已验证 locator 数组，不能用 title 替换。增加 Cell、output、无 Cell ID 和多级章节的旧 `/search` 回归。

### 3. 恢复原件后 legacy key 仍停留在父页

用 A03 PPTX 生成旧 deck/chunks 包，删除原件后迁移。表 element 因无原件正确回退到 `page:1`。恢复完全相同的 PPTX 后普通导入成功，同版出现 `page:1:shape:3` 且原件可读；再次迁移同一旧包仍返回 `backfilled`。但是 legacy element key 始终只返回 `page:1`：

```text
before restore       => ['page:1']
after original import => ['page:1']
after bundle remigrate => ['page:1']
expected verified     => ['page:1:shape:3']
```

`map_legacy_sources()` 对实际 A03 原件能独立算出 `page:1:shape:3`，问题在 `_bind_legacy()` 遇到已有 identity 后立即返回，没有重建或升级 `local_legacy_keys`。B01 规定无原件只能粗回退，而有原件并满足同页、唯一类型、文本和 bbox 时应映射精确对象。修复需在完整身份仍一致时事务更新 key 映射，同时保证不覆盖不同 hash/course/document/version，并增加“缺原件回填→恢复→重迁移→exact object”的端到端测试。

## 返工重审

### 修复核验

1. `_activate()` 只有在当前版相同且不存在 pending 时才直接 `skipped`。当前 v1、待定 v2 时再预约 v1 会把 pending 改成 v1 和新时间并递增 epoch。独立探针实际得到：

   ```text
   published / scheduled / scheduled
   current_version=1, pending_version=1, pending_at=T+20
   T+11 不命中已否决的 v2
   T+21 仍命中 v1，提升后的 epoch 正确递增
   ```

2. 旧搜索适配只接受 locator 中有效的字符串 `cell_id`、非 bool 整数 `cell_index` 和清洗后的字符串 `section_path`。独立探针实际得到：

   ```text
   cell:0 + cell_id=None => cell_id=None, cell_ids=[], cell_index=0,
                            section_path=[Course, Topic]
   cell:1:output:2 + cell_id=signal-plots
                         => cell_id=signal-plots, cell_ids=[signal-plots],
                            cell_index=1, section_path=[Course, Plots]
   ```

   ASGI 实测进一步覆盖有原始 Cell ID 和无 ID 的相邻 Cell，旧 `/search` 分别保留 `intro-original` 与 index-only 回退，不再从 opaque source ID 伪造身份。

3. 同一 legacy 身份、课程、hash、文档和版本不变且本轮有已验证原件时，旧 key 可从父级精化到唯一 `page_object/notebook_output`。已有精确映射不会被随后缺原件的粗映射降级。A03 PPTX 独立探针实际得到：

   ```text
   缺原件回填        => ['page:1']
   恢复并重新核对    => ['page:1:shape:3']
   再次缺原件回填    => ['page:1:shape:3']
   ```

   身份任一字段不一致仍由原有冲突检查拒绝，精化只改同一 legacy key 的来源行，不扩大资料归属。
