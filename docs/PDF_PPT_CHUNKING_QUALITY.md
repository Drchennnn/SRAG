## 一、实现概述

### PDF 解析与切块

**解析器**: `PDFParser` (使用 Docling)
- 转换 PDF → Markdown 格式
- 识别标题层级（## H1, ### H2）
- 提取段落、表格、图片引用

**切块器**: `PDFChunker`
- 策略：基于标题段语义切分
- 参数：
  - `soft_min_tokens`: 120
  - `target_tokens`: 280
  - `max_tokens`: 450
- 逻辑：
  1. 按标题段分组
  2. 累积内容直到超过 max_tokens
  3. 保留前缀上下文（文件名、章节路径）

### PPTX 解析与切块

**解析器**: `PPTXParser` (使用 python-pptx)
- 提取每张幻灯片的标题和正文
- 保留幻灯片顺序

**切块器**: `PPTXChunker`
- 策略：一张幻灯片 = 一个 chunk
- 每个 chunk 包含幻灯片标题和内容
- 添加文件名和幻灯片编号前缀

## 二、预期切分质量分析

### PDF 切分质量

#### 优点 ✅

1. **语义完整性**
   - 按标题段切分，保持概念完整
   - 不会打断一个小节的内容

2. **上下文清晰**
   - 每个 chunk 包含：文件名、类型、章节路径
   - 溯源信息完整（页码范围、章节）

3. **Token 可控**
   - 自适应合并小段落
   - 避免过大或过小的 chunk

#### 潜在问题 ⚠️

1. **标题识别准确性**
   - 依赖 Docling 对 PDF 布局的理解
   - 扫描版 PDF 可能标题识别不准
   - **缓解**: Docling 内置 OCR，支持扫描版

2. **跨页内容切分**
   - 一个段落跨页时可能被切断
   - 表格跨页问题
   - **缓解**: 基于语义段落而非页面边界切分

3. **图表关联**
   - 图表说明文字可能在下一页
   - 当前实现未处理图片
   - **改进方向**: Visual fusion 表示（已有框架）

#### 预期分布

基于 Notebook 经验（平均 chunk = 280 tokens）：

```
Token 分布（预估）:
  <120 (太小):    5-10%
  120-450 (正常): 80-90%
  >450 (太大):    5-10%
```

**理由**:
- PDF 段落通常比 Notebook cell 更长
- 标题段之间内容较连续
- 可能有少量超长章节

---

### PPTX 切分质量

#### 优点 ✅

1. **语义单元天然独立**
   - 幻灯片就是独立的信息单元
   - 不存在切分边界问题

2. **溯源极其清晰**
   - 幻灯片编号 = chunk_id
   - 用户可直接定位到具体幻灯片

3. **实现简单稳定**
   - 不依赖复杂的布局分析
   - 结构化提取，错误率低

#### 潜在问题 ⚠️

1. **Token 分布不均**
   - 标题页：可能只有几十 tokens
   - 内容页：可能超过 450 tokens
   - **影响**: 召回结果质量不稳定

2. **多张幻灯片讲一个概念**
   - 例如："概念介绍（1/3）、（2/3）、（3/3）"
   - 切分后丢失连贯性
   - **缓解**: 通过标题相似性关联

3. **图片内容丢失**
   - 当前只提取文本
   - 图表型幻灯片信息量大但文本少
   - **改进方向**: Visual fusion 表示

#### 预期分布

基于幻灯片特性：

```
Token 分布（预估）:
  <120 (太小):    30-40%  （标题页、图表页）
  120-450 (正常): 50-60%  （正常内容页）
  >450 (太大):    5-10%   （密集文字页）
```

**理由**:
- 幻灯片设计追求简洁，文本通常不多
- 大量图表型幻灯片文本极少
- 只有少数"文字墙"幻灯片会超长

| 维度 | Notebook | PDF | PPTX |
|------|----------|-----|------|
| **Token 分布均匀性** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐ |
| **语义完整性** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ |
| **溯源清晰度** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ |
| **实现复杂度** | ⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐ |

**结论**:
- Notebook 最优（结构化、可控）
- PDF 次之（依赖布局分析）
- PPTX 简单稳定但 token 分布不均

## 六、推荐配置

基于设计分析，推荐以下配置：

### PDF

```python
PDFChunker(
    soft_min_tokens=120,
    target_tokens=280,
    max_tokens=450,
)
```

**理由**: 与 Notebook 保持一致，平衡召回精度和上下文大小

### PPTX

```python
PPTXChunker()
# 无参数，一张幻灯片一个 chunk
```

**理由**: 幻灯片天然独立，不需要额外切分

### 未来优化

如果发现 PPTX token 过小影响召回：

```python
PPTXChunker(
    merge_small=True,  # 合并连续小幻灯片
    min_tokens=80,     # 低于此值尝试合并
)
```
