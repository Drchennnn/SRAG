2026-11-19 · 根据与 Carbon 的讨论修订。开发进度由[任务清单](../CHECKLIST.md)维护，当前可运行的功能以[项目首页](../README.md)为准。

## 1. 最终交付给谁，解决什么问题

SRAG 面向用讲义、幻灯片和实验 Notebook 复习一门课的学生。学生把资料加入课程后，在本地浏览器里用自然语言提问，得到能定位到原文的解释；看不懂时可以指着同一张图继续问，也可以从一个概念找到另一份文件里的实验。资料换版后，学生能看清新回答用的是哪一版，旧回答当时依据的又是哪一版。

**产品交付的完整过程**是让一个第一次拿到项目的人，按说明启动服务、配置模型、导入一套可分享的课程样例，独立完成“提问 → 核对原文 → 继续追问 → 跨文件找证据 → 更新资料再验证”。这一过程在网页里有明确入口和结果。模型、索引和图谱的价值，以它们能帮助学生完成哪一步来判断。

例如，学生先问“这页公式里的参数控制什么”，点开 PDF 核对公式；再问“哪个实验展示了改变它的效果”，打开 Notebook 中对应的代码和输出；最后追问“第二条曲线为什么更平滑”。如果课件只展示现象、没有给出因果解释，回答应标出课件支持的现象，并把进一步解释标为补充推断。这个例子描述目标体验，实际验收使用有原件和答案依据的样例。

| 交付层次 | 达到什么状态 |
| --- | --- |
| 首个可用版本 | 三类原件导入后原生文字先可搜；本地网页可在回答内显示整页、裁图或输出，追问同一对象，刷新后继续。 |
| 课程产品完整版 | 再完成三类资料的导入与换版、单文件总结与跨文件对照、一门试点课程的可溯源知识图谱、质量验收和可复现的交付包。 |
| 有条件启用的能力 | Jev 深入检索必须完成对照验证，按实测收益决定启用题型。桌面安装包由本地文件夹监听、系统打开原件或一键安装的实际需求决定。网页版可独立交付。 |

## 2. 网页里必须能完成的学习任务

### 2.1 资料库与版本管理

- **建立课程并加入资料。** 能把 PDF、PPTX、IPYNB 放入指定课程，看到文件名、类型、版本、可见状态和处理结果。首版通过网页本地导入，基础文字发布不等待全库向量化；已有预处理包可继续导入。扫描页和增强任务分别显示状态。新文件加入后，学生知道何时可以开始提问。
- **看懂处理状态。** 区分等待、处理中、可检索和失败。如果只有文字可读，要显示图表是否可用。失败时给出可执行的恢复方法，例如重新导入有效的预处理包、重试失败任务。重复导入同一内容应复用已有版本。
- **更新、移除和追溯。** 同一文件有新内容时生成新版本，发布成功后切换当前检索版本；更新失败时，上一可用版本仍能服务。移除资料后，新问题不能引用它。历史回答保留来源版本；旧原文无法取得时，显示失效原因。
- **验收。** 导入三种文件，各提一个需要其原文的问题。重复导入、修改其中一份、模拟一次更新失败、再移除另一份；逐步检查资料列表、新回答和旧引用是否一致。

### 2.2 范围选择、课程问答与总结

| 用户需求 | 必须表现出来的行为 |
| --- | --- |
| 在一门课、某份文件或全库中提问 | 页面始终显示本轮有效范围。选定文件后找不到答案，应说明查了哪里；用户可以主动扩大范围。 |
| 查概念、公式或代码 | 给出直接解释，关键结论能定位到原文。区分课件明确陈述与通用知识补充。对公式保留符号、条件和单位，对程序保留代码与输出的对应关系。 |
| 查第几页、某个 Cell 或指定图 | 位置明确时直接打开目标；同名文件、多份课件同有第 8 页等情况，给出简短选择。 |
| 总结一份讲义 | 按用户指定主题组织内容，列出支持各部分的页或 Cell，并展示读取范围、未读图片及中断情况。长任务提供等待状态和失败反馈。 |
| 对照不同资料 | 分别标明两份资料中的定义、条件、例子和来源。条件不一致时把差异留给读者核对。 |
| 判断“这份文件有没有讲过 X” | 说明检查过的文件版本、文字覆盖和未读内容。仅在少量候选里未找到时，只能给出本次检索的结果。 |

### 2.3 连续追问与会话

- **对象指代。** “上一页”“刚才第二张图”“你刚提到的参数”应能指回具体文件版本及对象。一个词可能指两张图时，用带页码或 Cell 的选项澄清，用户选中后继续原问题。
- **换题和切课。** 同一课程中提出独立的新主题应能重新搜索。用户明确切换课程或文件时，相应更新焦点；以前回答里的来源可以帮助解析指代，本轮用于支持结论的原文要重新核对。
- **恢复与隔离。** 刷新后能恢复会话、范围和引用。两个会话同时提问时各自保留上下文；发送重试不会生成两份相同轮次，失败的一轮不应冒充已回答。
- **验收。** 连续执行“读图 → 追问第二条曲线 → 换到另一份讲义 → 回看旧引用”。另开会话问另一门课，并在其间刷新页面、更新原文件，检查两边的焦点与来源。

### 2.4 来源阅读与多模态证据

回答在支持对应结论的段落下方直接显示整页 PPT、表格、论文局部或 Notebook 输出图，带来源标签与“问这张图”。有可靠区域才精裁；定位不确定时给整页或让用户选图。点击回答中的引用，阅读器应打开**本轮使用的文件版本和位置**，并能从原文回到回答。每张来源卡至少给出课程、文件、版本、页或 Cell、原文摘录及读取方式。

| 来源 | 打开后看到什么 | 容易出错时怎样处理 |
| --- | --- | --- |
| PDF / PPTX | 对应页或幻灯片，能查看页内公式、表格、图片及支持结论的摘录 | 仅检索到页面时显示已命中；只有实际读取目标图表后才显示对应转写。 |
| Notebook | 标题、相关 Cell、代码及对应的已保存输出；多张输出图可逐一选中 | 输出缺失时显示缺失状态；定位到相邻 Cell 不算打开了目标图。 |
| 图表 / 公式 | 原图与使用过的转写并列，能核对变量、轴标签、单位、表头 | 识别失败、读不清或只有部分信息时标出具体缺项，并允许查看原图。 |
| 历史版本 | 展示原版本；若仅保留引用元数据，显示原版本号和不可用状态 | 新版本可以另行打开，需明确告诉用户已切换版本。 |

**关键验收例。** 对同一 Notebook 中两张相似的图，要求系统打开指定输出并读出某个可辨认标签。答对文件名、页码或主题只证明定位到附近。测试必须分别记录“选中了哪张图”“实际读取哪张图”“答案由哪里支持”。

### 2.5 课程知识图谱

近期先交付文档结构导航；后续完整版至少在一门有讲义和实验的课程上交付一条可走通的路径：**概念 → 定义它的讲义位置 → 演示它的实验 → 可打开的代码或输出**。学生可以从回答进入这条路径，也可以从课程目录选概念开始浏览。

1. **结构导航。** 复用已有文档层级形成课程、文件、章节、页或 Cell、图表的从属关系。学生能回到上级，也能打开相邻内容。
2. **有依据的概念关系。** 试点优先实现“在此定义”“由此实验演示”。边带有关系类型、支持它的原文位置和版本。共享术语只能用作发现线索；只有原文确实支持的关系才可用于回答。
3. **用于问答。** 在允许的课程范围内，从已命中的概念沿一跳关系补充候选，再读取目标原文并产生引用。文件换版或移除后，对应旧边退出新查询。某概念没有可靠关系时，页面允许返回常规检索。
4. **验收。** 用一个确需跨文件的课程问题核对每条边和最终两处证据，并与“混合检索”“混合检索加章节邻接”对照。导航可作为功能独立交付；图谱进入默认回答路径需另有收益证据。

### 2.6 深入检索与 SAG-Wiki 参考

快速问答以 SQLite FTS5 和结构邻接为目标默认路径，旧 Qdrant 混合检索保留为增强路径及对照。对于已经定位到一份讲义、还缺另一份实验依据的题型，验证一种可选路径：扩大初始候选池，用 Jev 判断各段自身提供了什么必要证据，从高分段落提取扩展词，有界地继续检索，然后按相同最终证据预算作答。明确的页码或图像对象优先直读。

**本阶段必须交付的是选择依据。** 固定课程版本、题目、模型和最终证据预算，对比“现有召回”“同候选仅评分”“评分加扩展”。展示至少一个有收益的例子或如实记录未观察到收益，并保留失败例、调用次数和延迟。接入真实决策服务后才能报告 Jev 效果；协议模拟只用于测试软件行为。启用深入模式时，详情页应解释它新增了哪份证据。服务不可用时，用户能看到原因并选择快速检索。此时可交付深入模式关闭的版本，验收需出示不可用原因、未测对照组和快速路径实测；报告注明 Jev 效果待验证及重新评估条件。

上游参考固定为 SAG-Wiki 提交 `92cec19`。其评分协议、扩展检索和版本校验可供比对；SRAG 的课程范围、页/Cell/图表定位与可视化验证沿用本项目的数据。上游扩展贡献按独立项目推进。[上游检索实现](https://github.com/Zleap-AI/SAG-Wiki/blob/92cec195f9262f8506a3ae4b02ddce24b18635ac/core/src/retrieval.rs) · [决策评分协议](https://github.com/Zleap-AI/SAG-Wiki/blob/92cec195f9262f8506a3ae4b02ddce24b18635ac/core/src/models.rs)

## 3. 各模块怎样组成一个产品

| 产品入口 | 用户可见的信息 | 实现时复用或补齐的能力 |
| --- | --- | --- |
| 课程资料库 | 课程、文件、当前版本、处理状态、导入与更新入口 | SQLite 管理版本、原生正文和 FTS 发布；视觉与向量增强独立重试。 |
| 问答工作区 | 当前范围、会话、回答、引用、澄清选择、等待或失败状态 | FastAPI 封装现有会话引擎；持久化会话与轮次，CLI 和网页共享业务逻辑。[会话引擎](../app/rag/chat.py) |
| 来源阅读器 | 原文位置、摘录、图或输出、版本、读取状态 | 统一来源标识至少关联文档、版本、块及适用的页、Cell 或资源 ID。问答、图谱、历史记录共同使用。 |
| 知识导航 | 课程目录、概念关系、关系依据、原文跳转 | 在 SQLite 记录有类型的关系、支持块和版本；按可见性过滤。[现有元数据存储](../app/stores/sqlite.py) |
| 回答详情与评估 | 本轮检索方式、实际证据、额外模型调用、耗时及警告 | 保留候选和最终引用的对应关系，支持回放、人工核对和方案比较。[现有评估说明](../evals/README.md) |

核心数据流为“课程原件 → 解析并保留位置 → 发布可检索版本 → 解析问题及范围 → 直读、混合召回或补充检索 → 读取本轮证据 → 生成回答 → 引用回到原文”。SQLite 提供即时词法候选并决定版本可见性，有向量时可由 Qdrant 补充语义或视觉候选。网页和未来桌面端共用这一流程。现有实现与参数见[架构说明](../RAG.md)。

本地交付应说明哪些内容保存在本机，哪些问题、片段或图片会按配置发送给外部模型。模型密钥由后端读取；网页只用已登记的来源标识访问文件。交付示例使用可以分享的资料，学生可以另外导入个人课件。

## 4. 里程碑及交付物

| 里程碑 | 要交的东西 | 判定完成的动作 |
| --- | --- | --- |
| M0 · 确认起点 | 冻结版本、固定题集、已有 AI 评分和独立保存的人工复核 | 能从原始回答追到真实课件，分歧留有理由；另行锁定新资料题集。此项可与网页开发并行。 |
| M1 · 本地导入与第一处原件 | 文字快搜、结构树、最小问答网页及一个行内原件 | 新资料不经全量向量化即可命中；回答中的图能定位回版本化来源。 |
| M2 · 近期日常版 | 三格式换版、四类行内展示、持久化追问、一跳补证据与小课程验收 | 按分部 A–G 完成日常版审核，记录成功与失败例、覆盖范围及耗时。原 T1–T8 对照见任务清单。 |
| M3 · 课程关系与检索选择 | 单课程图谱试点、快速/深入检索对照及取舍记录 | 一道跨文件题能展示完整证据路径；明确哪类问题启用图谱或 Jev，以及增加多少调用和等待。 |
| M4 · 可交付版本 | 启动与配置说明、样例课程或预处理包、可回放示例、质量报告、已知限制 | 在干净的数据目录按说明启动，逐项执行下面的交付检查，记录版本、结果及失败项。 |
| 后续 · 桌面形态 | 有真实桌面需求时复用同一网页与服务，提供安装、文件选择或变更监听 | 在声明支持的平台完成安装、重新启动、资料更新与版本验证，单独报告各平台结果。 |

G19 后 M2 保持返工。近期先完成 [G20 真实课件诊断](./G/G20-证据断点诊断.md)，并列呈现历史配置质量与真实网页配置盲评；后续投入由首个证据断点和独立复核决定。

M0 的冻结答案由 R 独立组织人工复核，新资料题集由 A03 在首跑前锁定。M1 在 E04 实际打通最小网页路径时记录，M2 在 G04 审核。M3 的图谱 H 与检索实验 J 可并行；M4 的 K 等 H、J、R 均通过后才开始详细设计。每个分部的 01 设计和末项整体验收均留独立审核记录。

## 5. 最终验收与交付清单

**起点。** 2026-10-17 的候选 2 完成同一版本的固定 53 轮回归。原 30 轮完成 30/30、严重错误 0、来源组命中 32/32；全适用维度满分 24/30，整段多轮通过 2/4。阶段结论为未通过，AI 评分仍待人工确认。[本地最终结论与逐轮入口](../../SRAG-analysis/修复回归-20261016-163138/最终验收结论.md)

| 检查项 | 交付时应出示的证据 |
| --- | --- |
| 干净环境可用 | 实测的系统、依赖、启动步骤和所需模型配置；从空数据目录导入可分享样例，并在浏览器完成首问。说明没有模型凭据时仍可使用哪些已导入资料或回放样例。 |
| 三种来源可核对 | 保留整页 PPT、表格裁图、双栏论文局部与 Notebook 输出的浏览器回放；点图能回到对应版本及高亮位置，含多图和缺框场景。 |
| 多轮与版本行为正确 | 留下歧义澄清、显式切课、刷新、并行会话和课件更新后的操作记录；新答案使用当前版本，旧答案的版本信息可查。 |
| 固定题集质量 | 沿用原 30 轮门槛：30/30 完成且无未处理整轮异常，严重错误 0，全维满分至少 27/30，来源位置组命中至少 90%，整段多轮至少 3/4 通过。旧 23 轮另报逐题变化并核查新增严重错误。 |
| 新资料质量 | 首跑前锁定样例、答案依据、分母和通过标准。分别评事实与公式、引用支持、覆盖、对话一致性；记录图表对象是否选对。明确区分人工结论、AI 初评、自动测试与尚未验证项。 |
| 图谱与深入检索 | 可从图谱关系点回真实原件。对照报告给出每种策略的必要证据是否齐全、答案支持度、耗时和调用次数。样本过少时列逐题结果；对效果或成本不合适的模式记录取舍。 |
| 失败可解释、可恢复 | 覆盖索引失败、模型请求失败、视觉读取失败、旧引用失效；页面说明失败发生在哪一步及可用的下一步。确认恢复后没有重复轮次或半发布版本。 |

交付包由项目代码、用户启动说明、可分享的课程样例、演示脚本和带版本的验收记录组成。演示脚本至少保留一个成功例和一个必须澄清或承认证据不足的例子。当前任务勾选见[开发清单](../CHECKLIST.md)。
