## 一、本体与边界：两类有原文依据的关系与“仅共享术语”反例

### 1.1 图谱本体定位与单课程隔离边界

本阶段围绕产品路线（`docs/产品目标与交付路线.md` §2.5）“**概念 → 定义它的讲义位置 → 演示它的实验 → 可打开的代码或输出**”构建**单课程二部可溯源知识图谱**（Course-Scoped Provenance Knowledge Graph），严守单课程与版本边界：

1. **两类节点（不自造平行文件树）**：
   - **概念节点（Concept）**：隶属于单一课程 `course_id` 的规范化知识点 `(course_id, concept_key)`，记录展示名 `canonical_name`、规范化别名 `aliases_json`（中英文同义表达、常用缩写）以及经讲义原文明确声明的绑定实验符号 `anchor_terms_json`。
   - **已发布来源节点（Published Source）**：直接复用 A/B 层唯一跨层来源契约 `(document_id, version, source_id)`（见 [A01-公共契约.md](../A/A01-公共契约.md) §2–§3），对应 `local_sources` 中的 `page`、`page_object`（含表格/公式/图注）、`cell`（Notebook Markdown/Code Cell）与 `notebook_output`。
2. **严格限定的两类已接受关系边（`relation_type`）**：
   - **`defined_in`（在此定义）**：概念在该讲义/课件/论文/说明来源中被明确定义、给出数学表达式/判定规则、触发门槛或适用边界。
   - **`demonstrated_by`（由此实验演示）**：概念在该实验 Notebook 代码 Cell（连带同 Cell 已保存 `notebook_output`）或实测实验段中被实际运行、测量或可视化演示，能够打开对应的代码与保存输出。
3. **跨层一跳拓扑语义**：
   - 存储边为 `(concept_key) --[defined_in | demonstrated_by]--> (document_id, version, source_id)`；
   - **从概念浏览**：点选概念即可分别列出其 `defined_in` 讲义定义节点与 `demonstrated_by` 实验演示节点（含同 Cell `child_output`）；
   - **从来源一跳跳转**：当问答或目录命中某已确认概念的某一侧来源（如讲义 `defined_in`），沿同课程、同概念的 `accepted` 边**最多一跳（1-hop）**到达对端（`defined_in` ↔ `demonstrated_by`），绝不做多概念传递跳跃（禁止 `source_1 -> concept_A -> source_2 -> concept_B -> source_3`）。
4. **单课程绝对隔离原则**：
   - 任何概念节点、别名词表、绑定符号与关系边均以 `course_id` 为主作用域键。课程 A 与课程 B 即使导入同字节文件或共享完全相同的概念词与函数名，也绝不跨 `course_id` 合并概念或连边。

### 1.2 原文支持证据契约（Provenance Evidence Span）与两级状态机

每条图谱边必须携带完整的可机检原文溯源契约，直接对应存储表字段：

| 字段 | 类型与约束 | 语义与不变量 |
| --- | --- | --- |
| `course_id` | `TEXT NOT NULL` | 由 `local_documents.course_id` 核定，客户端传值不授权 |
| `concept_key` | `TEXT NOT NULL` | 课程内稳定小写规范键（如 `adaptive_notch_filter` / `kv_threshold_compression`） |
| `relation_type` | `TEXT NOT NULL` | 严格枚举：`'defined_in'` \| `'demonstrated_by'` |
| `document_id` | `TEXT NOT NULL` | 关联 `local_documents(document_id)` |
| `version` | `INTEGER NOT NULL` | 关联 `local_versions(document_id, version)`，正整数 |
| `source_id` | `TEXT NOT NULL` | 关联 `local_sources(document_id, version, source_id)` |
| `publication_epoch` | `INTEGER NOT NULL` | 构边时对应的 `local_documents.publication_epoch` |
| `content_sha256` | `TEXT NOT NULL` | 构边时对应的 `local_versions.content_sha256`（64 位小写十六进制） |
| `evidence_span_start` | `INTEGER NOT NULL` | 原文字符起偏移（`>= 0`），针对 `readable_source_text(source)` |
| `evidence_span_end` | `INTEGER NOT NULL` | 原文字符止偏移（`> evidence_span_start`，`<= len(text)`） |
| `evidence_excerpt` | `TEXT NOT NULL` | 非空原文摘录；**构建前强校验 `readable_source_text(source)[start:end] == evidence_excerpt`** |
| `status` | `TEXT NOT NULL` | 严格四态：`'candidate'` \| `'accepted'` \| `'rejected'` \| `'superseded'` |

> [!IMPORTANT]
> **四态语义铁律**：
> - **`candidate`（候选线索）**：仅表示发现过术语共现或弱线索，**严禁**出现在网页概念导航或问答 1-hop 候选中；
> - **`accepted`（原文确证支持）**：通过 Step A/B 确定性原文模式验证且未命中任何反例拒收规则，且 `evidence_span_start..end` 精确切出支持句；
> - **`rejected`（反例显式拒收）**：命中“仅共享术语”反例规则（附带可读 `rejection_reason` 用于审计与测试断言），永不进入导航与问答；
> - **`superseded`（换版/删除失效）**：文档升级版本、被软删除或关联跨文件定义锚失效时自动迁移至此状态，对一切新查询不可见。

### 1.3 零外部模型离线确定性构建管线（Zero-LLM Provenance Builder）

为确保在无外部大模型（`workspace_answer_enabled=False`、`deepseek_api_key=""`、无 Qdrant）的离线环境仍可稳定构建完整可溯源知识图谱，构边器（`app/rag/workspace_kg.py`）采用**纯本地确定性原文模式 + 跨文件符号核验**，不调用任何 LLM 或向量服务：

1. **统一原文入口**：对已发布的 `local_sources` 使用现有 [workspace_evidence.py](file:///Users/Link/code/SRAG-h/app/rag/workspace_evidence.py#L19-L29) 的 `readable_source_text(source)` 获取权威文本（兼顾 PDF `caption`/`formula` 的 `locator["object_text"]`、原生表格文本、`cell` 源码及 `notebook_output` 已保存输出文本）。
2. **Stage 1 · 讲义定义抽取（生成 `defined_in` 的 `accepted` 边）**：
   - 逐段扫描非代码纯测试类来源（`page`、`page_object`、`markdown cell`）。先按空行（`\r?\n[ \t]*\r?\n`）或明确节/定义/列表标题切分逻辑段落块 `[block_start, block_end)`，**保留原文内的单行硬换行 `\n` 与字符偏移**（避免 `pypdfium2` 提取 PDF 时在行尾插入的硬换行 `\n` 截断句子）：
   - **模式 D1（显式定义头）**：对齐现有 [evidence_supplement.py](file:///Users/Link/code/SRAG-h/app/rag/evidence_supplement.py#L33-L36) 并扩展带章节编号与复合标题前缀：
     - 可选前缀支持 Markdown `#`、章节编号（`2.1 `、`§2.3 `、`3) `、`(1) `、`（一）`）；
     - 标签覆盖 `Formal Definition`、`Core Concept`、`Definition`、`Def.`、`Rule`、`Theorem`、`Concept`、`核心概念定义`、`概念定义`、`核心概念`、`正式定义`、`基本定义`、`判定规则`、`判定条件`、`核心原理`、`定义`、`概念`（后接 `[:：]`）；
     - 标题行后若仅换行接正文（或正文跨单行硬换行 `\n` 折行），向后并入同一逻辑段直至空行、下一标题/编号或下一概念定义头，要求定义体长度 `>= 12` 字符且含实质释义/公式/条件动词（排除纯大纲占位行）。
   - **模式 D2（规范定义句式 + 跨单行硬换行匹配）**：
     - 在同一逻辑块 `[block_start, block_end)` 内允许单行硬换行 `\n`（以 `(?:[^\r\n。！？；]|\r?\n(?!\s*\r?\n))+` 跨行匹配至句子终结符 `[。！？；]` 或非小数/非点号标识符句点 `(?<!\d)\.(?!\d|[A-Za-z_])(?=\s|$)|[!?]|$`）：
     - 中文：`(?P<name>[\u3400-\u9fffA-Za-z0-9_.\- \n]{2,64}?)\s*(?:定义为|是指|指的是|的判定规则为|的定义为|即是指)\s*(?P<body>(?:[^。！？；]|\r?\n(?!\s*\r?\n)){10,})`
     - 英文：`(?P<name>[A-Za-z][A-Za-z0-9_\- \n]{2,64}?)\s+(?:is\s+defined\s+as|refers\s+to|denotes|is\s+formulated\s+as)\s+(?P<body>(?:[^!?]|\.(?=\d|[A-Za-z_])|\r?\n(?!\s*\r?\n)){12,})`
     - **跨度与规范名映射铁律**：`evidence_span_start = block_start + m.start()`、`evidence_span_end = min(block_start + m.end(), evidence_span_start + 600)`、`evidence_excerpt = raw_text[evidence_span_start:evidence_span_end]`，**100% 保证 `readable_source_text(source)[evidence_span_start:evidence_span_end] == evidence_excerpt`**；同时在生成 `canonical_name` 与 `aliases` 时对 `name` 折叠 PDF 单行硬换行（中文字符间换行直接拼接、英文换行规整为空格）。
   - **概念边界内非紧邻伴随锚抽取**：定义**概念作用域边界 `[def_start, boundary_end)`**（从当前概念 D1/D2 起始位置延伸至**同 `source` 内下一个概念定义头、下一节标题或 `len(raw_text)` 末尾**），扫描该边界内的**全部句子**（允许定义句与实验指向句之间间隔数学推导或参数条件段，不再局限于“定义句或物理紧邻句”）。仅从定义句本身或包含显式实验/实现提示词（`实验|验证|演示|实现|测试|复现|函数|接口|代码|脚本|数据|参见|见|notebook|ipynb|experiment|exp|demo|verify|validation|implement|code|script|benchmark|dataset|trace|metric|run|probe|audit`）且未命中 R2/R4 否定排除的句子中，提取反引号标识、`snake_case` 函数名、实验代号与数据集标识，登记至 `anchor_terms_json` 供 Stage 2 跨文件核验。
3. **Stage 2 · 实验演示抽取（生成 `demonstrated_by` 的 `accepted` 边）**：
   - 扫描同一课程下当前活跃的 `cell`（`cell_type == "code"` 或带紧邻 Code Cell 的实验说明 `markdown`）、`notebook_output` 及含结构化实验块的讲义/实验文档：
   - **条件前置守卫（无实际运行输出绝不建边）**：
     - 对 Notebook Code Cell，检查 `locator.get("outputs_state") == "available"` 且同版本至少存在一条关联的 `notebook_output`（`parent_id == cell.source_id`），且该输出具有**非空可用文本**（`text.strip()`）或**可用图像表示**（`_can_display(output)` 为真）。无输出或仅 `empty`/`missing`/`malformed` 的代码 Cell 直接拦截。
     - 若同一文档相邻结构中存在先导 Markdown 说明 Cell（如 `cell_index - 1` 标注 `# Demo: ...` / `## 实验：...`），提取其概念/实验说明作为上下文线索，但 `demonstrated_by` 边本身**优先锚定实际包含可执行/演示代码及关联输出的 Code Cell**（以及包含实测数值的 `notebook_output`），以便导航和问答共排直接拿到代码与实测输出。
   - **两条确证路径（满足其一且通过 R1–R5 反例与整句否定过滤方为 `accepted`）**：
     - **路径 E1（显式演示声明 + 实测输出）**：Code Cell 注释/紧邻导语或实验文本段显式声明演示或验证该概念（如 `# Demo: <Concept>` / `# Verify <Concept>` / `演示 <Concept>` / `验证 <Concept>` / `Experiment-ID:` + `<Concept>`），且包含参数配置/运行调用及有效已保存输出，同时所在句/注释行与先导导语未命中 R4 整句否定/免责声明。
     - **路径 E2（跨文件符号核验 —— 承接 J03 无共享术语 2-hop 观察）**：当某概念已在同课程的 `defined_in` 原文中显式登记了特定非泛词符号锚 `sym in concept.anchor_terms`（如 `dispatch_audit_v7`、`slab_probe_k12`、`MetricSet-8X`），而某个 `.ipynb` 文件通篇**未出现概念名词**，但其 Code Cell **非注释可执行代码体**或关联 `notebook_output` 精确出现了该符号（字面定义 `def sym(`、调用 `sym(`、配置赋值或输出匹配），同 Cell 拥有有效已保存输出，**且整个 Cell 未命中 R4 对该概念或该符号的否定/免责声明** → **跨文件符号确证成立**，建立 `demonstrated_by` `accepted` 边（记 `evidence_rule = "cross_file_symbol_verified"`），`evidence_span` 锁定该 Code Cell 含符号调用或核心演示句的字符区间（若为纯输出匹配则锁定对应 `notebook_output` 区间）。
4. **Stage 3 · 纯共现线索降级**：
   - 凡仅出现概念名或别名、既不满足 D1/D2 定义句式也不满足 E1/E2 实验演示确证的来源，最多记录为 `status = 'candidate'`（若命中反例规则则直接置 `status = 'rejected'` 并写明 `rejection_reason`）。

### 1.4 “仅共享术语”反例拒收规则（至少 4 类，本设计锁定 5 类）

构建器在将候选提升为 `accepted` 前，必须顺序执行以下 **5 类确定性反例拒收规则**；任意命中即阻断进入 `accepted`：

| 规则编号 | 反例类别 | `rejection_reason` | 原文典型反例样例 | 判定与处置规则 |
| --- | --- | --- | --- | --- |
| **R1** | **仅标题/目录/清单共现概念名** | `cooccurrence_only` | PPTX 第 1 页大纲 `"Agenda: 1. Adaptive Notch Filter 2. Ridge Regression"`；或 Notebook 注释 `"# TODO: Adaptive Notch Filter"` 但代码实为数据读取 `pd.read_csv(...)` | 命中位于大纲/目录页、纯词条列举（无定义谓词与释义体）、或代码/注释无演示调用与对应输出 → 停留在 `candidate` 或拒收为 `rejected`，**不建 `accepted` 边** |
| **R2** | **文献引用、致谢、对比排除或普通背景讨论** | `citation_or_comparative_mention` | `"Prior work [12] introduced KV Compression..."`；`"Unlike Adaptive Notch Filter, our method uses..."`；位于 `References` / `Related Work` / `参考文献` 节路径 | 匹配到引用标注 `\[\d+\]`、`et al.`、`Prior work`、`参考文献` 节路径，或句首/前导出现对比排除词（`unlike`、`compared with`、`in contrast to`、`不同于`、`而非`、`区别于`） → 直接判 `rejected`，**绝不成为 `defined_in`** |
| **R3** | **未来工作、假设设想或未运行空输出计划** | `hypothetical_or_unexecuted_plan` | `"Future work: we plan to run Adaptive Notch Filter on..."`；`"实验计划：拟测试..."`；或 Notebook Code Cell 写了 `run_anf()` 但 `outputs_state in {"empty", "missing", "malformed"}` | 复用并扩展 `_UNOBSERVED` 正则（`planned`、`proposed`、`future work`、`hypothetical`、`预期`、`拟开展`、`尚未运行`），以及 Code Cell `outputs_state != "available"` 或无有效输出内容 → 判 `rejected`，**绝不成为 `demonstrated_by`** |
| **R4** | **整句/注释级否定免责声明、异条件排除或泛词符号撞名** | `negated_or_mismatched_condition` / `generic_symbol_blocked` | `"# Do NOT treat this baseline script as Adaptive Notch Filter"`；`"# This cell does NOT implement or demonstrate Adaptive Notch Filter"`；`"# 非 Adaptive Notch Filter 实验"`；`"# 不用于验证 dispatch_audit_v7"`；讲义 `"do not use ridge_step when..."`；或泛词 `accuracy`/`loss`/`plot`/`Table-1` | 1. **泛词停用表**：扩充 `_S2A_TERM_STOPS` 严禁泛词进入 `anchor_terms_json`；<br>2. **整行/整句级非锚定否定检测（取消末尾 `$` 锚定）**：按注释行（`#`）与逻辑句（`[。！？；\n.!?;]`）切分，在包含概念或实验词的同一句/行内检测隔词否定与免责短语（英文 `\b(?:do\s+not|does\s+not|did\s+not|is\s+not|not|never|no|without|exclude|excluding|unrelated\s+to|disclaimer|caveat)\b` 含 `not\s+treat|not\s+implement|not\s+demonstrate|not\s+verify|not\s+for|not\s+use`；中文 `(?:并非|不是|不作为|不要把|切勿把|勿将|不得视作|不代表|不构成|未实现|未演示|未验证|未采用|未使用|不用作|不用于|非[^，。！？；\n]{0,24}(?:实验|演示|验证|实现|方法)|排除|区别于|不同于)`）；<br>3. **双向硬阻断**：一旦命中即判 `rejected`，**同时阻断 Stage 2 E1 与 E2（含仅在否定注释中出现锚符号情形）**，严禁建 `accepted` 边 |
| **R5** | **跨课程同术语绝不连边** | `cross_course_isolation` | 课程 `course-a` 讲义定义 `Sparse Routing` 并绑定 `dispatch_audit_v7`，干扰课程 `course-b` 实验运行同名 `dispatch_audit_v7` | 构边 SQL 与构建上下文严格锁定单一 `course_id` 集合，课程 B 的任何来源绝不参与课程 A 概念的构建与查询 |

## 二、SQLite 存储 Schema 与换版/删除自动失效规则

### 2.1 向后兼容 SQLite 表结构设计

在 [app/stores/local_library.py](file:///Users/Link/code/SRAG-h/app/stores/local_library.py#L21-L92) 的 `_SCHEMA` 末尾追加以下独立表与索引（使用 `CREATE TABLE IF NOT EXISTS` 与 `CREATE INDEX IF NOT EXISTS`，完全兼容 `PRAGMA foreign_keys = ON` 与任意既有旧库）：

```sql
CREATE TABLE IF NOT EXISTS local_kg_concepts (
    course_id TEXT NOT NULL,
    concept_key TEXT NOT NULL,
    canonical_name TEXT NOT NULL,
    aliases_json TEXT NOT NULL DEFAULT '[]',
    anchor_terms_json TEXT NOT NULL DEFAULT '[]',
    active INTEGER NOT NULL DEFAULT 1 CHECK(active IN (0, 1)),
    updated_at REAL NOT NULL,
    PRIMARY KEY(course_id, concept_key)
);

CREATE TABLE IF NOT EXISTS local_kg_edges (
    edge_id INTEGER PRIMARY KEY,
    course_id TEXT NOT NULL,
    concept_key TEXT NOT NULL,
    relation_type TEXT NOT NULL CHECK(relation_type IN ('defined_in', 'demonstrated_by')),
    document_id TEXT NOT NULL,
    version INTEGER NOT NULL CHECK(version > 0),
    source_id TEXT NOT NULL,
    publication_epoch INTEGER NOT NULL CHECK(publication_epoch >= 0),
    content_sha256 TEXT NOT NULL,
    evidence_span_start INTEGER NOT NULL CHECK(evidence_span_start >= 0),
    evidence_span_end INTEGER NOT NULL CHECK(evidence_span_end > evidence_span_start),
    evidence_excerpt TEXT NOT NULL CHECK(length(trim(evidence_excerpt)) > 0),
    status TEXT NOT NULL CHECK(status IN ('candidate', 'accepted', 'rejected', 'superseded')),
    evidence_rule TEXT NOT NULL DEFAULT '',
    rejection_reason TEXT NOT NULL DEFAULT '',
    created_at REAL NOT NULL,
    UNIQUE(course_id, concept_key, relation_type, document_id, version, source_id),
    FOREIGN KEY(course_id, concept_key)
        REFERENCES local_kg_concepts(course_id, concept_key),
    FOREIGN KEY(document_id, version)
        REFERENCES local_versions(document_id, version),
    FOREIGN KEY(document_id, version, source_id)
        REFERENCES local_sources(document_id, version, source_id)
);

CREATE TABLE IF NOT EXISTS local_kg_doc_state (
    document_id TEXT PRIMARY KEY REFERENCES local_documents(document_id),
    course_id TEXT NOT NULL,
    version INTEGER NOT NULL CHECK(version > 0),
    publication_epoch INTEGER NOT NULL CHECK(publication_epoch >= 0),
    content_sha256 TEXT NOT NULL,
    synced_at REAL NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_kg_edges_course_concept_status
ON local_kg_edges(course_id, concept_key, status, relation_type);

CREATE INDEX IF NOT EXISTS idx_kg_edges_doc_ver_status
ON local_kg_edges(document_id, version, status);

CREATE INDEX IF NOT EXISTS idx_kg_edges_source_lookup
ON local_kg_edges(document_id, version, source_id, status);
```

- **外键与水位线安全性说明**：`LocalLibraryStore.publish()` 换版保留 `local_versions(doc, v1)` 与 `local_sources(doc, v1, *)` 行，`delete_local()` 仅设 `local_documents.deleted = 1` 不删除版本行；当某概念在换版/删档后失去全部活跃 `defined_in` 边时，`local_kg_concepts` 将其置 `active = 0` 并清空 `aliases_json='[]'`、`anchor_terms_json='[]'`（仅当 `local_kg_edges` 无引用时物理删除），既彻底清理残留概念与锚词，又确保 `PRAGMA foreign_keys = ON` 下历史审计边永不违约。`local_kg_doc_state` 记录每份活跃文档最近同步构边的 `(version, publication_epoch, content_sha256)` 水位线，用于 O(1) 检测 `promote_due` 提升或旧库回填缺口。
- **旧库零破坏迁移**：现有数据库首次初始化 `LocalLibraryStore.initialize()` 自动创建以上三张空表与索引，零触碰 `local_documents`、`local_versions`、`local_sources`、`local_fts` 与 `workspace_*` 表结构；所有 KG 读入口均自动触发 `ensure_course_kg_synced()` 幂等对齐。

### 2.2 换版、同内容重导、删除、预约提升与迟到写回的一致性规则

为保证在任意写操作或并发/延迟场景下**新查询绝不命中旧版或已删除边，历史回答引用绝不受破坏**，设计“**事务内同步失效与全量概念重算 + 消费入口统一 CAS 对齐 + 查询层快照硬过滤**”三重护栏：

1. **换版（`v1 → v2` 立即发布）与概念/锚词全量重算 `sync_course_kg_in_tx(db, course_id)`**：
   - 在 `LocalLibraryStore.publish()` 的同一个 `BEGIN IMMEDIATE` 事务中，当 `_activate(...)` 返回 `"published"`（或 `"backfilled"`）且切换了 `current_version` 时：
     1. 立即执行失效更新：将 `document_id` 下所有 `version != active_version` 或 `publication_epoch != new_epoch` 且 `status IN ('candidate', 'accepted')` 的 `local_kg_edges` 更新为 `status = 'superseded'`；
     2. 在同一事务末尾调用 `sync_course_kg_in_tx(db, course_id)` 执行两遍确定性全量重算：
        - **Pass 1（全量重算 `local_kg_concepts` 与 `defined_in`）**：仅从当前 `deleted = 0 AND current_version = s.version` 的活跃来源重新提取全课 `defined_in` 边，并**全量覆盖写回**每个活跃概念的 `canonical_name`、`aliases_json`、`anchor_terms_json`（`active = 1`）；对在当前课程已失去任何活跃 `defined_in` 支撑的概念，置 `active = 0, aliases_json = '[]', anchor_terms_json = '[]'`（若无历史外键引用则物理删除），并将依附旧锚词建立的残留 E2 `demonstrated_by` 边置为 `status = 'superseded'`（`rejection_reason = 'definition_anchor_removed'`）；
        - **Pass 2（重算 `demonstrated_by` 与水位线更新）**：基于 Pass 1 新鲜重算的活跃 `local_kg_concepts` 扫描当前活跃实验源执行 Stage 2/3，并写入最新 `local_kg_doc_state` 水位线。
2. **同内容重导（`status == "skipped"`）与同版补图（`added_images` / `plan.move`）**：
   - 若同字节重导未发生版本、路径与 `added_images` 变更：`publication_epoch` 不变，`local_kg_doc_state` 命中直接幂等复用，**零重复建边、零多余写锁**；
   - 若触发 `plan.move` 或 `_append_missing_pdf_images` 导致同版 `publication_epoch` 递增：在同一事务内同步更新 `(document_id, version)` 未失效边的 `publication_epoch` 及 `local_kg_doc_state`，并增量补建新增对象边，确保不被查询层的 `epoch` 校验误判失效。
3. **预约发布（`scheduled`）与到期提升（`promote_due`）直接问答同步建边**：
   - 预约发布 `v2`（`release_at > now`）返回 `"scheduled"` 时，当前可见版本仍为 `v1`，**严禁提前为 `v2` 写入 `accepted` 边**；
   - 当未来任意读操作触发 [local_visibility.py](file:///Users/Link/code/SRAG-h/app/stores/local_visibility.py#L6-L38) 的 `promote_due(db, cutoff)` 将 `pending_version` 提升为 `current_version` 并递增 `publication_epoch` 时，在同一事务中立即将刚提升文档的旧版本边置为 `status = 'superseded'`；
   - **消费入口统一调用 `ensure_course_kg_synced(course_ids)`**：规定全部 4 个 KG 消费入口——① `kg_concepts()`、② `kg_concept_detail()`、③ `plan_retrieval()` / `_expand_kg_one_hop()`（问答 1-hop）、④ `related_concepts` 投影——在读取 KG 前均统一调用 `ensure_course_kg_synced(course_ids)`。该函数先运行 `promote_due(db, _now())`，再单 SQL 比对 `local_documents` 与 `local_kg_doc_state`：若全部活跃文档 `(version, publication_epoch, content_sha256)` 一致则 `<0.2 ms` 直接返回；一旦发现任何文档刚被 `promote_due` 提升或属于旧库未建边文档，立即开启 `BEGIN IMMEDIATE` 事务复核 `local_documents` CAS 后执行 `sync_course_kg_in_tx(db, course_id)`。从而保证即使用户**未先打开概念面板而直接发起问答**，同样立即可用 `v2` 边。
4. **删除（`delete_local`）显式 `BEGIN IMMEDIATE` 事务锁与旧索引撤权（`revoke_legacy_document`）**：
   - 改造 `LocalLibraryStore.delete_local(document_id)` 与 `local_visibility.revoke_legacy_document()`，**显式以 `db.execute("BEGIN IMMEDIATE")` 加写锁包裹全过程**：
     1. 查询目标 `course_id` 并原子置位 `deleted = 1, current_version = NULL, pending_version = NULL, pending_at = NULL, publication_epoch = publication_epoch + 1`；
     2. 同事务将 `document_id` 的所有活跃/候选 `local_kg_edges` 标为 `status = 'superseded'`（`rejection_reason = 'document_deleted'`）并删除 `local_kg_doc_state` 记录；
     3. 同事务调用 `sync_course_kg_in_tx(db, course_id)` 全量重算剩余活跃概念、清理被删讲义独有的 `aliases_json`/`anchor_terms_json` 并撤销悬空 E2 边，杜绝 WAL 读写锁升级竞态与删除残留。
5. **查询层快照硬过滤（Hard Snapshot Filtering）**：
   - 任何图谱查询在调用 `ensure_course_kg_synced()` 之后，仍强制联合 `local_documents`、`local_versions`、`local_kg_concepts` 与当前会话 `StructureSnapshot` 做双层校验：
     ```sql
     SELECT e.*
     FROM local_kg_edges e
     JOIN local_kg_concepts c ON c.course_id = e.course_id AND c.concept_key = e.concept_key
     JOIN local_documents d ON d.document_id = e.document_id
     JOIN local_versions v ON v.document_id = e.document_id AND v.version = e.version
     WHERE e.course_id IN (...)
       AND e.status = 'accepted'
       AND c.active = 1
       AND d.course_id = e.course_id
       AND d.deleted = 0
       AND d.current_version = e.version
       AND d.publication_epoch = e.publication_epoch
       AND v.published_at IS NOT NULL
       AND v.content_sha256 = e.content_sha256
     ```
   - 在内存层进一步比对当前 `StructureSnapshot` 的 `SnapshotDocument`（`course_id`, `version`, `publication_epoch`, `content_sha256`）与会话授权范围 `allowed_courses ∩ session.course_ids`（以及问答路径下的 `session.document_ids`），形成**“写入事务失效 + 入口 CAS 对齐 + 读取快照硬过滤”三重保险**。
6. **迟到派生写回防护（Late-Writer CAS Guard）**：
   - 任何独立/增量/回填建边入口（如 `write_kg_edges(expected_refs, ...)`）进入 `BEGIN IMMEDIATE` 事务前必须验证每个目标来源对应文档满足 `deleted = 0 AND current_version = expected_version AND publication_epoch = expected_epoch AND content_sha256 = expected_sha256`。一旦文档在准备与写入之间换版或被删除，写回立即拒绝并丢弃（返回 `False`），与 `LocalLibraryStore.write_enhancement()` 契约完全对称。
7. **历史回答回看零破坏**：
   - 已完成的 `workspace_messages` 保留自己的 `sources`（含 `TurnEvidence.revision` 的 `document_id`, `version`, `publication_epoch`, `content_sha256`）与 `workspace_media` 附件。历史引用接口（`historical_evidence` / `historical_media` / `render_citation_preview`）只校验 `WorkspaceStore.filter_accessible(..., current=False)`，**不查询 `local_kg_edges.status`**。因此 `v1 → v2` 换版后，旧回答继续回看 `v1` 原件，新回答与概念导航只见 `v2`。

### 4.2 问答一跳候选补充管线（Strict 1-Hop + Snapshot Guard + 多概念槽位配额）

在 [app/rag/workspace_retrieval.py](file:///Users/Link/code/SRAG-h/app/rag/workspace_retrieval.py#L352-L575) `plan_retrieval()` 中，在完成首跳 `S0` 词法/双语池 `pool` 构造之后、最终截断 `selected[:budget]` 之前，执行受控一跳图谱增强 `_expand_kg_one_hop(...)`：

```text
问句 question + 首跳 S0 pool
        │
        ├─[显式位置 / 单短文件 / kg_disabled]──→ 跳过，按原 S0 路径走
        │
        ▼
[Step 0] ensure_course_kg_synced(effective_courses) ──→ CAS 对齐当前快照（含 promote_due 提升版）
        │
        ▼
[Step 1] 概念锚定（仅限当前 _PinnedScope 授权课程与文档，最多取 3 个概念）
  ├─ 路径 A：从 pool[:min(6, len(pool))] 的 source_key 反查 accepted 边所属概念
  └─ 路径 B：在授权课程活跃 local_kg_concepts (active=1) 中匹配 question 提及的概念名/别名
        │
        ├─[无匹配概念 或 无 accepted 边]──→ trace.kg.status="no_reliable_edges"，零阻塞退回 S0
        │
        ▼
[Step 2] 沿 accepted 边最多一跳取对端对象（严格过滤 doc_id ∈ scope.docs & epoch/sha256 一致）
  ├─ 若对端为 Notebook code cell → 自动提取同 Cell 的 readable/visual child_output 一并带入
  ├─ 记录 reason="kg_one_hop"（与 "kg_one_hop_child_output"），绝不将 evidence_excerpt 当原文
  └─ 受保护槽位 + 单概念配额上限 + 多概念轮转重排，严格截断 <= final_source_budget
        │
        ▼
[Step 3] 送入 read_window() / _read_text() 实时重读当前 SQLite 原文
  └─ 经 read_source() 版本哈希复核 + G21 32,768B 预算 + generate_response() + finish() 提交校验
```

1. **同步校验与严格快照过滤**：
   - 在 Step 0 先对 `scope.snapshot_request.course_ids` 调用 `ensure_course_kg_synced()`，保证即使 `promote_due` 刚提升新版本而用户未点开侧边栏，1-hop 仍能命中最新版边；
   - 在 Step 1 和 Step 2 前后均调用 `scope.verify()` 检查并发换版/删除与取消状态（`active()`）；
   - 目标边 `(document_id, version, source_id)` **必须同时满足**：
     1. `status == 'accepted'` 且所属概念 `active == 1`；
     2. `document_id in scope.docs`（当会话 `session.document_ids` 仅选中单份讲义时，指向未选中实验文件的边**绝不能进入问答候选**，并在 `trace["kg"]["filtered_out_of_scope"]` 计数）；
     3. `(document_id, version, source_id) in scope.sources` 且边上的 `publication_epoch == doc.publication_epoch`、`content_sha256 == doc.content_sha256`。
2. **多概念槽位配额上限与轮转防挤占机制**：
   - **首跳保底区**：优先保留首跳命中中最高排序锚点 `protected_count = min(2, max(1, budget // 3))`（如 `budget = 6` 时保底前 `2` 条首跳锚点，避免把原本命中的定义页挤出）；
   - **KG 扩展总配额**：`kg_reserve_cap = min(max(2, budget // 2), max(1, budget - protected_count))`（如 `budget = 6, protected_count = 2` 时，图谱扩充最多占用 `3` 个新槽位，留足首跳与高分 S0 候选空间）；
   - **单概念槽位配额上限（Per-Concept Cap）**：
     - 限制最多展开前 `max_concepts = 3` 个命中概念（排序优先：问句直接点名命中概念 > 首跳更高排名来源关联的概念 > 缺对端边需要补齐的概念）；
     - **单概念命中（`len(concepts) == 1`）**：`per_concept_cap = min(3, kg_reserve_cap)`（最多取 `1` 条缺侧 `defined_in` + `1` 条 `demonstrated_by` `cell` + `1` 条配套可读 `child_output`，或 `2` 条对端 + `1` 条 `child_output`），防止单个多实验概念挤占整窗；
     - **多概念命中（`len(concepts) >= 2`）**：严格限定 **`per_concept_cap = 2`**（每个概念最多占 `2` 槽：`1` 条缺失对端核心对象 + 至多 `1` 条配套 `child_output`），并采用 **跨概念轮转交错（Round-Robin Interleave）** 依次抽取各概念第 1 顺位缺失对端（如 `C1.exp`, `C2.exp`, `C1.child_output`, `C2.child_output`），直至填满 `kg_reserve_cap`；
     - 对命中概念的未覆盖对端生成 `StructureCandidate(match_kind="structural", reasons=[CandidateReason(code="kg_one_hop", seed=...)])`，若对端已在 `pool[:budget]` 中，记录 `trace["kg"]["status"] = "already_covered"`，保留原有 `pool` 秩序与 Notebook `child_output` 共排顺序。

### 4.3 Notebook `child_output` 共排机制（承接 J03 盲测改进）

针对 `J03` 独立审核指出的“代码 Cell 入窗却将 `stdout` 子输出挤出 6 槽预算导致 `J_Q05`/`J_Q06`/`J_Q08` 失分”的问题，在两个衔接点统一实施共排闭环：

1. **通用检索池共排（`_prioritize_continuations()` in `workspace_retrieval.py`）**：
   - 扩展 [workspace_retrieval.py#L734-L775](file:///Users/Link/code/SRAG-h/app/rag/workspace_retrieval.py#L734-L775) 的 `_prioritize_continuations()`（并可选传入 `scope.sources` 查找未进入 FTS Top-K 的同 Cell 可读输出）：
   - 当排在靠前位次（如 `anchors=3`）的候选是 Notebook 代码 `cell`（`kind == "cell"` and `locator.get("cell_type") == "code"`）时：
     - 优先将其同 Cell 下属的**可读文本 `notebook_output`**（`parent_id == cell.source_id` 且 `text.strip()` 非空，按 `output_index` 排序）紧跟在父代码 `cell` 之后成组排列（`preferred_codes` 补充 `"child_object"`，且允许成对保留 `cell + primary_child_output`）；
     - 同时保证**共排组总数不突破 `final_source_budget`**（若单组 `cell + output` 占 2 槽，仍严格遵守 `len(selected) <= budget`）。
   - 若同 Cell 的 `notebook_output` 为图像输出（`_can_display(output)` 为 True 且非空），将其加入 `visual_candidates` 供 `_attach_images()` 自动挂卡展示（或供显式读图使用），不挤占纯文本候选槽。
2. **图谱一跳 `demonstrated_by` 专属共排**：
   - 当图谱 `demonstrated_by` 边指向代码 `cell` 时，自动查找该 `cell` 下全部已保存 `notebook_output`：
     - 文本输出以 `CandidateReason(code="kg_one_hop_child_output", seed=cell_key)` 紧随父 `cell` 排入 `selected`；
     - 图像输出加入 `visual_candidates`，使“概念 → 讲义定义 → 实验代码 + 实测输出（文本/图像）”在一次问答内完整交付。

### 4.4 强制重读与核验铁律（绝不把边摘录直接当答案）
