## 一、总体评价

`H01-边及导航设计.md` 整体架构边界清晰，具备以下扎实设计基础：
1. 严格复用 A/B 层 `(document_id, version, source_id)` 跨层契约与 `readable_source_text(source)` 统一文本入口，不自造平行文件树；
2. 明确了 `defined_in` / `demonstrated_by` 两类关系边、`evidence_span_start..end` 逐字核验与四态状态机（`candidate` / `accepted` / `rejected` / `superseded`），并给出纯离线零 LLM 构边思路；
3. 问答路径坚持“边摘录绝不当事实”，强制通过 `read_window()` 实时重读当前 SQLite 原文并经 `WorkspaceStore.finish()` 提交前复核；
4. 明确将 `workspace_kg_retrieval_enabled` 默认设为 `False`，且将“导航独立功能”与“问答同预算三臂对照（`S0_base` / `S0_adj` / `S0_kg`）”结论严格分列。

但逐行对照现行 `app/` 与 `app/web/workspace/` 源码实现后，发现 **4 处会在 `H02` 实现与 `H03` 验收中直接引发漏抽、误收、早退或一致性的阻塞性缺口**，须在设计阶段先行闭环。

## 二、阻塞性必改项（共 4 项）

### 必改项 1：修复 `plan_retrieval()` 与 `_plan_search()` 在默认 `strategy="fts"` / 无双语场景下的早退与预算分裂

- **源码核验依据**：
  - [app/rag/workspace_retrieval.py#L436](file:///Users/Link/code/SRAG-h/app/rag/workspace_retrieval.py#L436)：`plan_retrieval()` 入口存在 `if strategy == "fts" or request.location is not None or initial.status in _SCOPED_FAILURES: return finish(pool)`，一旦传入 `strategy="fts"` 会直接跳过后续全部增强阶段；
  - [app/rag/workspace.py#L1760-L1778](file:///Users/Link/code/SRAG-h/app/rag/workspace.py#L1760-L1778)：`_plan_search()` 在 `strategy == "fts"` 且 `is_han_latin == False`（纯中文或纯英文课程资料/问句）时，`plan_strategy` 仍为 `"fts"` 且默认 `candidate_budget = min(4, request.top_k)`，而 `"bilingual"` 为 `request.top_k`（12）、`"s0"` 为 `min(6, request.top_k)`（6）；
  - [app/rag/workspace.py#L1508-L1517](file:///Users/Link/code/SRAG-h/app/rag/workspace.py#L1508-L1517)：构造 `StructureSearchRequest` 时未透传 `include_adjacency`。
- **设计缺口**：
  1. `H01` §4.1 仅声明“在 `_plan_search()` 中不因 `strategy == 'fts'` 早退”，遗漏了 `plan_retrieval()` 第 436 行同样会在 `strategy == "fts"` 时直接 `return finish(pool)`，导致纯中文或纯英文课程开启 `workspace_kg_retrieval_enabled=True` 时无法到达 `_expand_kg_one_hop()`；
  2. 未明确 `Settings.workspace_retrieval_include_adjacency` 如何注入 `StructureSearchRequest.include_adjacency`，使 §4.5 对照臂 `S0_base` (`False`) vs `S0_adj` (`True`) 缺少落点；
  3. 未明确 `workspace_kg_retrieval_enabled=True` 且 `workspace_retrieval_budget == 0` 时的统一 `candidate_budget` 口径（避免 `fts=4` / `bilingual=12` / `s0=6` 破坏同预算公平性），也未定义多概念同时命中 `pool[:6]` 时单概念注入上限（防单个概念耗尽全部剩余槽位而挤出跨文件多概念问句的另一侧证据）。
- **必须修改**：
  - 在 §4.1–§4.2 明确：`StructureSearchRequest` 透传 `include_adjacency=settings.workspace_retrieval_include_adjacency`；`plan_retrieval()` 第 436 行须允许 `kg_enabled=True` 时继续进入 `_expand_kg_one_hop()`（且需同时兼容 `S0_base` / `S0_adj` 在 `allow_bilingual` 上与默认 `S0` 完全对齐）；补充同预算解析与多概念按序/限量槽位配额规则。

### 必改项 2：修补 Stage 1 定义与伴随锚抽取对 PDF 硬换行、带编号标题及非紧邻条件段的漏抽

- **源码核验依据**：
  - SRAG 对 PDF 原文（`pypdfium2`）保留页内换行 `\n`；PPTX 与 PDF 原生文本不含 Markdown 反引号。
- **设计缺口**：
  1. §1.3 模式 D1 正则以 `^(?:#+\s*)?` 锚定行首且关键词缺少常见教学标题变体（如 `核心概念`、`概念定义`、`核心概念定义`、`正式定义`）及可选章节编号前缀（如 `1. `、`1.2 `），在标准编号讲义 PDF/PPTX 中会系统性漏匹配；
  2. §1.3 模式 D2 定义体使用 `[^。\n]{10,}` / `[^.\n]{12,}`，遇到 PDF 页内自动换行 `\n` 即提前截断；若定义谓词（如 `是指`、`is defined as`）靠近行尾，换行前不足 10/12 字符将导致整条定义漏抽；
  3. 伴随锚抽取仅扫描“definition `evidence_span` 所在句或紧邻句”，但实际讲义页面常在“正式定义句”与“实验演示对应句”之间插入“数学/机制成立条件”段落，导致二者并不物理紧邻，从而遗漏 `anchor_terms_json` 并使依赖 E2 跨文件符号核验的实验边无法建立。
- **必须修改**：
  - 在 §1.3 明确：D1 支持可选章节编号前缀与复合定义前缀；D2 及跨行块抽取支持跨单行换行符 `\n`（以空行、下一标题或句末标点终止）并保留精确字符起止偏移映射，保证 `readable_source_text(source)[start:end] == evidence_excerpt` 仍严格成立；伴随锚抽取扩大到同一概念作用域内（从该概念定义起点至同 `source` 下一概念标题或文档末尾），并要求同句/同段落具备明确的实验/演示/函数提示语。

### 必改项 3：封堵 Stage 2 / R4 对代码注释与句中否定免责声明的绕过漏洞

- **源码核验依据**：
  - [app/rag/evidence_supplement.py#L76-L80](file:///Users/Link/code/SRAG-h/app/rag/evidence_supplement.py#L76-L80) 中 `_NEGATES_CONDITION` 末尾带有 `$` 锚点，仅匹配紧挨在目标词前方相邻位置出现的否定词。
- **设计缺口**：
  - §1.4 规则 R4 依赖 `_NEGATES_CONDITION` 类前缀否定。但真实 Notebook 代码注释或说明段常出现跨词否定免责句式（如 `# Do NOT treat this helper as <Concept>`、`# does NOT implement or demonstrate <Concept>`、`# 仅作基准计时，非 <Concept> 实验`），否定词与概念名/实验声明词之间隔有若干动词或定语，导致紧邻 `$` 正则失效；更严重的是此类注释同时包含 `demonstrate` / `实验` / 概念名，若未在句/行级拦断，Stage 2 E1 可能将其误判为有效演示边。
- **必须修改**：
  - 在 §1.4 R4 明确新增**行级/句级整句否定守卫**：对代码注释行、紧邻 Markdown 导语及句级声明，只要同一注释行或同一句内出现否定表达（如 `do not`、`does not`、`not implement`、`not demonstrate`、`not treat ... as`、`never`、`非...实验`、`不是...演示`、`未实现`、`不演示`、`禁用`）并与概念名或实验声明共现，即刻判为 `rejected`（`mismatched_condition_or_generic_symbol`），同时阻断 E1 与 E2。

### 必改项 4：补齐 `promote_due` 到期自动建边、`delete_local` 显式事务锁、概念锚词全量重算及 `_catalog` 课程过滤

- **源码核验依据**：
  - [app/stores/local_library.py#L279-L291](file:///Users/Link/code/SRAG-h/app/stores/local_library.py#L279-L291)：`delete_local()` 当前未显式使用 `BEGIN IMMEDIATE`；
  - [app/stores/local_visibility.py#L6-L38](file:///Users/Link/code/SRAG-h/app/stores/local_visibility.py#L6-L38)：`promote_due()` 会在任意读写路径中到期提升 `pending_version`；
  - [app/rag/workspace.py#L3340-L3357](file:///Users/Link/code/SRAG-h/app/rag/workspace.py#L3340-L3357)：`WorkspaceService._catalog(session_id)` 按 `self.allowed_courses` 构造全部课程目录树，而非按 `session.course_ids` 过滤。
- **设计缺口**：
  1. **预约提升后的问答零边漏洞**：§2.2.3 在 `promote_due` 内只置旧边为 `superseded`，而将新版本建边延迟至“下次图谱只读查询”。若 `scheduled` 版本刚到期被检索/提交路径里的 `promote_due` 提升，而用户未点开侧边概念导航直接提问（开启 `workspace_kg_retrieval_enabled=True`），`plan_retrieval()` 会读到空边。须明确**所有 KG 读取与消费者入口**（`kg_concepts`、`kg_concept_detail`、`plan_retrieval` 1-hop、`related_concepts` 投影）均在读取前调用 `ensure_course_kg_synced(...)`（CAS 对齐当前快照 `publication_epoch`）；
  2. **`delete_local` 事务原子性与 `local_kg_concepts` 锚词清理**：`delete_local` 与 `revoke_legacy_document` 必须显式在 `BEGIN IMMEDIATE` 事务内原子完成文档失效、边 `superseded` 迁移与 E2 复核；且 `sync_course_kg_in_tx` 必须依据当前活跃 `defined_in` 边**全量重算 `local_kg_concepts` 的 `aliases_json` 与 `anchor_terms_json`**（并清理不再被任何有效定义边支撑的旧绑定锚词），避免旧讲义删改概念后残留旧锚词继续错误绑定实验；
  3. **`_catalog` 与历史芯片 404 降级边界**：`kg_concepts` / `kg_concept_detail` 严禁仅因节点存在于 `_catalog()`（`self.allowed_courses`）就暴露给未包含该课的会话，必须严格校验 `course_id in (session.course_ids ∩ self.allowed_courses)`；同时在 §3.2 明确前端点击已整条失效的历史消息概念芯片触发 404 时，由概念详情面板就地拦截并展示“当前版本暂无可靠图谱关系 + 一键常规检索”，避免全局错误横幅误报 `not_accessible`。
